# Augmentor, ResonantOS, SDK, and Living Archive Ontology Documentation Strategy

## Direct Strategy

Build from the current owners instead of treating the existing robot page as
the architecture. The research should establish one joined component graph,
split it into separately owned ontology packages, and derive one progressive
documentation experience from that graph:

```text
ResonantOS system package
  ├─ Augmentor agent package
  │    ├─ internal architecture and capabilities
  │    └─ Agent API / consultation interface package
  ├─ Add-on SDK and add-on package
  └─ Living Archive knowledge and memory package
       └─ source-bound ontology material and projections

joined by typed cross-package relations
  └─ projected into one human documentation page and one machine view
```

The existing Add-on SDK is part of the ResonantOS capability environment around
Augmentor. The narrower SDK declaration for requesting Augmentor ontology
consultation remains a separately classified feature until current source proves
it implemented. Living Archive should hold source-bound, revision-aware ontology
material and derived projections without turning retrieval or memory into
automatic ontology promotion.

## Dependency Flow

```text
explorers (parallel)
  -> synthesizer
  <-> reviewers (one zig-zag)
  -> exact-binding evidence closure
  -> writer
  -> auditor
  -> parent
```

One bounded synthesizer-to-explorers feedback edge may repair missing source
evidence. One bounded auditor-to-writer edge may repair wording, structure, or
citation placement after evidence closure. Explorer-owned gaps cannot be
laundered through writer revision.

- **Target:** `projects/augmentor/ontology/unified-agent`, with current
  ResonantOS and Living Archive sources as read-only owner evidence.
- **Desired outcome:** a deep, MVP-ready, non-executed plan for the joined graph,

  versus federated packages versus view-only composition;
  `memory_residue_for_context_recovery` for prior Augmentor/Living Archive work;
  `toy_game_for_low_cost_falsification` for the literal MVP witness; and
  `protected_context_for_external_or_sensitive_evidence` for the private/public
  and cross-repository evidence boundaries.
- **Subagent strategy:** `recommended` for the upstream research dispatch; no
  additional sibling agents are proposed inside the ten-stage Refine loop unless
  the audited research exposes a named gap.
- **Refine join policy:** consume only an auditor-accepted `findings.md` and its
  exact evidence-closure receipt; then run the canonical Context Builder,
  Define, review, research decision, Distill, Design, design review, Distill
  Repair, Plan, and final synthesis sequence.
- **Refine output boundary:** run-folder artifacts and a non-executed Work Pack
  only. Product, ResonantOS, Living Archive, ontology admission, publication,
  deployment, and release remain later owner routes.

The exact Refine dispatch will be materialized and validated only after the
