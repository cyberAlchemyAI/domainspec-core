# Augmentor Subagent Strategy Integration — Research Strategy

This is a durable, non-authoritative research proposal. It does not authorize
the dispatch, modify ResonantOS, promote the public Subagent Strategy sigil,
install a capability, or change DomainSpec/Arcanum authority.

## Direct strategy

The integration to test is:

```text
ordinary user request
  -> preview-only StrategyProposal
  -> immutable RouteDecision
  -> explicit owner confirmation
  -> validated Dispatch Spec
  -> Orchestrate-owned native actions and joins
  -> host-owned Run projections referencing existing execution owners
  -> independently controllable results or blockers
```

Augmentor should expose one conversational experience, but it must not become a
second scheduler, job registry, workspace manager, artifact store, memory
authority, or copy of the private DomainSpec dispatch ledger. The public
Subagent Strategy lifecycle is the portable contract; a ResonantOS runtime
profile and adapter should bind it to current host owners.

## P1 trigger decision

Dispatch is required on all four P1 triggers:

- **Synthesis:** public Arcanum lifecycle, private adapter precedent, accepted
  Augmentor routing/session research, current ResonantOS runtime, IDE
  Ergonomics, and external protocols must be reconciled.
- **Context protection:** the raw contract, code, UX, and primary-source
  precedent evidence is larger than the parent should carry.
- **Isolation:** portable ownership, current runtime, human experience, and
  protocol/degraded-mode claims need independent evidence and adversarial
  review.
- **Parallelism:** the four explorer lanes are independent until synthesis.

The live dispatch type is `research`; the sheet uses schema `0.8.0`.

## Dependency flow

```text
explorers
  -> synthesizer
  <-> reviewers
  -> evidence closure
  -> writer
  -> auditor
  -> parent
```

- One bounded feedback edge lets the synthesizer request missing source
  evidence from explorers.
- The synthesizer/reviewer zig-zag has a loop cap of two.
- One bounded auditor-to-writer edge permits a final repair.
- Every spawned agent must be joined and closed.
- The strategist mechanically appends verbatim explorer returns to
  `research.md`; the writer never authors or rewrites that source record.

## Research obligations

The findings must answer:

1. What is the smallest public-neutral `StrategyProposal` and runtime-profile
   contract Augmentor needs?
2. Which fields stay server/adapter-side because they reveal private
   DomainSpec schema, agent identities, ledgers, or paths?
3. How does an approved strategy become a Dispatch Spec and Orchestrate run
   without duplicating host scheduling or state?
4. Which existing ResonantOS owner carries each execution, approval, context,
   artifact, notification, and recovery concern?
5. How does ordinary conversation preview, edit, confirm, control, interrupt,
   resume, and consume parallel work without context bleed?
6. What happens when the capability, native host operation, parallelism,
   approval, validation, or one child is unavailable?
7. What exact incremental slice produces the accepted subagent-strategy plus
   Whisper two-child browser witness?
8. What tests and overhead budgets distinguish useful agent experience from
   schemas, dashboards, or receipts without user value?
