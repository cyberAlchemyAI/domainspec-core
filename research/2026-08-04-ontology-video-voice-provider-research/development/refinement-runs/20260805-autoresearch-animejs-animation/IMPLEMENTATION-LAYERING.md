# Implementation Layering — Ontology Video Anime.js Prototype

| Layer | Decision question | Minimum working unit | Exit evidence | Deferred |
|---|---|---|---|---|
| L0 — trust | Can an agent build and consult a source-bound animation candidate without inflating claims? | schema, source snapshot, fixtures, candidate builder, consultation adapter, hard prechecks | deterministic tests and zero source/vault delta | Anime.js runtime and visual output |
| L1 — prototype | Can one S6 beat produce the intended standard and reduced semantic states? | admitted local runtime, static SVG scene, ten-second timeline | local prototype bytes and state-machine checks | full S6 scene, voice, render |
| L2 — witness | Does the prototype preserve semantics in a real browser and merit reuse? | fixed-state Playwright checks plus human review | browser receipt, screenshots, source delta check, owner disposition | audience comprehension and production |
| L3 — learning | Can the attempt become durable residue without becoming unearned truth? | one closed WorkEpisode and an S7 handoff candidate | episode receipt, projection read, `Lesson=false` assertion | Lesson admission, full film, release |

## Non-regression rules

- Later layers cannot weaken source hashes, proof-state separation, reduced-motion equivalence, or owner gates.
- A different Anime.js asset, browser, source image, timing fixture, or candidate fingerprint creates a new witness identity.
- L2 screenshots supplement semantic DOM/SVG assertions; they never replace them.
- L3 may preserve a successful attempt but cannot turn it into a verified Lesson or ontology authority.
- No layer edits `projects/autoads/`, `projects/animejs/ontology/agent-knowledge-vault/`, or the source video package.

Recommended next layer: L0. Selected SWU: none.
