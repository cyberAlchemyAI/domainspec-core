Product bet

Musicians should not have to choose between control and speed.

Agentic Music Studio is a product direction for turning high-level musical intent into deterministic, inspectable code that the musician can hear, edit, replay, and steer.

The musician supplies intent and taste. The agent does the engineering grind over one shared spec. The sound still comes from authored, seeded code.

Craft stays black-box audio stays out

Problem

Aesthetic intent is easy to say and hard to engineer.

A musician can say "dark violin stochastic synth, bring strangeness" in one breath. Turning that into reproducible sound usually means either endless parameter work or surrendering the result to a black box.

1

Intent is rich

Musicians speak in feel, gesture, references, texture, tension, and timing.

2

Tools are literal

Most production surfaces ask for knobs, notes, routing, automation, or prompts.

3

Metrics are hidden

When the sound changes, the artist rarely sees what perceptual target moved.

4

AI can erase craft

Prompt-to-audio can be fast, but the artifact is hard to inspect, diff, or replay.

5

The need

Keep expressive control while letting software handle the tedious search.

Problem statement

The product challenge is not "generate music." It is "make intent executable while preserving authorship."

How we solve it

Make the spec the product center of gravity.

Every interface edits one reproducible musical spec. The agent writes inspectable code and searches real measurements. The musician judges and steers.

1

Say the intent

"Dark violin stochastic synth, bring strangeness."

2

Compile to spec

Closed vocabulary, targets, constraints, seed, and editable fields.

3

Write code

The agent emits Tidal-style deterministic code the musician can read.

4

Search targets

Objective search tunes synth parameters against measured features.

5

Steer by taste

The musician hears it, edits it, critiques it, and loops back.

INTENT -> SPEC -> PROGRAM -> RENDER -> STEER human taste -> editable target -> inspectable code -> deterministic audio -> critique loop

What exists today

The proof already renders sound.

The current build is small by design: one timbre engine, one intent path, measurable targets, and a steering loop that proves the core product motion.

Product insights

The important discoveries are product-shaping, not just technical.

The work surfaced four constraints that should guide the studio experience.

1. Effects are objectives

Darkness and strangeness should be open goals composed over closed measurable primitives, not hard-coded primitives themselves.

2. The floor must be measured

Peak-picking drifted 6.1 percent on GENDYN. Multitaper moment centroid brought drift to 1.3 percent.

3. Honesty is a feature

The UI must label analyzer-independent claims, proxies, and felt listener claims differently.

4. Steering is trade-off navigation

"More bite" raises measurable dissonance and centroid. The product should show the cost of each move.

Why we are doing it

The goal is not to automate taste. It is to make musical intent executable.

Musicians should be able to work at the level of feeling and structure while retaining the right to inspect, edit, reject, replay, and perform the result.

For the musician

Stay in the artistic loop. The product handles parameter search, but the musician keeps judgment, authorship, and final say.

For the artifact

The piece becomes source-like: diffable, forkable, replayable, and teachable instead of a one-off opaque output.

For trust

The studio exposes what it optimized and what remains only a proxy, so the musician can argue with the machine intelligently.

Why it matters

The product value is a new division of labor: human taste, machine engineering, shared evidence.

How others can leverage it

It is more than one app surface. It is a reusable studio pattern.

The product can be adopted as a musician workflow, a research harness, a live-coding companion, or a design pattern for other creative tools.

Musicians

Use voice, code, critique, gesture, and annotation as different ways to edit one piece rather than jump between disconnected tools.

Tool builders

Reuse the spec-as-lingua-franca pattern: every interface writes the same reproducible document, every meter reads back from it.

Researchers

Swap in measurable objectives, run listener studies, and test which proxies actually predict felt effects.

Live coders

Keep rule authoring as the high-craft surface while letting the agent propose measurable parameter moves.

Educators

Show how timbre, tuning, spectrum, dissonance, and stochastic processes become audible decisions.

Product teams

Borrow the communication-process taxonomy: command, declaration, objective, example, critique, annotation, performance, and feedback.

Day in the life

A musician works with it like a co-engineer, not a slot machine.

The studio should feel like moving between intention, audition, edit, performance, and versioned craft.

Reader terms and reader outcomes

Spec means a reproducible musical document; objective search means deterministic tuning against targets; proxy metric means a measurement that still needs listening judgment.

Product roadmap

The proof is working; the product gates are clear.

The next work is not random feature growth. Each item turns a product risk into a sharper interface or stronger claim.

  • Spectralize-v2. Make roughness and strangeness as stable as darkness.
  • O1 felt-match. Prove whether dissonance predicts what listeners call strange.
  • Steering-v2. Replace weighted-sum steering with explicit Pareto navigation or preference learning.
  • Scope expansion. Add open vocabulary, rhythm, pitch, sequencer, and scale modules.

Product status

v1 proves the loop: intent goes in, inspectable code renders sound, objective search tunes measurable targets, and the human steers. The next gates decide how broadly that loop generalizes.

Human taste sets direction. Agentic engineering turns it into reproducible sound. Evidence keeps both sides honest.
