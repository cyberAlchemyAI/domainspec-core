# Discord API and Organizational Network Analysis Research Strategy

## Direct strategy

Research the current Discord developer surface and determine which organizational
network analyses can be supported without confusing available platform traces with
collaboration, influence, performance, consent, or organizational truth. The result
will be an evidence-bound study blueprint, not a live collector or an analysis of a
real server.

The dispatch is explicitly barred from requesting credentials, creating a bot,
joining a server, calling the Discord API, collecting messages or metadata, or
implementing an analysis runtime.

## P1 trigger decision

This is a governed `research` dispatch. It satisfies all four Principle-1 triggers:

- synthesis: current Discord API and policy evidence, ONA methods, privacy and ethics,
  and finite validation must be reconciled;
- context protection: official API details and methods literature would create much
  more raw evidence than the parent should carry;
- isolation: technical availability, analytical validity, and privacy acceptability
  need independent returns that can be rejected without contaminating one another;
- parallelism: the API, ONA, and governance corpora can be investigated concurrently.

## Lanes, groups, and subagents

### Group 1: explorers, parallel

Anti-bias axis: composite `source-corpus` plus `methodology`, specialized from the
global theme of evidence validity from observable Discord events through defensible
network inference to privacy-preserving use.

- `Turing, Alan` — Discord API explorer. Verifies current first-party REST, Gateway,
  object, event, intent, permission, pagination, rate-limit, policy, and missing-data
  boundaries. Output: exact-bound observability matrix.
- `Senge, Peter` — ONA methods explorer. Maps legitimate organizational questions to
  multiplex, bipartite, directed, weighted, and temporal graphs; tests metrics,
  confounds, sampling bias, and external validation. Output: construct and
  metric-to-claim matrix.
- `Meadows, Donella H.` — privacy and governance explorer. Attacks consent,
  employment-power, re-identification, purpose, minimization, retention, deletion,
  access, small-group, policy, and surveillance risks. Output: control set, red lines,
  and safer alternatives.

Every unordered explorer pair has one digest-owned predicted-disagreement statement
in the admitted sheet.

### Group 2: synthesizer, sequential

- `Simon, Herbert` reconciles the three returns into an exact-bound study blueprint:
  observability and permission matrix, event-to-network bindings, schemas, collection
  architecture, graph choices, validity and bias register, privacy threat model,
  aggregate reporting, abstention rules, and a fully synthetic fixture.

The synthesis must keep six gates separate: technical observability, authorization,
data quality, analytical validity, privacy acceptability, and organizational decision
authority.

### Group 3: reviewers, parallel after synthesis

Anti-bias axis: `attack-vector`, specialized from the same evidence-validity theme.

- `Lakatos, Imre` — precedent skeptic. Verifies existing Discord and ONA owners and
  classifies reuse; precedent never emits KILL.
- `Popper, Karl` — non-vacuity skeptic. Requires a finite synthetic event corpus,
  deterministic graph projections, expected metrics, negative controls, and
  abstention cases.
- `Quine, Willard Van Orman` — definitional-soundness skeptic. Attacks collapses such
  as message=work, reply=knowledge flow, centrality=performance, API
  permission=consent, or pseudonym=anonymity.

Every unordered reviewer pair has one digest-owned predicted-disagreement statement
in the admitted sheet.

### Group 4: writer, sequential after evidence closure

- `van Lamsweerde, Axel` writes only `findings.md`, and only when the exact-binding
  handoff gate returns `ready`. The strategist, not the writer, mechanically assembles
  `research.md` from verbatim explorer returns.

### Group 5: auditor, sequential after writing

- `Brandenburg, Martin` audits `findings.md` against the frozen sheet, source-bound
  evidence, synthesis, reviewers, privacy constraints, and claim ceiling. The parent
  remains final approver.

## Dependency flow

```text
explorers (3 in parallel)
  -> synthesizer
  <-> reviewers (3 in parallel; zig-zag cap 1)
  -> exact-binding evidence closure
  -> writer
  -> auditor
  -> parent final approval

synthesizer -> explorers (feedback cap 1, only for explorer-owned evidence gaps)
auditor -> writer (feedback cap 1, only for evidence-already-present writing defects)
```

No downstream wave opens merely because an upstream file exists. All expected agents
must join and close, and the declared wave gate must pass. Missing Discord source
selectors route to the explorer feedback edge, not to writer revision.

## Research obligations

The confirmed run must use current first-party Discord sources for platform claims and
primary or authoritative sources for ONA methods. It must record exact selectors,
access date or immutable identity where available, proof status, missing observations,
sampling and selection bias, construct validity, alternative explanations, validation
tests, privacy controls, owner decisions, and abstention rules.

The intended deliverable includes safe aggregate use cases and explicit red lines. It
must reject unsupported individual productivity, performance, leadership, sentiment,
or influence scoring and must not give jurisdiction-specific legal conclusions.
