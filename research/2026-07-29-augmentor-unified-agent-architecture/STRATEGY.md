# Augmentor Unified Agent Architecture — Research Strategy

This is a durable, non-authoritative research proposal. It does not authorize
the dispatch, modify Augmentor or ResonantOS, change Arcanum, write memory or
ontology state, make an authority decision, promote an artifact, or claim that
DomainSpec or Saturn is publicly shipped.

## Direct strategy

Research one architecture with three non-collapsing planes:

```text
human plane
  ordinary conversation · visible user model · route/proposal controls
  threads · child status · grounded answers · correction/forgetting
                         │
runtime and control plane
  Interaction · ContextSnapshot · RouteDecision · StrategyProposal
  ReasoningRequest/Judgment · Dispatch Spec · Orchestrate · host Runs/effects
                         │
authority and knowledge plane
  explicit handles · Living Archive sources · disposable semantic index
  Inventory evidence · ontology candidate/map · authority decision · promotion
```

The planes integrate through typed references and events, not shared mutable
ownership. The target artifact must explain every connection as:

```text
producer -> typed artifact/event -> consumer
          + authority owner
          + exact source selector
          + sync/async posture
          + failure/degraded behavior
```

The result must be an implementation-usable current-versus-target blueprint,
not a new meta-runtime. Augmentor remains one conversational experience while
current owners retain routing, sessions, execution, memory, artifacts,
ontology, authority, and promotion.

## P1 trigger decision

Dispatch is required on all four triggers:

- **Synthesis:** the accepted user-graph/reasoning, routing/session, and
  Subagent Strategy results must be reconciled with the reasoning evaluator,
  IDE Ergonomics, Arcanum guidance, Inventory, ontology, authority, Living
  Archive, and current ResonantOS.
- **Context protection:** exact contracts, findings, source bytes, ownership
  boundaries, and proof residue exceed a safe parent-chat context.
- **Isolation:** authority/knowledge, runtime/control, and human experience need
  independent methods before they can be joined.
- **Parallelism:** all three explorer lanes are independent until synthesis and
  fit the available three-child runtime ceiling.

The live type is `research`; the sheet uses schema `0.8.0`.

## Dependency flow

```text
three explorers
  -> synthesizer
  <-> three reviewers
  -> exact-binding evidence closure
  -> writer
  -> auditor
  -> parent
```

- One bounded synthesizer-to-explorer feedback edge repairs missing source
  evidence.
- The synthesizer/reviewer zig-zag has a loop cap of two.
- One bounded auditor-to-writer edge repairs presentation when evidence already
  exists.
- Explorer evidence gaps cannot be disguised as writer revisions.
- Every spawned agent must be joined and closed.
- The strategist mechanically appends verbatim explorer returns to
  `research.md`; the writer never authors or rewrites that source record.

## Exact-binding evidence contract

For every load-bearing claim, fixture, object, and connection, evidence closure
requires:

- stable claim or fixture ID;
- immutable source identity;
- exact source-local selector, anchor, or structured pointer;
- explorer return reference;
- evidence scope;
- proof status: `observed`, `executed`, or `unverified`; and
- exact pointer sufficient to reproduce the claim.

An invented selector, a strategy document, a component diagram, `TODO`, or “the
transcript supports it” does not close evidence.

## Vertical witness

The keel is one browser-testable route:

1. the user asks naturally for help on an active thread;
2. Augmentor grounds context in explicit user preferences and source records,
   with visible sources and no graph-as-truth claim;
3. a bounded reasoning request produces a typed judgment, not an approval;
4. Augmentor previews a two-child strategy and receives one explicit approval;
5. two isolated host-owned children run while the parent conversation remains
   usable;
6. one child requests targeted clarification and the other returns a result or
   blocker;
7. state survives reload and the user consumes one result without sibling
   context bleed;
8. Augmentor separately proposes a memory-intake candidate; no memory,
   ontology, authority, or promotion write occurs without its owner.

The first slice fails if it only renders diagrams, graphs, schemas, cards,
prompts, dashboards, or receipts.
