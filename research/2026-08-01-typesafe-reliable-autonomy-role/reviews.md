# TypeSafe Custom Role — Reviewer Findings

## Precedent and ownership reviewer

Verdict: the original Rank 1 is `BUILD-FROM-OWNED`, not precedent-clean. Most advertised ownership already sits with TypeSafe's Synthetic Data, Product, Platform, Infrastructure, and Developer Advocate roles. The narrow surviving seam is building task environments, replayable model-and-tool qualification harnesses, cross-layer failure evidence, and regression gates. The reviewer recommends a conventional frontier-lab family—`Member of Technical Staff, Agent Evals & Environments`—embedded beside or within Synthetic Data. Product retains task and release ownership; Synthetic Data retains model evaluation and training-intervention authority; Platform retains runtime reliability.

Exact ownership question:

> Who at TypeSafe currently owns the end-to-end path for a multi-step, tool-using real-world task—from defining the task environment and grading contract, through replayable traces and cross-layer failure attribution, to landing the result as a regression gate—and which parts of that path are explicitly outside the Synthetic Data and Product Engineer charters?

Rank 2 substantially overlaps existing evaluation tooling. Rank 3 maps either to Technical Program Management or folds into the technical Rank 1. The no-standalone-role fallback is precedent-clean.

## Non-vacuity reviewer

Verdict: Rank 1 is `GO` only after replacing an abstract “economically valuable task” with an admitted real task and economic experiment. Required conditions:

- one existing, recurring, reversible TypeSafe task;
- current task volume, human minutes, model/tool cost, latency, accepted-result rate, and material failure baseline;
- an actual versioned model interface and tool sandbox;
- candidate-authored running code: task adapter, frozen fixtures, effect sandbox, required event schema, failure injector, replay command, and digest-bound run bundle;
- a prospective sample size, quality threshold, cost ceiling, trace-completeness rule, and invest/hold/stop decision rule;
- injected stale-input, incomplete-trace, unauthorized-effect, partial-completion, missing-telemetry, and replay-divergence failures;
- a bounded intervention, same-contract rerun, and comparison of quality, human burden, runtime cost, latency, failure visibility, and upkeep.

Contracts, taxonomies, diagrams, and decision packages without the running trial are `KILL`. A regression gate lands only when measured decision value exceeds maintenance cost. Rank 2 survives only as an embedded source-to-check impact pilot. Rank 3 is killed because making it non-vacuous collapses it into Rank 1.

Admission rule:

> Within the first 30 days, TypeSafe must supply one existing task, live internal interfaces, a measurable baseline, functional collaborators, and a decision owner. The candidate must build and run the thin slice. If any input is absent, if another team already owns the complete loop, or if the measured decision value cannot justify the harness cost, activate the no-standalone-role outcome.

## Definitional and claim-boundary reviewer

Verdict: the original package is not writer-ready. Rank 1 is repairable, Rank 2 needs narrowing, and Rank 3 should be killed.

Required semantic repairs:

- `reliability` may mean only task-contract explicitness, replayable local evidence, failure visibility, and fail-closed routing—not model, production, safety, availability, or causal reliability;
- `autonomy` may mean only one bounded multi-step model-and-tool task in a controlled trial—not independently operating production agents;
- `systems` is supported only by repository-local executable harnesses and interfaces—not frontier-systems research or production-systems ownership;
- `qualification` returns a non-authorizing recommendation; designated owners retain all model, product, infrastructure, risk, and release decisions;
- failure classification produces evidence-backed hypotheses and unresolved cases, not exact attribution.

The reviewer recommends `Autonomy Task Qualification Engineer` for Rank 1 and `Research Engineer, Task Specification and Traceability` for Rank 2. Add Staff seniority only after employment-history evidence is established. Rank 3 is killed as a duplicate/process layer.

Approved public capability posture:

> My repository work includes bounded, repository-local contracts and prototypes for deterministic validation, failure-first gates, replay, and inspectable handoffs. I would propose applying that practice to one controlled, falsifiable model-and-tool task trial.

Forbidden public claims include frontier-model reliability expertise, safe AI, production autonomy qualification, end-to-end model reliability, ownership of model evals or synthetic-data evaluation, a general reasoning engine, formal proof of AI correctness or safety, production-grade multi-agent orchestration, exact cross-layer failure attribution, TypeSafe having an unowned seam, and private project names, paths, authority terms, promotion levels, or copied private prose.
