# OEW Runtime Rebuild Lessons Research Strategy

This is a non-authority Inventory read model of a confirmation-ready but
unconfirmed research proposal. It does not authorize the dispatch, change the
active Goal or selected SWU, mutate OEW source, alter package manifests or
locks, generate a build, run the browser witness, promote ontology authority,
or establish release or production readiness.

## P1 Trigger Decision

The dispatch is required by synthesis, isolation, context protection, and
parallelism. It must reconcile empirical package/runtime behavior, the complete
blocker and Refresh chronology, and a clean-slate minimum architecture without
allowing the current plan to validate itself. The admitted type is `research`
under schema `0.8.0`.

The working hypothesis is intentionally non-authoritative: exact package SHA
values guard reproducibility rather than cause compilation failure; the
observed strict-TypeScript diagnostics are a real source failure; and the
current ownership and work-pack granularity may have amplified an ordinary
repair into repeated Refresh cycles.

## Candidate Matrix

The dispatch compares four candidates:

1. retain the current `007T -> 013B -> 014 -> 014V` chain;
2. rebuild as a thin private adapter within the existing upstream pnpm
   workspace;
3. use a static or Node-native first browser-prototype lane;
4. create a new generalized runtime.

Every candidate requires an owner/precedent label, a non-vacuity witness, a
definitional-soundness result, and a retain, defer, or kill verdict. Every
affected artifact requires `KEEP`, `REBUILD`, `DELETE`, or `DEFER`.
