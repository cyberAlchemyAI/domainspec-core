# RWO And Codex Runtime Migration Audited Research Result

This is a candidate, non-authority Inventory read model of an audited research
result. It does not authorize implementation, adapter registration, provider or
model execution, Task Session admission, Craft or Goal mutation, lifecycle
promotion, Git operations, publication, release, deployment, or production use.

## Decision And Claim Ceiling

The selected topology places Codex App Server as a private physical leaf beneath
RWO. The RWO Go coordinator and journal remain the sole owners of durable
delivery, retry, recovery, ambiguity, and raw provider-event truth. The RWO Rust
kernel remains the semantic compiler, reducer, and no-successor owner. Arcanum's
provider-neutral runtime is the outer projection-only envelope, while Task
Session retains admission, receipt topology, owner review, and closeout.

This is an audited architecture and executable-fixture plan, not implementation,
Codex compatibility, lifecycle readiness, or production evidence.

## Eve Active-Byte And Historical-Preservation Ledger

The exact filesystem search window closed 2,378 literal Eve occurrences across
284 literal-hit files, plus three path-only fixtures and one semantic-only
selector family: 288 classified files, zero unclassified, and zero duplicates.
Active provider code is replaced or generalized; provider-neutral Eve-shaped
names are generalized; tests and current documentation migrate with their
owners; generated and lifecycle material is regenerated or superseded; immutable
history remains unchanged. This denominator is not Git tracked, ignored,
deleted, or post-window closure.

## Current Component And Authority Map

The authority-preserving chain is: Task Session admission and single-use ticket;
Arcanum outer runtime envelope; private RWO adapter; RWO Go coordinator and
journal; Rust semantic reducer; private Codex translator; provider-evidence
validation; durable Go admission recording; Rust semantic acceptance; generic
status projection; executor receipt; capability-owner verdict; routed-owner
synchronization; Task Session governance terminal; privacy-safe observation.

Codex collaboration does not satisfy Orchestrate, App Server goals do not drive
Craft or Goal, and no second scheduler, journal, retry owner, admission owner, or
runtime envelope is introduced.

## Provider Profile And Contracts

The first Codex profile is intentionally narrow: private stdio transport,
explicit process/connection/thread/turn/item/request identities, raw event
persistence before normalization, and host-enforced denial for ungranted tool,
network, shell, realtime, global administration, or broader filesystem effects.
Runtime permission is not human confirmation, semantic acceptance, owner
approval, Craft apply, or lifecycle promotion.

## Identity Persistence And Receipt Rules

RWO command, cursor, operation, attempt, send-try, armed-send, accepted event,
and terminal identities remain distinct from Codex process, connection, thread,
turn, item, and server-request identities and from Arcanum Task Session,
Orchestrate, Craft, and Goal identities. Each send try has one immutable,
durably synced arm record before provider write. Exact duplicate evidence is
inert; mismatched replay blocks; ambiguous creation is reconciled uniquely or
frozen fail-closed.

## Finite Executable Trace Plan

The findings specify self-contained traces for success and no-successor,
permission pause, stale input, interrupt and recovery, three ambiguity branches,
exact duplicate no-op, replay mismatch, invalid or post-terminal events, Task
Session closeout failure, and inherited durability cuts. Each trace names its
identities, preconditions, ordered persistence and provider messages, result and
gate, first stop, forbidden effects, proof status, and exact future validator.
All Codex traces remain specified-unexecuted.

## Exact Durability And Eval Denominator

The durability/eval denominator has nine boundary IDs and 42 cases covering
store append and sync, cursor compare-and-swap, lease and fence, arm-before-send,
provider write, raw evidence, terminal convergence, Rust reduction and
admission, and outer projection. Existing fake-Eve evidence is historical
provider-substitution precedent only; it does not prove Codex behavior.

## Dependency-Ordered Non-Executed Implementation Work Pack

The proposed order is: fresh Git-aware byte inventory and ownership binding;
installed binary/source/schema/fixture parity; host denial and ambiguous-create
policy proof; private contract and raw-wire fixture implementation; RWO Go/Rust
migration; Arcanum adapter binding only if the provider-neutral public contract
must change; Task Session execution and owner closeout; observation; and a new
Refine/Invoke migration epoch with fresh validation and acceptance.

## Open Gates And Final Residue

Open gates include concurrent-byte ownership, real CLI worker wiring, binary and
source parity, negative host-policy witnesses, exact create reconciliation or a
freeze rule, executed raw-wire/crash-cut fixtures, and a fresh owner-approved
Work Pack. Historical Eve evidence is preserved rather than rewritten.
