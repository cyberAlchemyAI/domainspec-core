# Akashic Periodic-Table Graph-Schema Research Result

This entry is a non-authority Inventory read model. It makes a governed
research result discoverable but does not approve the findings, change Akashic
L0, admit an ontology, implement the proposed contracts, or authorize
publication or promotion.

## Run Outcome

The human-confirmed dispatch ran four explorers, one synthesizer, three
skeptics, one writer, and one auditor through one synthesis/reviewer zig-zag
and one bounded writer revision. The append-only dispatch ledger closed with
`loop_ceiling_reached`.

The final auditor accepted the architecture and three of four requested
corrections, but did not approve the findings because the executable
seven-principle fixture still lacks exact source bindings for `Mo`, `Gr`, and
two card-tag assertions required by the Q5 co-occurrence result.

## Smallest Surviving V1 Design

The surviving proposal keeps `SourceRecord` and `ClaimRecord` as the only
top-level semantic content kinds.

- Principles use a closed, role-specific Claim payload.
- Groups remain one of eight finite profile values stored on the Principle
  Claim.
- Captured corpus bytes and reviewed cited-work identities remain distinct
  Source roles.
- `illustrated_by` and `classified_in_domain` are the only proposed authored
  relation predicates, carried by structured relation Claims.
- Co-occurrence is a direct query join with cited-work witnesses, not an
  authored edge.
- Overlap, reinforcement, conflict, and tension remain deferred because the
  inspected corpus supplies no pair-specific assertion.
- The six named operations scan validated Inventory records directly; no
  persisted graph edge file, graph index, Olog runtime, or graph database is
  admitted for the first slice.

The operational proposal surrounds authored records with bounded,
commit-pinned GitHub ingestion, local raw-text and JSON Pointer selector
profiles, provenance-bound candidates, explicit review receipts, and
zero/one/many upstream-impact reports.

## Evidence And Execution Boundary

The corpus facts are pinned to
`jarulraj/periodic-table@a5771d00dad91b631bf015ecdb6a281b263185f1`.
Retrieval and corpus inspection support the observed groups, principles, card
counts, selected examples, and one candidate upstream tag addition.

The new roles, predicates, importer, selector profiles, review boundary,
queries, and impact suites are planned and unexecuted. Passing the proposed
acceptance command would establish finite retrieval, binding, validation,
determinism, and query behavior only. It would not establish semantic truth,
legal permission, extraction completeness, global scholarly-work identity,
ontology correctness, authority, or production readiness.

CyberAlchemy contributed private candidate design ideas and collision
warnings only. No private identifiers, owner routes, authority kinds,

contract, and no private planned witness counts as Akashic runtime proof.

## Unresolved Audit Blocker

The findings intentionally preserve unresolved fixture evidence rather than
inventing it:

- exact raw-README selectors for the `Mo` and `Gr` principle blocks;
- an exact JSON Pointer for the `Mo` tag observation on `osdi23-50`;
- an exact JSON Pointer for the `Gr` tag observation on `vldb2023-10`.

These four bindings are required before the seven-principle fixture can be
called fully evidence-bound or executable. The current `findings.md` remains
a useful candidate design, not an auditor-approved result.
