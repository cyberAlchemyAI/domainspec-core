# Co-Op Project Showcase And Recruitment Research Strategy Result

This is a non-authority Inventory read model of the proposed research strategy.
It does not authorize the dispatch, establish the external precedents, admit
project claims, author public copy, or authorize implementation.

## Corrected Scope

The Co-Op Engine is already the 45-minute weekly meeting. The researched
product is its dual-use project showcase: one browser artifact for live
presentation and self-guided recruitment, with a strong portfolio opening,
brief but substantial project openings, and progressive detail.

## P1 Trigger

All four triggers apply:

- synthesis across current external sources, fourteen project corpora, live
  and self-guided use, recruitment, two audiences, and three evidence lanes;
- context protection because raw evidence would overwhelm the parent;
- isolation so competing page architectures remain discardable;
- parallelism across information architecture, facilitation, project truth,
  and recruitment decisions.

## Lanes, Groups, And Subagents

- `lane_z_explorers` builds and attacks the portfolio-first hypothesis:
  - `Ahrens, Sönke` compares portfolio, editorial index-to-detail, and
    browser-native presentation patterns.
  - `Senge, Peter` tests live facilitation, projection, and handoff to later
    self-guided browsing.
- `lane_a_explorers` tests a genuinely different decision-first route:
  - `Alexander, Christopher` verifies the fourteen project corpora and derives
    a shared opening/detail content grammar without erasing project voice.
  - `Christensen, Clayton` compares problem-first, skill-first, domain-first,
    ask-first, and project-first contributor journeys.
- `Simon, Herbert` synthesizes both lanes into bridge decisions, a recommended
  architecture, an alternative, fourteen opening-content maps, a Whisper
  intake substrate, and evidence plans.
- `Popper, Karl`, `Taleb, Nassim Nicholas`, and
  `Quine, Willard Van Orman` apply precedent, non-vacuity, and
  definitional-soundness gates in parallel.
- `Drucker, Peter` writes `findings.md` only.
- `Brandenburg, Martin` audits `findings.md` only and recommends acceptance or
  one bounded revision. The parent remains the live-schema final approver.

The rejected decomposition was one agent per project or file. That would
duplicate the same content question fourteen times and fail to adjudicate the
portfolio-first versus decision-first architecture.

## Dependency Flow

Both explorer lanes run in parallel and feed the synthesizer. Synthesis
zig-zags with the reviewers for at most two loops, then flows to the writer and
auditor. Auditor-to-writer revision is capped at one. The dispatch has
`max_loops: 2`.
