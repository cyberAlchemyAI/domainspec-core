# Akashic Records Content-Library Architecture Research Result

This is a non-authority Inventory read model of an audited research report. It
does not turn the proposed schema into a canonical ontology, bind owners,
authorize implementation, or establish source truth, legal permission,
retrieval quality, agent throughput, or production readiness.

## Bounded Decision

Akashic Records should begin with contributor-attributed `SourceRecord` and
`ClaimRecord` files in Git. Deterministic Inventory and context-packet outputs
are generated retrieval projections over those authored records. Agent
capability profiles remain content-free; selected agents receive bounded,
digest-bound content packets.

RDF, SHACL, a semantic graph, an Olog substrate, rich epistemic record kinds,
and a persistent capability registry are not part of the smallest witness.
Ologs remain conditional on repeated total functional path equations and a
structure-preserving mapping need that survives a simpler validator.

## Schema And Relation Boundary

The proposed Phase-0 `ContentRecord` is a closed discriminated union with only
`source` and `claim` kinds. A source binds `resource_level`,
`identity_scope`, and typed identity bases so work, edition, manifestation,
and captured bytes cannot silently collapse. A claim embeds an attributable
evidence value with an exact source selector.

Raw `supported_by`, stored `input_to`, generic `is_part_of`, and
`derived_from` are killed for v1 because they are ambiguous or duplicate a
kind-specific authored fact. Categories, tags, concepts, collections, and
semantic relations remain deferred until a fixture proves distinct retrieval
or validation behavior. Any future graph node is a generated projection with
one `authored_record_id` origin and no independent authority.

## Agent Pull-Request Boundary

The candidate operating path is typed issue, trusted base-policy packet,
unprivileged `add-content` draft PR, deterministic checks, distinct
`review-content` findings, configured human owner review, merge, and
post-merge Inventory regeneration. GitHub documents component mechanisms, but
the target has not configured or witnessed this composition. Passing checks
cannot establish truth, fair interpretation, licensing permission, or owner
acceptance.

## Witness And Closeout

The smallest proposed implementation is one Phase-0 contract-and-witness PR:
two source records, three claims that exercise exact same-level source reuse,
closed schemas, single-fault negative fixtures, and a deterministic Inventory
projection. Context-packet freshness and forbidden control-plane mutations
belong to a later staging-PR witness.

The precedent reviewer passed the revised candidate. Non-vacuity and
definitional reviewers retained six blocker clusters at the registered loop
ceiling: phase ownership, exact normalization proof, evidence granularity,
lifecycle and attribution authority, source identity levels, and projection
identity. The writer preserved them in `findings.md`; the report auditor
approved that preservation. The parent accepts the report as the durable
research result, not the architecture as converged or implementation-ready.

## Next Route

Bind the Phase-0 schema/validator, source-identity, content/domain, rights, and
Inventory-generator owners. Then use Invoke to define and design only the
Phase-0 contract-and-witness PR. Every later record kind, relation, graph
projection, Research Tower record, agent registry, and alternate substrate
remains residue until it earns a separate witness and owner.
