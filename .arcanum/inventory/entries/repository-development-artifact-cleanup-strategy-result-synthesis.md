## Result

The dispatch answer is conservative: the best path is `build-from-owned`.
Immediate VS Code relief should use workspace `files.watcherExclude` and
`search.exclude` for generated/runtime pressure paths such as `.lake`,
`node_modules`, `.venv`, caches, build outputs, and inactive
`.claude/worktrees`. That editor relief is not cleanup proof.

The future cleanup capability should be a preservation-led dry-run gate:
classify artifacts, prove canonical successors or archive owner, preserve open
development packets, emit owner-scoped handoffs, and route destructive apply
work to a later bounded `task-session`.
