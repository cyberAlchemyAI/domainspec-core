# Augmentor, ResonantOS, SDK, and Living Archive Ontology Documentation Research Strategy

## Direct Strategy

The frozen proposal researches one source-grounded documentation experience in
which Augmentor is presented as the ResonantOS agent, the existing Add-on SDK is
part of its capability environment, the Agent API exposes bounded consultation,
and Living Archive owns source-bound, revision-aware knowledge and memory. The
page should be a human projection of the same typed graph available to machines,
not a separately maintained architecture story.

The working hypothesis splits the ontology into separately owned packages for
the ResonantOS system, Augmentor agent, Add-on SDK and add-ons, Agent API and
interface contracts, Living Archive knowledge and memory, and one cross-package
experience projection. Research must compare that federation with a monolith
and a view-only composition before selecting the MVP.

## P1 Trigger Decision

P1 passes on synthesis, context protection, isolation, and parallelism. The
question spans current ResonantOS implementation, Augmentor ontology and page
evidence, SDK and Agent API contracts, Living Archive memory-agent planning,
and prior ontology-presentation research. Competing ontology splits must remain
discardable until evidence is reconciled.

## Lanes, Groups, and Subagents

- Three parallel explorers own current implementation, documentation and Living
  Archive experience, and typed ontology federation.
- One synthesizer produces an exact-bound component graph, package split,
  information architecture, Living Archive contract, and literal MVP witness.
- Three parallel reviewers attack precedent and ownership, non-vacuity, and
  definitional collapse.
- One writer may author only evidence-closed `findings.md`; one auditor may
  approve it or return one bounded revision. The parent remains final approver.

Both multi-agent groups contain every unordered anti-bias pair required by the
current dispatch contract. Two independent pre-confirmation tension checks pass
over the frozen sheet digest.

## Dependency Flow

`explorers -> synthesizer <-> reviewers -> evidence closure -> writer -> auditor
-> parent`, with at most one source-evidence repair loop and one bounded writer
revision loop. Writer revision cannot repair missing explorer evidence.

## Strategy Inventory Packet

The DomainSpec machine Inventory is lookup-ready. ResonantOS and Living Archive
have no machine Inventory in their current checkouts, so their owner sources
must be inspected directly. Selected precedents cover the accepted disposable
Augmentor graph, the ResonantOS/Living Archive seam, simple ontology
presentation, and ontology-to-agent-context explanation.

Current evidence already distinguishes the existing ResonantOS Add-on SDK from
the narrower planned ontology-consultation declaration. It also preserves the
Living Archive rule that source memory and derived projections cannot promote
ontology meaning automatically. The research must reconcile those facts with
the current Augmentor anatomy map, which presently describes the SDK seam too
broadly as planned and disconnected.

those exact findings and produce a non-executed MVP Work Pack. Its overlays are
baseline sequencing, hidden-structure x-ray, alternative tournament, memory

Refine dispatch is deliberately not materialized yet because future findings
and evidence-closure digests do not exist.
