# Augmentor User Understanding, Disposable Graph, and Bounded Reasoning Research Result

This is a non-authority Inventory read model of an auditor-accepted research
result. It makes the recommended Augmentor architecture and its implementation
boundary discoverable. It does not implement ResonantOS, install a memory or
graph service, create durable user state, promote an ontology, authorize the
private reasoning engine, verify a performance target, establish human benefit,
or prove production readiness or release.

## Dispatch Outcome

- Dispatch `2026-07-28-authority-memory-augmentor-integration` completed with
  four explorers, one synthesizer, three skeptics, one writer, and one auditor.
- One exact-path explorer-feedback route and two synthesizer/reviewer

## Accepted Architecture

Augmentor should compile a few explicit request/session handles with existing
Living Archive source records, ask the existing memory domain for a disposable
source-bound semantic projection, run one deterministic operation, and
optionally explain that result with one claim-grounded provider call.

The derivation direction is:

`extension settings + ephemeral handles + owned source refs/digests ->
memory-owned disposable semantic index -> bounded projection ->
operation-specific deterministic result -> optional grounded presentation`.

The product experience is a better answer plus a quiet context-status control
that lets the user inspect, exclude, correct, forget, or disable the context.
It is not a graph browser, receipt console, second memory provider, durable host
user ledger, or copy of private CyberAlchemy authority semantics.

## Literal V0 Witness

The complete first releasable verification target asks whether a release can be
deployed while the user explicitly requires verified rollback support.

- The user constraint remains an ephemeral handle outside the graph.
- A source-bound `GraphDelta` materializes a `TaskGoal`, a `TaskConstraint`,
  and their `requires` edge in the memory-owned disposable index.
- A bounded one-hop projection contains two nodes and one edge.
- `find_missing_premise` searches for a current, uncontested
  `Claim --supports--> TaskConstraint` relation.
- With no such claim, the deterministic result is `missing_premise` and the
  answer refuses to recommend deployment until rollback evidence is supplied.
- Exclusion, handle correction, forgetting, memory-off, pending source
  correction, and accepted source correction each have distinct rerun
  semantics.

This is a design witness, not executed product evidence. Receipt-only,
schema-only, prompt-only, and graph-view-only increments are internal
scaffolding; none is a releasable v0 claim.

## Ownership And Transfer Boundary

- Existing extension settings continue to own explicit profile and Augmentor
  prompt values.
- v0 handles are request/session-only; no durable preference owner or host
  ledger is invented.
- Existing Living Archive records remain source truth.
- The existing memory domain/service owns the disposable semantic index,
  adjacency optimization, and cache lifecycle.
- One coordinator may call existing memory and provider functions and extend
  the sole prompt builder; it does not own a second retriever, prompt builder,
  provider, or source store.
- Generic DTOs, typed traversal, deterministic operations, grounding
  validation, and user-facing explanation may transfer to ResonantOS.
- Private CyberAlchemy vocabulary, authority snapshots, gate semantics,
  `CAV2-D*` terms, ACI bindings, and private receipt prose may not.

The finite private semantic evaluator is algorithmic precedent only. It is not
a complete engine, runtime authorization, or ResonantOS dependency.

## Verification And Claim Boundary

The accepted targets include at most 24 nodes, 48 edges, two hops, eight
handles, 1,200 added context tokens, 2,000 total reasoning-input tokens, and
zero or one model call. Named tests also target an 800 ms retrieval timeout,
GraphDelta p95 at 250 ms for at most 100 operations, direct-scan p95 at
150 ms, deterministic evaluation p95 at 20 ms, bounded derived storage, and
retrieval-quality thresholds.

Every number remains unverified until its named executable measurement records
the corpus, operation count, warm/cold posture, token estimator, provider or
stub posture, and percentile sample count. No research artifact establishes
implementation, passing tests, measured user benefit, authority promotion,
production readiness, or release.
