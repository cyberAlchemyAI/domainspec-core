# Arcanum As A ResonantOS Add-on Research Result

This is a non-authority Inventory read model of an auditor-accepted research
contract. It does not implement or validate the add-on, authorize a product or
Bootstrap mutation, admit a public capability, transfer DomainSpec or Saturn
authority, prove the browser witness, or establish readiness, promotion,
deployment, release, or production status.

## Recommendation And Claim Ceiling

The selected integration type is `BUILD-FROM-OWNED + NOVEL-ATTEMPT`.
Arcanum Bootstrap remains the sole installer, selector, refresher, and restorer
of generated public capabilities. ResonantOS remains the sole product owner of
manifest, discovery, installation, reviewed grants, bridge routes,
provider/delegation execution, run truth, artifacts, secrets, lifecycle,
readiness, promotion, and release. Augmentor remains a projection that
classifies unmatched ordinary language, renders immutable proposal bytes,
captures human intent, and displays owner-backed state.

No current integration or witness claim follows. The requested
`../workspace-resonantos` path is absent, the corrected target remains
owner-unconfirmed, and the nested product checkout is stale.

## Expected Future End State

A later implementation may expose a selected public Arcanum catalog through
one ResonantOS-native add-on and the existing authenticated loopback host.
Augmentor may present a side-effect-free proposal and collect edit, decline,
clarification, or approval intent. The host must validate and persist exact
approval, enforce scoped capabilities, invoke retained owners, persist their
truth, and return opaque projections. Opening, attaching, consuming, and
requesting memory intake remain separate user actions.

## Owner-Preserving Contract

The accepted proof chain is:

`deterministic resolution -> authenticated bridge -> scoped capability gate ->
host-owned exact approval -> retained execution owner -> persisted owner state
-> redacted Augmentor projection`.

HTTP, authentication, capability, registration, approval, receipt, UI, or
browser success never substitutes for owner-backed execution or terminal
truth. The result separately defines manifest requests, reviewed grants,
installation, and enablement; preserves the Alpha browser-token exception;
separates receipt, observability, evidence, readiness, promotion, and release;
and separates disable, uninstall, product rollback, Bootstrap restore,
promotion, and release.
