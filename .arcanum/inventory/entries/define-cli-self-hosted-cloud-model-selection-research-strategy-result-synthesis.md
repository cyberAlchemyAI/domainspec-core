# CyberAlchemy v2 Define CLI self-hosted cloud model-stack selection research strategy

This is a non-authority Inventory read model of a confirmation-ready research
strategy. "Self-hosted cloud" means CyberAlchemy operates an inference endpoint
over a pinned open-weight checkpoint on rented or owned GPU infrastructure. It
does not mean laptop-local inference or a proprietary managed-model API.

## P1 trigger decision

Dispatch is required because the answer must synthesize current checkpoint,
license, inference-runtime, accelerator, cloud-infrastructure, and cost evidence
with the private Define product and session workload. Those facts are
temporally unstable, and "best" requires independent precedent, concrete
capacity and cost witnesses, and definitional challenge.

## Lanes, subagents, and dependency flow

- Explorers run in parallel: Turing owns the Define workload and evaluation
  rubric; Shannon owns exact checkpoint, license, precision, serving runtime,
  VRAM/KV-cache, and GPU-topology evidence; Porter owns total infrastructure
  economics and utilization sensitivity.
- Noether synthesizes one complete primary stack, one lower-cost fallback, and
  scale, switch, and escalation thresholds without collapsing reasoning
  quality, serving behavior, reliability, privacy/license fit, or total cost.
- Lakatos, Russell, and Wittgenstein independently attack precedent, concrete
  capacity/cost witnesses, and definitional collapse.
- Baez writes `findings.md` only after evidence closure; Brandenburg audits it
  and may request one bounded writer revision.

The fixed dependency spine is explorers -> synthesizer <-> skeptics -> writer
-> auditor, with one bounded missing-evidence feedback route and one writer
revision. For the first fair pilot, the same frozen checkpoint and serving
identity must serve planner and implementer within each task block. Final
approval remains with the parent.
