# Augmentor Routing And Multi-Session Fabric Research Result

This is a non-authority Inventory read model of an auditor-accepted research
blueprint. It does not implement ResonantOS, accept a runtime schema, import a
private Necronomicon session store, create a new routing or job registry,
change Spellcraft, execute the two-child witness, measure route quality, or
establish production readiness.

## Status And Product Thesis

Augmentor should be one conversational shell without one global mutable
context. Each user turn is first interpreted against a thread-local active
interaction. Consequential routing is an immutable host decision. Approved
execution is correlated by a `Run` envelope that references, rather than
replaces, current command, registry, approval, ComputeJob, goal, delegation,
task-workspace, dispatch, artifact, evaluation, and memory owners.

Current ResonantOS already has project/thread contracts, goal workspaces,
bounded delegation/task workspaces, durable shell persistence, command routing,
and goal/delegation artifacts. Active chat execution remains one global
transient run. General child concurrency, run ancestry, notification runtime,
join/resume behavior, and the browser witness are absent.

## State And Ownership Model

The smallest surviving hierarchy is interface focus over projects and threads,
with at most one active interaction and one foreground run per thread plus
policy-bounded child runs. These cardinalities are independent.

The derivation is one-way:

`user turn -> immutable RouteDecision -> current owner gate -> immutable
ContextSnapshot -> Run correlation -> owner execution/receipt -> append-only
transition/outcome -> explicit artifact attachment or memory intake`.

Runtime `Interaction` and `RouteDecision` records are public-neutral
ResonantOS-owned projections of admitted routing precedent. They do not import
or duplicate private Necronomicon state. `Run` is a correlation envelope, not
a second execution job, workspace, artifact, or route authority.

## Classification And Route Decisions

Classification resolves explicit interrupt, side note, pending response,
handoff continuation, fresh route, and material ambiguity before capability
choice. Low-confidence routes are offers, never silent execution.

Easy is one-off and bounded, Test belongs to an evidence owner such as
Experiment Harness, and Hardening belongs to Spellcraft for reusable
composition or Sigil Development for a primitive contract change. These are
different owner/evidence levels, not cosmetic UI modes.

Capability gaps search current installed surfaces and canonical registries,
offer only credible fallbacks, and block honestly when none exists. Adding a
capability or authoring a reusable artifact remains explicitly owner-gated.

## Repaired Notification-Control Contract

The proposed policy inherits from run to thread to project to user default,
with explicit mute, unmute, and snooze. A muted clarification remains visible
and keyboard-answerable without stealing focus. Delivery, unread state, and
result consumption are independent. Progress coalesces, restoration does not
reannounce, and only destructive or imminent-loss events may bypass mute.

Notifications remain projections. They cannot mutate runs, interactions,
artifacts, blockers, memory, or execution authority.

## Literal V1 Browser Witness

The first product acceptance contract keeps the main architecture conversation
active while two approved children run: a governed subagent-strategy proposal
and an isolated Whisper page. The user switches threads; neither child pauses,
reparents, or receives new-thread context.

Only the strategy child asks a clarification. The user answers through its
muted but discoverable notification, and only that child changes. Whisper
returns one owner artifact; strategy returns a result or blocker. Reload
restores unread projections without reannouncement. Results are consumed
independently, and planted secret/prompt/artifact markers prove no bleed or
silent memory intake.

This is an executable acceptance contract, not current runtime evidence.

## Routing-Quality Fixture Matrix

The accepted blueprint names fixtures for continuation, side note, fresh
route, ambiguity, unsupported capability, Easy, Test, Hardening, protected
actions, two-child isolation, targeted clarification, sibling cancellation,
blocker/resume, restoration, notification control, secret containment, and
late-result quarantine.

Proposed v2 gates include at least 95 percent exact disposition accuracy,
macro-F1 of at least 0.95, a complete confusion matrix, zero silent
delegations, zero protected false continuations, 100 percent mutation
owner/confirmation correctness, and zero explicit-command regressions. Error
costs distinguish false continuation from false fresh routing and unnecessary
clarification. These thresholds require evaluation-owner acceptance and
execution; the router cannot grade itself.

## Integration Route And Verdict

- **v0 — infrastructure only:** public-neutral classification projections,
  immutable decisions/outcomes, current-owner revalidation, normalization, and
  honest workspace/owner references. Not product acceptance.
- **v1 — first product acceptance:** thread-local interaction/run projections,
  immutable snapshots, child correlation, targeted clarification, notification
  control, cancellation/blocker/restart/resume semantics, explicit attachment,
  and the live two-child browser witness.
- **v2 — evaluated quality:** run the labeled corpus and browser regimes through
  Experiment Harness or an explicit evidence owner, calibrate budgets, and
  route reusable composition or primitive changes to their lifecycle owners.

The reviewers closed precedent/duplication, non-vacuity, and non-collapse.
Evidence closure returned `ready`. The auditor returned
`RECOMMEND_ACCEPT` after one bounded citation-only writer revision. The parent
accepted the research artifact and closed the dispatch with
`exit_reason: resolved`.

## Open Decisions

Accepting owners still need to decide the admitted public-neutral routing
artifact, persistence and retention, scheduler ceilings, context-update
semantics, cancellation acknowledgement, restart reconciliation, default
notification policy and safety taxonomy, artifact/memory intake gates, v2
evaluation ownership and corpus stewardship, and the update point from the
consumer checkout before implementation.

No SWU is selected and no product implementation is authorized by this
Inventory entry.
