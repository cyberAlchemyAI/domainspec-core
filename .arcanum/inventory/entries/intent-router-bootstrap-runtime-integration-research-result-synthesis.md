# Intent Router Bootstrap and Runtime Integration Research Result

This non-authority Inventory read model records the auditor-accepted research
result. It does not authorize public extraction, accept canonical Arcanum
source, generate a Claude or Codex package, implement an orchestrator adapter,
admit a private reasoning-stack component, promote, publish, install, deploy,
release, or establish production readiness.

## Direct result

The private intent-route resolver is a real standalone component with a live
34-test pass, but Arcanum Bootstrap cannot select it today because no canonical
public sigil or spell owns it. Direct current Bootstrap integration is killed.

A future topology is selected in principle:

```text
runtime-owned intent capture
    -> typed request
    -> digest-bound read-only catalog
    -> generic zero-authority resolver
    -> candidate | ambiguous | no-match | invalid
    -> human confirmation
    -> existing canonical Dispatch/group/seat
    -> existing host binding, authorization, execution, persistence, effects
```

The private implementation cannot simply be copied into public Arcanum. A
fresh project-agnostic extraction, canonical acceptance, generated runtime
promotion, release, consumer installation, and private admission are separate
authority transitions.

## Bootstrap and runtime profiles

After an accepted public sigil exists, Bootstrap can project one canonical
closure into thin Claude and Codex packages. That establishes a feasible path
to presence parity, not current behavior parity.

The research freezes an implementation-ready future acceptance contract across
five surfaces and 78 logical cases. It binds schemas, numeric exits, canonical
bytes, timeout, provenance, disable, rollback, and zero-authority counters.
The contract is design only: no runner, generated package, release archive,
consumer install, adapter, or parity witness currently supplies those paths.

## Orchestrator and authority boundary

The smallest future orchestrator seam is a thin process-bound JSON adapter
before the existing host workflow-binding path. The adapter validates transport
and integrity only. It does not repair intent, rank or select routes, open a
Dispatch, create a registry or lifecycle, authorize, schedule, persist
independently, execute, or claim effects.

Only an already confirmed canonical Dispatch/group/seat may cross the binding
seam. Human choice, binding, authorization, execution attempt, observed effect,
and required receipt remain distinct and independently fail closed.

## `cyberAlchemy-v2`, Augmentor, and reasoning

The resolver is currently part of `cyberAlchemy-v2` only in the
repository/component sense. No ACI, Augmentor, ResonantOS, orchestrator, or
whole reasoning-stack consumer installs or invokes it.

It advances the Agent Reasoning Engine narrowly by making pre-inference
capability routing deterministic, traced, digest-bound, and abstaining. It does
not supply semantic judgment, object-level inference, actor protocol,
memory/replay, effects, or a whole reasoning engine.

Augmentor, Claude, Codex, or another runtime may later own a source adapter that
forms a typed request or renders the disposition. This transfers no resolver,
Dispatch, approval, authorization, execution, persistence, or effect authority.

## Accepted project path

The ordered path is:

1. approve the public/private extraction boundary;
2. bind canonical catalog inputs, catalog-projector ownership, request
   normalization ownership, and ACI artifact-reference fields;
3. author and review a fresh generic zero-authority public contract;
4. separately accept it as canonical Arcanum source;
5. implement the core runner and synthetic fixtures;
6. generate disposable Claude and Codex packages;
7. execute the frozen presence, behavior, negative, disable, provenance,
   timeout, and rollback acceptance contract;
8. separately promote, publish, and prove a disposable consumer install;
9. implement the orchestrator adapter in advisory shadow mode;
10. prove owner non-substitution at the workflow seam; and
11. add a separate ACI-subordinate private entry-routing and semantic-evaluator
    handoff witness.
