# Augmentor Unified Agent Architecture Research Strategy

This is a non-authority Inventory read model of a confirmation-ready but
unconfirmed research proposal. It does not authorize the dispatch, register
agents, implement Augmentor, change Arcanum, write memory or ontology state,
make an authority decision, promote an artifact, deploy, or release.

## Direct strategy

Research one architecture with three non-collapsing planes:

- human: ordinary conversation, understandable user context, threads,
  children, grounded answers, correction, forgetting, and progressive route
  controls;
- runtime/control: Interaction, ContextSnapshot, RouteDecision,
  StrategyProposal, bounded reasoning, approval, Dispatch Spec, Orchestrate,
  host-owned Runs and effects, joins, and result consumption;
- authority/knowledge: explicit handles, Living Archive sources, memory-owned
  disposable semantic index, Inventory evidence, ontology candidate/map,
  authority decision, and governed projection.

The planes integrate through typed references and events, not shared mutable
ownership. Every connection must name producer, typed artifact or event,
consumer, authority owner, exact selector, timing, and failure behavior.

## P1 trigger decision

Dispatch is required by synthesis, context protection, isolation, and
parallelism. Separate accepted Augmentor results for user graph/reasoning,
routing/session, and Subagent Strategy must be reconciled with the bounded
reasoning evaluator, IDE Ergonomics, Arcanum guidance, Inventory, ontology,
CyberAlchemy v2 authority, Living Archive, and current ResonantOS.

The live type is `research`; the admitted sheet uses schema `0.8.0`.

`Shannon, Claude` synthesizes. `Lakatos, Imre`, `Gödel, Kurt`, and

after exact-binding evidence closure. `Brandenburg, Martin` audits it; the
parent remains final approver.

## Dependency flow

`explorers -> synthesizer <-> reviewers -> exact-binding evidence closure ->
writer -> auditor -> parent`

The route permits one bounded synthesizer-to-explorer evidence repair, two
synthesizer/reviewer exchanges, and one auditor-to-writer revision. Every agent
must be joined and closed. The strategist mechanically assembles `research.md`
from verbatim explorer returns; the writer does not.

## Inventory preflight

The owner machine index passed lookup readiness with zero failures and 111
inherited uncontrolled-tag warnings.

Selected evidence includes the verified user-graph/reasoning,
routing/session, Subagent Strategy, and reasoning-engine contract results plus
candidate IDE Ergonomics, Living Archive, Inventory-to-ontology,
ontology-operationalization, and CyberAlchemy v2 authority/determinism
evidence. Superseded unexecuted strategies are excluded.

The design consequence is three independent lanes, an exact connection
catalog, one narrow vertical witness, and strict rejection of duplicate
routing, session, execution, memory, graph-truth, reasoning, ontology, or
promotion owners. Inventory remains discovery only.

## Exact-binding evidence contract

Every load-bearing claim, fixture, object, and connection must preserve a
stable ID, immutable source identity, exact selector or structured pointer,
explorer return reference, evidence scope, proof status, and reproducible
pointer. Diagrams, proposal prose, invented selectors, or TODOs do not close
evidence.

## Required architecture output

The final research must contain the system context, current-versus-target
matrix, plane and owner map, non-collapsing object catalog, exact connection
catalog, end-to-end turn and knowledge/control sequences, session hierarchy,
one-interface journeys, capability-gap routes, public/private boundary, absent
adapter map, dependency-ordered increments, exact vertical witness, tests,
overhead budgets, verdict matrix, and open owner decisions.

## Vertical witness

The architecture must prove one browser-testable route that grounds explicit
user context, produces a bounded typed judgment, previews and receives one
approval for two isolated children, preserves parent conversation, handles
targeted clarification and partial success/blocker, survives reload, supports
selective result consumption, and separately proposes—but does not
automatically execute—a memory-intake candidate.
