# CyberAlchemy Naturalized Interface Design Research Result

This is a non-authority Inventory read model of an auditor-accepted research
dispatch. It selects a bounded prototype direction but does not implement it,
validate a human benefit, mutate ontology or definitions, grant authority, or
authorize publication, release, deployment, or production use.

## Dispatch Outcome

The eight-agent governed research dispatch completed all five waves with one
feedback loop. Evidence closure was ready, both final reviewer gates passed,
the orchestration reducer completed, all 58 event records validated, and the
auditor accepted `findings.md` at SHA-256
`8a1e370c345fcefa9eaa5ede9eb08daf0d7aafd0ddb80a5746d531c9a0ed5604`.
One separate helper repaired only the writing-contract receipt boundary.

## Accepted Interface Direction

Keep the existing non-execution and proof-ceiling rules. Harden exact source
binding. Make one structural interface change: preserve floor, inspection,
filter, and focus state while the operator opens an unavailable System source
reference and returns. The result explicitly rejects a coupled
"naturalized" redesign as unsupported.

## VerificationPromptProjection Contract

The smallest structurally discriminable prototype experiment is a floor-bound
`VerificationPromptProjection` containing:

- `selected_floor_id`;
- exact bound evidence references;
- `known_evidence` and `unbound_evidence`;
- `verification_question`;
- `route_suggestion` with `executable: false` and no execution endpoint.

This is an evidence-bound read projection, not an agent action, learning claim,
task dispatch, workflow transition, authority decision, or recommendation of
human benefit.

## Continuity State Contract

The investigation-continuity change preserves the selected floor, active
inspection target, relation filter, and return focus before opening a System
reference. Closing or returning restores that exact state. The System remains
unavailable and outside the tower rather than becoming an implemented floor.

## Fail-Closed Source Binding

A missing source object, missing path, or digest mismatch must fail closed. An
Inventory entry cannot substitute for the bound primary source. The source
ledger preserves the crosswalk as candidate architecture discovery, the
naturalized-environments findings as rejected-after-loop-2 working synthesis,
and the named Lean declarations only at their audited ceiling.

## Verdict Matrix

- KEEP: K1 non-execution.
- KEEP AND HARDEN: K2 provenance and fail-closed source binding.
- CHANGE: C2 investigation-state continuity.
- EXPERIMENT: E1 floor-bound verification prompt.
- KILL: C1 standalone plane labels and E2 investigation landmark.
- DEFER: E3 task-relation links and E4 contrast versus decorative color.
- OUT OF QUEUE: E5 representation comparison.
- MERGE: A1 ambient appearance only as a future R1 control.
- REJECT: R1 coupled naturalized redesign and R2 static learning/update claim.

## Claim And Authority Boundary

Automated structure can witness bindings, state restoration, refusal behavior,
and non-execution. It cannot establish usefulness, comprehension, learning,
trust, workload reduction, preference, accessibility conformance, or transfer
to representative users and data. The White Tower remains a candidate-local
interface over one locked synthetic fixture.

## Residue

The naturalized source remains provenance-defective, its primary human papers
were not independently audited, and no human study has run. Screen-reader and
literal 200/400 percent zoom checks remain manual residue. E3 and E4 require a
named White Tower task, typed binding, and direct evidence re-audit before
admission. No product, ontology, authority, publication, release, deployment,
or production effect follows from this result.

## Next Implementation Decision

If the owner chooses to prototype, refine only the combined C2 plus E1 slice:
continuity-preserving System reference open/return and one fail-closed,
non-executable `VerificationPromptProjection`. Preserve the current locked
fixture, refusal behavior, source digests, keyboard/focus behavior, and
reduced-motion boundary; validate the implementation separately.
