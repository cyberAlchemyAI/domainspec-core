# Invoke one-shot workflow research findings

## Plain-language result

The workflow repeats Plan, Refresh, and Task Session because canonical Plan
authoring is not yet compiled into the exact frozen object Task Session admits.
Deterministic material, receipt, closeout, and route omissions therefore cross
the owner boundary before they are detected. Generic Refresh then performs
planning repair, projection synchronization, and material production under one
name, which makes valid transitions look like execution progress.

## Accepted architecture

Do not add a standalone admission compiler or another outer runner.

- Invoke Define/Design/Plan remain canonical authoring owners.
- Exact per-SWU producers own product or staged material bytes.
- Work Pack Readiness Audit phases 1–4 gain a deterministic, non-authoritative
  admission-projection generator and exact-binding validation.
- Decision Gate/human approval binds the frozen audit projection, canonical
  semantic digest, frontier, runtime identity, risk, and budget.
- Task Session Until Blocker remains the finite-frontier coordinator.
- Each unit still executes through one fresh, bounded Task Session.
- Continuation Router verifies canonical successors and closeout routes.
- Invoke Refresh is narrowed to genuine synchronization and receipt-bound
  closeout, not normal-path planning repair or execution.

The proof ceiling is `frozen-input-contractual-readiness`. Runtime drift,
command failure, unavailable tools, browser behavior, and external effects
remain empirical Task Session residue.

## Candidate verdicts

- KILL: harden Invoke Plan alone as a sufficient solution.
- KILL: add a duplicate closure stage.
- KILL: add a standalone compiler/materializer.
- KILL: use generic Refresh as the repair/admission lane.
- Conditional PASS: WPRA-internal no-authority admission projection.
- Conditional PASS: approved finite-frontier execution through Task Session
  Until Blocker, preserving one Task Session per SWU.

## Exact acceptance package

The research artifact specifies 19 proposed, unverified, unexecuted fixtures:

- one stable Body War SWU-001 replay;
- ten deterministic Body War omissions that must block before any Task Session
  request;
- one post-approval concurrent-drift runtime fixture;
- one projection-equivalence fixture;
- five semantic-invalidation fixtures;
- one empirical command-failure fixture.

Each fixture binds frozen paths, JSON Pointers, SHA-256 values, zero/one fault,
first-knowable and first-detected gates, owner, terminal code, receipt count,
allowed writes, and forbidden transitions. The final audit independently
validated all 19 contracts and 16 frozen input bindings.

## Runtime workflow residue observed during this research

The native dispatch coordinator resets action numbering after later waves and
cannot reopen a blocked gate after an authorized feedback turn. This run used
the same canonical action compiler with a cumulative offset and preserved the
blocked native evidence stream while recording post-feedback continuation
separately. Both event segments validate, but these are runtime defects to
repair before treating Orchestrate as a complete multi-wave feedback runner.
