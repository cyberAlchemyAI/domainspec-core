# Essays Rust desktop and supervised browser-control runtime research strategy

This is a non-authority Inventory read model of a completed but auditor-blocked
research dispatch. The surviving candidate uses Tauri with the existing editor,
an in-process Rust Essays core and SQLite, plus a separately supervised Chromium
worker controlled through an inherited CDP pipe. It does not select or admit the
stack, authorize browser execution, or replace the current Essays baseline.

## P1 trigger decision

Dispatch is required because the answer must synthesize exact Essays semantic
compatibility, Rust and SQLite realization choices, desktop/editor trade-offs,
local and remote transports, browser-control protocols, Unix process
supervision, security boundaries, and current open-source evidence. Independent
precedent, non-vacuity, and definitional challenges protect the result.

## Lanes, subagents, and dependency flow

- Four explorers run in parallel. Turing owns Essays semantic compatibility and
  the D65 predecessor chain. Shannon compares Tauri/Wry and Rust-native desktop
  or editor options. Hewitt compares in-process, Unix-socket or named-pipe,
  loopback, and remote HTTP topologies. Simon defines the finite browser-control
  denominator and compares direct CDP, Playwright, WebDriver BiDi, Rust clients,
  pipes, process groups, pidfds, cgroups, namespaces, and platform equivalents.
- Noether synthesizes one primary and one fallback architecture without
  collapsing browser coverage, command speed, authority, isolation, durability,
  or portability.
- Lakatos, Russell, and Quine independently attack precedent and licensing,
  concrete performance/failure witnesses, and definitional collapse.
- Baez writes `findings.md` only after evidence closure. Brandenburg audits it
  and may request one bounded writer revision. Final approval remains with the
  parent.

The dependency spine is explorers -> synthesizer <-> skeptics -> writer ->
auditor, with one bounded evidence-feedback route to explorers and one bounded
writer revision.

## Research result and next action

The research-level architecture survived semantic, non-vacuity, and
definitional review: keep React/Milkdown in Tauri; put accepted-state semantics
behind an in-process Rust core and SQLite repository; supervise a distinct
Chromium child; use direct CDP over an inherited pipe as the shortest-boundary
Chromium-specific candidate; and reserve Playwright for an evidenced
cross-engine fallback. All performance, D1-D15 completion, migration,
cross-platform cleanup, license/SBOM, and equivalence witnesses remain
`NOT_EVALUATED`.
