# CyberAlchemy Lab Foundation Research Strategy Result

This non-authority Inventory read model records a confirmation-ready research
strategy. It does not confirm or register the dispatch, run any proposed agent,
create the CyberAlchemy Lab product, ingest repository research, define or
promote ontology meaning, implement the IDE workbench, publish, deploy, release,
or establish production readiness.

## P1 Trigger Decision

The strategy is a dispatch because it must synthesize Tower System and Research
Tower semantics, a repository-wide and duplicate-prone research corpus, current
IDE workbench reality, ontology/authority boundaries, and external precedent.
It also needs context protection, isolated attacks, and parallel explorer and
skeptic lanes.

## Project And Initial Witness Boundary

CyberAlchemy Lab is proposed as a governed local research workbench that exposes
source-backed Research Tower knowledge through a candidate ontology projection
and the existing IDE workbench without making the projection or Canvas the
canonical source or authority.

The raw preflight observed 41 `TOWER.md` paths only when ignored/generated
paths are included. Because those paths include worktrees, test output,
handoffs, nested surfaces, and possible duplicates, the strategy treats "all
research" as a coverage problem that must define eligibility, identity,
version, supersession, privacy, exclusions, and residue.

The first proposed witness is one existing tower, one candidate-local ontology
projection, one read-only Canvas Tower Navigator, and exact source path/digest/
selector evidence. Personas, scoring, automatic promotion, bulk ingestion,
human-usefulness claims, publication, and deployment are excluded.

## Dependency Flow

`explorers -> synthesizer <-> reviewers -> evidence closure -> writer ->
auditor -> parent`.

- Synthesizer/reviewer zig-zag cap: 1.
- Synthesizer-to-explorer evidence feedback cap: 1.
- Auditor-to-writer revision cap: 1.
- Whole-dispatch max loops: 2.

The writer remains blocked when exact source, selector, digest, provenance, or
runtime evidence is unresolved and cannot be repaired through a declared edge.
