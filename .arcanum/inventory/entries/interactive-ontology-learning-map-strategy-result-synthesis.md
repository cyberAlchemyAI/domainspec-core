# Interactive Ontology Learning Map Strategy Result

This is a non-authority Inventory read model of the resolved research dispatch
`2026-07-14-interactive-ontology-learning-map`. It makes the accepted research
architecture searchable without promoting a projection schema, a CAV2 kind,
a DomainSpec relation, a Craft claim, or a publication decision.

## Trigger And Dispatch Shape

The P1 decision required a governed dispatch because all four triggers applied:

- **synthesis:** formal ontology, Craft interpretation, learning design, and web
  architecture had to be reconciled;
- **context protection:** the evidence corpus crossed large independent source
  families;
- **isolation:** formal/governance, historical/interpretive, and
  empirical/computational judgments needed distinct roles;
- **parallelism:** independent explorer and skeptic lanes could run concurrently.

The nine working roles were:

- Abramsky, formal/governance explorer: node, relation, provenance, proof,
  authority, and non-collapse constraints;
- Beer, Craft philosophy/formal explorer: operational cycle, formal cousins,
  structural analogies, philosophy of making, and universal horizon;
- Alexander, learning-system explorer: learner journeys, accessibility, graph
  contracts, rendering, layout, and scale;
- Simon, synthesizer: one reconciled candidate architecture;
- Meadows, precedent skeptic: ownership and reuse classification;
- Popper, non-vacuity skeptic: finite positive and negative witnesses;
- Quine, definitional skeptic: category-error and terminology gate;
- Lawvere, findings writer; and
- Bourbaki, independent final auditor.

The dependency flow was explorers to synthesizer, synthesizer in bounded
zig-zag with the three reviewers, reviewers to writer, and writer to auditor.
The reviewer group retained three separate gate powers. Runtime capacity
serialized the third launch and one cross-review turn, but did not merge roles.

## Accepted Architecture

The bounded recommendation is a **private, read-only projection compiler and
learning application**, not a live canonical ontology.

It classifies records across six internal planes:

1. source artifacts and revision-pinned anchors;
2. source-local semantic concepts and relations;
3. epistemic claims, proof scope, analogy, interpretation, and unknowns;
4. governance owner routes, gates, decisions, and authority posture;
5. Craft operational contexts, conditions, artifacts, residue, and
   recomposition; and
6. learner-facing projections and layouts.

These planes are not CAV2 canonical node kinds. The compiler emits three
separately stored views over stable identities:

- a governed semantic view;
- an authored learner concept map; and
- a non-semantic navigation view.

Removing learner and navigation edges must leave semantic bytes unchanged.
Projection remains distinct from promotion, authority, proof, and publication.

## Craft Claim Boundary

The learning spine preserves five non-collapsible levels:

```text
operational method
  -> formal correspondence in a named domain
  -> structural analogy
  -> philosophy of making
  -> universal/reality horizon
```

No level proves the next. “Building through models” is the operationally
supported reading. “Building transforms bounded reality” is an interpretation.
“Reality itself is building” remains an explicit speculative horizon. The
AutoBayes numbering discrepancy and independently unverified sibling Lean
claims remain visible residue.

## Concrete Witness And Build Recommendation

The primary witness is the Agent Execution Orchestrator SPEC:

- preserve the source-local admitted
  `PipelineRouteTemplate --contains--> StageContract` relation;
- keep `AssemblePipelineRoute --enforces--> StageContract` only as an
  `AttemptedRelation` plus residue; and
- never infer a CAV2 morphism or runtime result from the document row.

Financial Settlement is a separate positive document/schema learner fixture,
not business-runtime proof.

The first private witness should use immutable JSON, deterministic extraction,
a GET-only API, React Flow 12 with precomputed ELK layout, and equivalent DOM
hierarchy and relation-table surfaces. The 250-visible-node, 500-visible-edge,
and 1,500-total-node values are unmeasured review triggers, not library limits.

All executable endpoint, runtime, browser, assistive-technology, performance,
determinism, and publication checks remain `NOT_RUN`.

## Public And Authority Boundary

The integrated map stays private because it combines public Arcanum with
private CAV2 and DomainSpec evidence. A possible public surface is a separately
built, default-deny Arcanum-only candidate, never a redacted private snapshot.

Its test contract requires both:

- a positive non-empty Arcanum fixture with complete provenance; and
- negative private path/content injection in every declared output channel,
  failing before publishable output.

`projectionOwnerRoute` and `publicationOwnerRoute` remain distinct and
unresolved. A technically successful build cannot issue its own publication
verdict. No public derivative was built or approved by this dispatch.

## Dispositions And Reuse

- **Blocked:** missing source-owned CAV2 hom-sets, endpoint tables, path laws,
  exact projection vocabulary, SWU expansion, theorem citation, or proof
  verification.
- **Excluded from the MVP:** mutation, promotion, owner decisions, source
  editing, invented canonical kinds, account state, and automatic renderer
  switching.
- **Deferred pending gates:** RDF/SPARQL, inference, scale renderers, persistent
  learner state, and any Arcanum-only public derivative.

Closing a gate opens review; it never auto-adopts, promotes, proves, or
publishes the deferred object.
