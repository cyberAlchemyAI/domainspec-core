# Augmentor Unified Agent Architecture Research Result

This is a non-authority Inventory read model of an auditor-accepted research
architecture. It does not implement Augmentor, create a memory or graph owner,
execute the specified fixture, establish an evaluator/effect path, promote
ontology or authority state, publish a public capability, deploy, release, or
establish production readiness.

## Status And Direct Thesis

The accepted direction is `GO — BUILD_FROM_OWNED + EXPLICIT ABSENT ADAPTERS`
with `NO_WITNESS_CURRENT`.

Augmentor becomes one trusted conversational interface over retained owners,
not one collapsed state model. It may adapt, correlate, and progressively
project grounding, route choice, approval, concurrent work, artifacts, and
knowledge controls. It must not become a second router, scheduler, session
store, job/workspace/artifact owner, memory provider, graph truth store,
reasoning authority, ontology writer, effect authority, or promotion
authority.

## System Context And Retained Owners

The architecture separates three planes:

- authority/knowledge: provider-owned source truth, disposable derived index,
  Inventory candidate validation, ontology candidates, named authority owners,
  canonical artifacts, and optional governed projections;
- runtime/control: immutable route and proposal bytes, explicit approval,
  Dispatch Spec, Orchestrate actions, host-owned Runs, addressed revisions,
  joins, and selective result consumption;
- human experience: ordinary conversation, source visibility, progressive
  route disclosure, concurrent threads and children, correction, tombstoning,
  local intake drafts, artifacts, and accessible notifications.

Integration is by typed immutable references and events. Projection never
inherits source or execution authority.

## Non-Collapsing Object Model

The result explicitly separates source from index, retrieval from reasoning,
judgment from approval, proposal from execution, Dispatch from Run, Run from
Thread, join from consumption, consumption from intake, provider acceptance
from Inventory validation, candidate evidence from authority, ontology
candidate from decision, decision from transition, transition from canonical
artifact, and projection from source.

## Exact Connection Catalog

The report binds C01–C21 across turn/Interaction resolution, handle and source
selection, optional derived graph/projection, immutable context composition,
routing, preview, approval, future bounded reasoning, Dispatch Spec,
Orchestrate, host Runs, addressed clarification, join, consumption, provider
review, Inventory candidate validation, ontology review, named authority
decision and canonical write, and a separately owned protected-effect path.

Every target-only adapter is marked absent. Current owners retain their
authority, and missing owner/operation/schema paths fail closed.

## Exact Future V0 Witness Contract

The proposed local fixture pins literal UTF-8 bytes and SHA-256 digests for
sources, context before/after correction, deterministic results, turns, route
configuration/decisions, proposal, approval, Dispatch, child snapshots,
addressed revision, join, result consumption, local intake draft, and reload
seed. It also pins a 20-event parent/child protocol, counter checkpoints,
browser selectors/actions, accessibility assertions, and unexecuted timing,
storage, graph, token, and attention measurement contracts.

The journey covers grounded conversation, exact preview/approval, two isolated
children, continued parent conversation, A-only clarification, A blocked/B
done partial outcome, thread switching, reload without respawn, B-only
attachment, H-LATE tombstone, one session-local intake draft with zero trusted
writes, and a missing capability that blocks with zero effect.

This is `SPECIFIED FUTURE WITNESS; UNIMPLEMENTED AND UNEXECUTED`.

## Version Dependency Sequence

- v0 implements and executes the deterministic local fixture only.
- v1 binds accepted owner-backed production adapters without changing
  authority.
- v2 may add governed knowledge evolution and a separately admitted evaluator
  and effect path only after their owners, schemas, and executable evidence
  exist.

The reviewer group passed precedent/duplicate-ownership, non-vacuity/overhead,
and non-collapse after two bounded synthesis revisions. Evidence closure
returned `ready`. The auditor requested one selector-only writer correction,
then returned `RECOMMEND_ACCEPT`. The native 63-event causal stream validates
`PASS`.
