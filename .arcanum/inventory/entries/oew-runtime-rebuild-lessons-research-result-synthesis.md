# OEW Runtime Rebuild Lessons Research Result

This is a non-authority Inventory read model of an auditor-approved, closed
research dispatch. It records a diagnosis and a proposed next target. It does
not establish a working browser prototype, authorize implementation, select an
SWU, change ontology authority, or establish promotion, release, or production
readiness.

## Result

The package manifests and pinned SHA values are not the direct runtime failure.
One clean isolated replay produced the exit vector `[0,0,0,1]`: frozen install,
explicit core build, and dashboard tests passed; dashboard build failed in
`tsc -b` with 48 strict-TypeScript errors in exactly three OEW overlay files.
The frozen archive retained eight package manifests before and after the run,
the overlay owns zero manifests, and OEW retains one existing dependency-free
command registry. Recent work added zero manifests.

The reproducibility invariants were real, but exact ownership and work-pack
granularity amplified incomplete lock and build-order ownership into repeated
stop-Refresh-reselect cycles. From first-working selection, four Task Sessions
were consumed; three were blocked build or reproducibility sessions and none
reached a browser. The audited lower bound is at least 56 governance path-write
events versus 28 runtime implementation writes.

The thin direction needs no new package manifest. It requires strict typing
repair in `types.ts`, `loadOewBundle.ts`, and `store.ts`; build-from-owned
loopback `/oew-data/*` routing; forced focused typed-test discovery; and one
exact fail-closed Playwright runner and receipt.

## Evidence Boundary

The no-new-package browser sequence is proposed, not executed. The challenged
`2 -> 1` runtime-root, `4 -> 2` gate, and `6 -> 4/5` command reductions are not
measured results because the compared boundaries omit different materialize,
verify, serve, assertion, and cleanup operations.

Passing the future witness would prove only one local automated Poker-Team
journey. It would not prove ontology correctness, product acceptance,
promotion, release, or production readiness.
