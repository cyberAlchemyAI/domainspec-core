# EvidenceSets - Schema / Classification / View Primitives

Source dispatch: `2026-06-21-schema-taxonomy-view-primitives`

EvidenceSets are candidate Inventory read models. They group evidence-card IDs
for repeated lookup and handoff assembly. They do not imply definition,
constitution, axiom, discipline, ontology, schema, validator, or Context Builder
authority.

## `evset-governed-action-facet-enforcement-slice`

- Status: candidate
- Evidence cards:
  - `governed-action-facet-obligations`
  - `schema-facet-reference-only-shape-evidence`
  - `classification-facet-taxonomy-boundary`
  - `human-continuation-view-boundary`
  - `machine-checkable-view-validator-residue`
- Inclusion reasons: Supports the next buildable slice: specify a minimal
  governed-action-facet envelope and typed-residue grammar, then test it against
  one ordinary CyberAlchemy action plus one definition candidate, one
  constitution candidate, one axiom candidate, and one discipline/check
  candidate without promoting any of them.
- Excluded card refs:
  - `governed-facet-negative-controls`: belongs to validator-fixture design, not
    the core envelope concept.
- Handoff target: `definitions-governance`, `constitution-governance`,
  `discipline-governance`, and `decision-gate`.
- Synthesis note: Use this set when turning the audited research finding plus
  operator correction into a candidate action-constitution package. It permits
  design and test scaffolding; it blocks claiming enforcement before validators
  and owner routes exist.
- Index terms: `governed action facet obligations`, `action-method`,
  `schema_ref`, `classification_ref`, `human_view`, `machine_view`,
  `typed-residue`, `owner_route`, `source_posture`, `promotion-guardrail`
- Residue: The owner matrix, envelope shape, and typed-residue validator do not
