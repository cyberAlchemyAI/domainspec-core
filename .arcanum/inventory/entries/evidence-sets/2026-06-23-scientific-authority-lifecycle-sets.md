# EvidenceSets - Scientific Authority Lifecycle

EvidenceSets are candidate Inventory read models. They group evidence-card IDs
for repeated lookup and handoff assembly. They do not imply ontology,
definition, constitution, schema, ledger, invariant, pattern, or Context Builder
authority.

## `evset-scientific-authority-lifecycle-provenance-relations`

- Status: candidate
- Evidence cards:
  - `scientific-authority-lifecycle-thesis`
  - `operational-evidence-to-promotion-candidate`
  - `ontology-view-routing-boundary`
  - `authority-owner-decision-gate`
  - `pattern-authority-promotion-path`
  - `governed-artifact-nonprimitive-guardrail`
  - `relation-provenance-map`
- Inclusion reasons: These cards jointly preserve the candidate synthesis that
  CyberAlchemy's knowledge-promotion loop is a scientific-method-like authority
  lifecycle: operational evidence creates candidates, inventory preserves
  evidence, ontology views route meaning, owner decisions govern movement, and
  only surviving candidates can become pattern authority, invariant pressure, or
  constitution pressure.
- Excluded card refs:
  - `simple-ontology-authority-caveat`: useful presentation evidence, but
    excluded because this set is about the operational-to-authority lifecycle
    rather than public explanation.
  - `op-ontology-d19-demotion-boundary`: useful demotion precedent, but excluded
    because this set does not decide Operational Ontology.
  - `ledger-ontology-bridge-edge-kill-until-amendment`: useful bridge-edge
    open-link evidence, but excluded because this set is a synthesis and does
    not amend ontology schema.
- Handoff target: definitions-governance for naming; ontology route for relation
  review; architecture-pattern-inventory for pattern-candidate packaging;
  constitution-governance for invariant/constitution pressure; task-session only
  after owner routes choose a concrete mutation.
- Synthesis note: Use this set when a future task asks how CyberAlchemy closes
  the loop between operations and knowledge governance. The safe reading is:
  scientific method as authority lifecycle, not automatic promotion.
- Index terms: `scientific authority lifecycle`, `pattern authority lifecycle`,
  `knowledge promotion`, `operational evidence`, `OutcomeEvent`,
  `MetricObservation`, `PromotionCandidate`, `OwnerDecision`,
  `KnowledgeProjection`, `ontology view`, `inventory evidence`, `owner route`,
  `pattern candidate`, `architecture pattern authority`, `invariant pressure`,
  `constitution pressure`, `view is not authority`, `evidence is not authority`
- Residue: No canonical definition or schema exists for this lifecycle. Saturn
  and DomainSpec bridge claims remain outside this set until a later review adds
  source-backed cards.
