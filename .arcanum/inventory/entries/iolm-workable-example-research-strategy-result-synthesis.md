## Trigger And Dispatch Shape

The P1 gate required a governed dispatch because four pressures coincided:

- **synthesis:** live DomainSpec fixture contracts, the IOLM learner journey,
  provenance, Craft continuation, and CAV2 authority boundaries had to agree;
- **context protection:** compiler, work-pack, private-governance, and UI evidence
  were independently large source families;
- **isolation:** runnable-sooner, learner-first, and authority-safe judgments
  needed separate owners; and
- **parallelism:** three explorer lanes and two independent reviewer attacks could
  proceed without collapsing their methods.

The eight counted roles were:

- Abramsky, contract-first explorer: live graph, manifest, receipt, compiler,
  binding, and deterministic-check compatibility;
- Alexander, learner/UI explorer: the smallest useful screen, shared selection,
  accessibility protocol, local run path, and later renderer options;
- Beer, governance explorer: Craft context, provenance, posture, evidence, owner,
  revision, and publication boundaries;
- Simon, synthesizer: the reconciled fixture-backed route;
- Popper, non-vacuity skeptic: runnable witness, exact commands, and red controls;
- Quine, definitional skeptic: artifact-role, posture, semantics, and authority
  separation;
- Lawvere, findings writer; and
- Bourbaki, independent final auditor.

The dependency flow was explorers to synthesizer, a one-revision synthesizer and
reviewer zig-zag, reviewers to writer, writer to auditor, and one bounded
auditor-to-writer correction followed by final recheck. No synthesizer-to-explorer
feedback edge fired.

sidecar. It must first be proposed as `SWU-IOLM-00C-UI-A`, dependent only on the

for this slice nor proven compatible with the later implementation environment.

`contracts/source-binding.v1.json` must pin the three canonical paths, their
SHA-256 values, source-set digest, profile and profile digest, generator, kinds
digest, relationships digest, the `4 nodes / 3 edges` counts, and every stable
node and edge ID. Before serving bytes or binding a port, the gateway rejects
hash or field mismatch, any symlinked path component, repository-root escape,
and every non-canonical path.

The accepted processing seam is:

```text
PinnedMintedFixtureGateway
  -> MintedFixtureBindingGuard
  -> DemoSnapshotV1Adapter
  -> DemoSnapshotV1Guard
  -> QuestionSliceSelector
  -> Graph | Outline | Table
                       -> shared selection -> provenance inspector
```

The input is `fixture`; `DemoSnapshotV1` is a `generated-read-model` and the only
layer that adds `posture: candidate` plus `authority_effect: none`; UI lenses are
`projection`; run reports are `demo-evidence`. None is `source` or
`authoritative`.

## Observable Witness And Evidence Contract

The default view shows four stable nodes and three directed, labeled relations.
The focus question, “What does the Player do, and what supports that connection?”,
selects the induced two-node/one-relation slice. Graph, outline, and table remain
co-primary views of one immutable snapshot, preserve selection by full stable ID,
and feed one provenance inspector.

Automated Node tests cover only pure snapshot, slice, projection, selection, and
inspector models. Python tests cover binding and server behavior. Keyboard, focus,
reduced motion, rendered-DOM parity, and visual text/shape sufficiency remain
manual browser checks; pure-model results cannot stand in for them.

Every run owns:

```text
generated/runs/<run-id>/automated-results.json
generated/runs/<run-id>/manual-results.json
generated/runs/<run-id>/validation-summary.json
```

Manual results begin `NOT_RUN`. Overall status is `BLOCK` for binding/security
failure, `FAIL` for another required failure, `NOT_RUN` while any required manual
check is unperformed, and `PASS` only when every required automated and manual
check passes.
