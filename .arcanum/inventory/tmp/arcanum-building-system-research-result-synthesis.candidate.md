# Arcanum building system research result

## Result and claim boundary

The current Arcanum building system is not one runner. It is an owner chain:
Invoke authors the agreement; Work Pack Readiness Audit freezes and verifies
one semantic unit without granting mutation authority; Task Session admits and
executes exactly one SWU; Continuation Router joins a separate Refresh-owner
closeout; Craft may record recursive local state without becoming Work Pack,
execution, lifecycle, registry, or production authority.

The individual contract and fixture fragments are substantial, but this
dispatch did not prove one exact Invoke output through a real product execution,
real Refresh-owner join, synchronized result, and continuity cursor. The
complete positive path remains normative and unverified.

## Holistic owner chain

1. Invoke Define, Design, and Plan own intent, independent Design evidence,
   implementation layering, Work Pack/SWU structure, validation, and closeout
   contracts.
2. Work Pack Readiness Audit owns frozen audit, semantic manifest, and a
   non-authoritative selected-unit receipt.
3. Task Session owns consumer entry, current mutation admission, one-SWU
   execution, critical validation, and an execution-terminal receipt.
4. Invoke Refresh owns closeout mutation; Continuation Router owns exact
   one-hop admission, dispatch, and join; Task Session derives synchronized
   completion only after that separate owner result passes or a validated
   no-op applies.
5. Lifecycle judgment belongs to Sigil Development or Spellcraft. Registry
   release is a separate axis whose exact owner was not bound by this research.

## Most important current findings

- Generated Work Pack Readiness Audit, Task Session, and Continuation Router
  provenance is known, but current generated bytes are stale or behaviorally
  unverified against canonical live sources.
- The tested plan-once positive fixture stops at mutation admission; it is not
  an end-to-end execution-and-closeout witness.
- Implementation Readiness and Task Session Until Blocker currently overlap on
  ordered until-real-blocker series reduction. The owner boundary must be
  decided; the research does not combine them or invent a third reducer.
- Distill `flag` still lacks a machine-bound assertion that every flagged gap
  is non-critical; that binding belongs in existing Plan/Work-Pack data.
- The exact runtime material producer and real producer-to-consumer receipt
  chain remain unbound.
- This dispatch reproduced two distinct canonical Orchestrate defects:
  receipt-directory overreach and cross-wave action-ID reuse. The action-only
  receipt directory and deterministic ID remap repaired only this run; neither
  is a canonical implementation repair.

## Capability closure and forgotten skills

The ordinary one-SWU core is Invoke, Implementation Layering, Distill, Work
Pack Readiness Audit, Context Builder, the applicable Decision Gate, Task
Session, Continuation Router, and Invoke Refresh. Conditional outer or
maintenance capabilities include Implementation Readiness, Task Session Until
Blocker, Goal, Dispatch Spec, Subagent Strategy, Orchestrate, Craft, Inventory,
Sigil Development, Spellcraft, Experiment Harness, Signal Observer, Workflow
Reflect, and Observability Setup. These capabilities have different owners and
evidence ceilings; they are not interchangeable stages of one readiness scalar.
