# Inventory Findings: Verification Weaver

## Candidate Finding

`verification-weaver` should be recorded as a candidate public Arcana
testing-specific router and parent receipt contract.

It should classify testing targets, select status-qualified owner lanes, join
native lane receipts into `VERIFICATION-WEAVE`, and preserve gaps, residue, and
candidate owner routes.

It is not a canonical tester and does not own derivation, UX validation,
experiment execution, architecture mapping, research evidence upgrade, task
execution, definition mutation, registry exposure, or promotion.

## Promotion Owner

Promotion owner: `sigil-development`, after local validation and
`experiment-harness` evidence exist.

## Excluded Private Evidence

Private evidence may remain in the internal `ops/` research package but is
excluded from public package fixtures, examples, and proof claims:

- private implementation paths;
- private fixtures and examples;
- private pass/fail result claims;
- generated runtime outputs;
- local observability logs.

## Residue

- Public package is not implemented yet.
- `ux-evidence-validator` remains seed/not promoted.
- Negative controls are specified here but become validation evidence only when
  implemented as runnable fixtures.
- Registry and generated runtime exposure remain blocked.
