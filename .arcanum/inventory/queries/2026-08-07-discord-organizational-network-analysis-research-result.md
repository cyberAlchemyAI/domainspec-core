# Discord API and Organizational Network Analysis Research Result

This is a candidate, non-authority Inventory read model of an audited research
result. It does not authorize Discord access, collection, relationship profiling,
employment use, implementation, privacy acceptance, organizational decisions,
publication, deployment, release, or production operation.

## Executive verdict

Current Discord documentation exposes fields that can be mechanically projected
into relation-shaped tables, but current Discord Developer Policy rule 16 prohibits
using API Data to profile users, identities, or relationships and prohibits
employment-eligibility use. The audited result therefore blocks live person-linked
Discord ONA. Consent, server-owner approval, pseudonymization, or metadata-only
collection does not cure that platform-policy gate.

Non-relational channel/time aggregates remain uncleared. Written Discord
clarification of the exact design is necessary but cannot independently pass data
quality, descriptive validity, privacy/ethics, or organizational-use gates.

## Six independent gates

The result keeps API observability, platform authorization, data quality,
analytical validity, privacy/ethics, and organizational decision authority
independent. Passing one never passes another.

The only admitted analytical artifact is a fully fictional, unexecuted paper
specification with exact normalized records, projection rules, expected arithmetic,
deletion and erasure mutants, a permission-gap mutant, suppression behavior, and
deterministic abstention codes. Manual review validates internal paper arithmetic
only; synthetic execution could never prove a real Discord or organizational study.

## Candidate alternatives

- Live person-linked Discord ONA: blocked.
- Employment use: prohibited.
- Non-relational aggregate dashboard: hold pending written Discord clarification
  and every other gate.
- Fully synthetic methods research: admitted for paper and later runtime testing of
  internal transformations only.
- Voluntary self-report ONA and participatory mapping: hold as independent,
  non-Discord candidates with protocols and accountable decisions unclosed.
