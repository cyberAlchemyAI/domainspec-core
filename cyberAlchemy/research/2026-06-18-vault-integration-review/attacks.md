## Governance Attack

Kahneman's core objection: CyberAlchemy can easily overfit from evocative
method labels into fake authority. The user-facing language is rich enough that
agents may treat review terms as schema terms, or treat a research finding as a
promoted vault node.

Surviving concerns:

- Method labels can bias agents into treating `define`, `research`, `design`,
  `plan`, `constitution`, `axiom`, `confidence`, `ergonomics`, and
  `governance` as stable vault categories before the schema accepts them.
- Review artifacts can create a false sense of completion when no linter,
  schema migration, or owner promotion has happened.
- Confidence terms are especially risky because the vault already has governed
  confidence semantics.

Verifier outcome: keep as MAJOR integration gates.

## Mechanics Attack

Turing's core objection: the executable system is narrower than the conceptual
model. A successful integration must pass through frontmatter literals,
edge-field definitions, migration scripts, and validation fixtures.

Surviving concerns:

- Current `NodeType`, `Status`, and edge-field literals do not admit
  CyberAlchemy values by default.
- The human edge catalog and executable edge fields diverge.
- The documented enforcement gap means prose rules can drift from machine
  behavior unless a validation path is added.
- Current-vs-proposed axes need an adapter contract instead of direct
  installation.

Attacker severity was critical for direct mutation. Verifier severity is MAJOR
because no canonical mutation happened in this run.

## Ownership Attack

Quine's core objection: several artifacts are tempting to cite as authority
while actually living at different authority levels.

Surviving concerns:

- The active vault subagent constitution and the repo-local draft replacement
  both exist; integration language must not blur which one is authoritative.
- PromotionRecord/B3/B4/OIL records may be useful evidence shapes, but they are
  not DomainSpec vault frontmatter values.
- CyberAlchemy research findings are not automatically vault amendments.

Attacker severity was critical for authority substitution. Verifier severity is
MAJOR because the current deliverable is a review packet.

## Operability Attack

Alexander's core objection: the ontology can become unusable if it asks agents
to reason across too many untyped layers.

Surviving concerns:

- Cross-system witnesses need explicit `authority_scope` and non-authority
  notices.
- Method ontology records need selectors, owner routes, contradiction handling,
  and maintenance expectations.
- Templates should separate review output, promotion packet, retrieval packet,
  and maintenance/reflection packet.

Verifier outcome: keep as MAJOR/MINOR implementation readiness work.

## Verifier Outcomes

canonical vault schema. The concerns are still valid as integration gates, but
they are not evidence of a broken canonical vault.
