# Source Digest: CyberAlchemy Method

Source: [CYBERALCHEMY-METHOD.md](../../../arcanum/framework/CYBERALCHEMY-METHOD.md)
Ledger: [../source-ledger.md](../source-ledger.md)

## Why This Source Matters

The CyberAlchemy Method defines the working discipline behind Arcanum: governed synthesis through artifacts, research, tension, trace, routing, and reflection.

It explains how vague intent becomes a reusable, inspectable, improvable artifact.

## Compiled Concepts

### Five Anchors

The method keeps five anchors visible:

| Anchor          | Question                                                                |
| --------------- | ----------------------------------------------------------------------- |
| Objective       | What are we trying to solve?                                            |
| Output artifact | What should exist when work is done?                                    |
| Discovery       | What must be learned before closure?                                    |
| Tension         | What could make the artifact brittle, unsafe, oversized, or misleading? |
| Route           | Who or what owns the next lifecycle step?                               |

### Method Loop

The method loop:

```text
orient
  -> discover
  -> shape
  -> stabilize
  -> evolve
```

It is recursive. Discovery, tension, or validation may send the work back to an earlier step.

### Synthesis Pattern

CyberAlchemy synthesis is not summarization.

It moves:

```text
seed intent
  -> bounded context
  -> objective and output artifact
  -> discovery
  -> local vocabulary
  -> candidate structure
  -> tension
  -> revised artifact
  -> validation evidence
  -> lifecycle route
```

### Method Primitives

Important primitives for the agentic system:

| Primitive                 | Rule                                                                                            |
| ------------------------- | ----------------------------------------------------------------------------------------------- |
| Route Before Work         | Choose the smallest responsible lifecycle authority before producing output.                    |
| Gate Before Mutation      | Consequential changes stop until blockers are resolved or explicitly overridden.                |
| Obligation-Linked Context | Include evidence because it closes a named obligation.                                          |
| Trace Before Promotion    | Terms, claims, conventions, and confidence states promote only through evidence and governance. |
| Artifact As State         | A run should leave a durable artifact, not only conversation.                                   |
| Navigable Work Surface    | Artifacts should expose start points, status, gaps, links, and next actions.                    |
| Reflection Outer Loop     | Usage signals and output drift should produce improvement proposals.                            |

## CyberAlchemy Adaptation

The agentic system should treat method primitives as candidate ontology entries.

They are not just writing advice. They define how agents should work:

- route before work affects execution;
- trace before promotion affects ontology;
- obligation-linked context affects Context Builder;
- reflection outer loop affects Operational Ontology.

## Candidate Ontology Claims

| Claim                                        | Branch               | Candidate Entry                              |
| -------------------------------------------- | -------------------- | -------------------------------------------- |
| A run should leave a reviewable artifact.    | operational          | `method-primitive-artifact-as-state`         |
| Route should be selected before work begins. | operational          | `method-primitive-route-before-work`         |
| Context should be obligation-linked.         | memory               | `method-primitive-obligation-linked-context` |
| Promotion requires trace.                    | knowledge-governance | `method-primitive-trace-before-promotion`    |
| Repeated use should improve the method.      | feedback             | `method-primitive-reflection-outer-loop`     |

## Tensions And Promotion Gaps

- Some method primitives may become constitutions later, but most should start as candidate operational rules.
- The method is broad; ontology entries should avoid turning every sentence into a rule.
- The first working loop should prove which primitives need operational enforcement.

## Agent Payload

When creating or revising any agentic artifact:

```text
name objective
name output artifact
discover before closure
test with tension
record trace
route next owner
reflect after use
```
