# Glossary And Ontology: CyberAlchemy Agentic System

This glossary is the terminology authority for the current define baseline. Terms are candidate-scoped unless linked to an already-authoritative repository source.

## Plain Language Terms

| Term             | Meaning In This Module                                                                                                   | Related Concepts                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| Chasing symmetry | Keeping what the system says should happen and what actually happens close enough that drift is visible and correctable. | Schema Layer, Evidence Layer, Translation Residue        |
| Residue          | What remains unresolved, ambiguous, contradictory, or costly after translating between intent and observed operation.    | Translation Residue, Residuality Finding                 |
| Memory           | The working continuity layer that helps agents resume, route, and avoid repeated friction.                               | Execution Context Memory, Memory Observation             |
| Ontology         | Governed knowledge with roles, edges, confidence, and promotion rules.                                                   | Business Ontology, System Ontology, Operational Ontology |
| Context solution | A reusable shortcut that says what context and route usually works for a recognized execution situation.                 | Context Solution, Execution Context                      |
| Promotion        | The process that moves a repeated observation into reviewed knowledge or capability change.                              | Promotion Gate, Operational Lesson                       |
| Meta-model       | A reusable model about models, such as a layer, taxonomy, or pattern that applies across domains.                        | Meta-Model Candidate                                     |

## Deterministic Linking Order

1. Match existing authorized repository terms first.
2. If an existing term covers the meaning, reuse it and mark `linked`.
3. If existing terms cover only part of the meaning, mark `partial` and explain the missing authority.
4. If no existing concept exists, mark `no-match` and keep the term candidate-only.
5. Do not promote candidate terms into ontology authority without ontology-harness or decision-gate review.
