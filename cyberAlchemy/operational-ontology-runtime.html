What The Ontology Is

In this system, ontology is not a vocabulary list. It is the governed meaning layer that says what a concept means, where it applies, where it does not apply, what evidence supports it, how confident the system is, and how an agent should use it during execution.

Thin Ontology

Names a concept and points elsewhere. Useful for navigation, weak for execution, and risky when agents infer rules from labels.

Thick Ontology

Carries definition, scope, exclusions, examples, evidence, confidence, edges, maintenance triggers, and an agent payload.

Agent Payload

The compact execution part: when to use the entry, what to load, which route to choose, what failure to avoid, and when to stop. 

raw source
  -> inventory source summary
  -> typed inventory entry
  -> thick ontology candidate
  -> premise or confidence review
  -> promoted ontology entry
  -> route, capability, specification, or context update

The Practical Rule

Inventory answers "what did the evidence say?" Ontology answers "what does it mean, where can it guide execution, and what can invalidate it?"

Differences Between Ontologies

Different ontology branches carry different kinds of authority. This keeps agents from mixing intent, implementation, alignment, and execution lessons into one ambiguous pile.

Ontology Branch Authority Typical Questions Common Failure If Mixed Up
Business Ontology Intent, policy, value, domain language, expected outcomes. What should the system mean? Who does it serve? What counts as success? Implementation details masquerade as product truth.
System Ontology Implementation reality: code, runtime, tests, APIs, infrastructure. What exists? How does it behave? How is it measured? Aspirations are treated as shipped behavior.
Bridge Ontology Traceability between intent and realization. Which implementation realizes which intent? What proves alignment? Business claims and system artifacts drift apart invisibly.
Operational Ontology Reusable knowledge about routes, agents, prompts, sigils, workflow execution, failures, and maintenance. How should agents choose context, routes, gates, and recovery paths? Every run rediscovers the same workflow lessons.
Memory Patterns Continuity and ergonomics inside privacy and scope boundaries. What happened before? What preference or blocker matters now? Session observations become hidden law.

Promotion System

Non-Promotion Rule

Raw memory, unreviewed telemetry, pointer-only entries, and local tricks do not become global rules. They must pass through evidence, scope, owner, confidence, and maintenance gates.

Axioms, Constitutions, Premises

These roles prevent the system from treating every good idea as a law. They encode different strengths of commitment.

Axiom A rare load-bearing truth or epistemic foundation. It justifies downstream governance and should survive contradiction review before agents use it as a reason for other rules.
Constitution A codified operating rule, process convention, or safety boundary. It tells humans and agents how to act in a defined scope.
Premise A working bet. It may guide exploration, but it keeps its uncertainty visible and includes falsification criteria.
Confidence Decision A review that separates "the evidence supports this" from "we are willing to rely on this now."
Evidence Commitment Meaning Action
Low Low Exploratory idea. Keep as candidate or research seed.
High Low Well-supported but not load-bearing. Keep as reference or scoped entry.
Low High Risky bet. Require explicit decision gate and rollback path.
High High Strong promotion candidate. Promote within scope and add maintenance trigger.

How Operational Ontology Helps Agent Execution

Operational ontology is the branch that lets the system learn how its own agents, routes, prompts, sigils, workflows, and execution patterns actually work. It is the system governing the governor.

Route Patterns

"Use ontology review before invoke when the task changes governed knowledge." The route choice becomes explicit instead of remembered by the human operator.

Context Solutions

"For define to design, load definition, glossary, architecture, gaps, and source map." The context bundle is reusable.

Failure Modes

"Memory treated as authority creates accidental canon." Agents get the warning where the mistake would happen.

Capability Patterns

Skills carry input contracts, output shapes, telemetry expectations, validation gates, and composition rules.

Maintenance Triggers

Repeated output drift, recurring route misses, or validation gaps create review pressure instead of disappearing after the run.

Workflow Optimizations

Proven shortcuts can be compiled into workflow definitions with scope, expiry, pitfalls, and evidence selectors.

Why This Means Less Consulting

The agent no longer has to consult the whole corpus to remember how to operate. The ontology review happens upstream; the result is a compact payload embedded into the skill or workflow definition. The theory becomes a small executable checklist at the point of work.

Memory As Execution Context

Memory gives continuity. It helps the system resume a task, recognize a pending response, preserve side notes, recall route history, and avoid forcing every run to rediscover the same local facts. But memory is not authority.

Hot Active task state, pending prompt, current route, blockers.
Warm Recent validated decisions, route history, useful side notes.
Cold Archived historical memory, old traces, retired context.
Memory Pattern Execution Use Promotion Boundary
One task decision Resume the current work correctly. Stays session evidence unless it has durable value.
Repeated route miss Warn the agent and adjust route selection for similar tasks. Inventory entry, then operational ontology candidate.
User workflow preference Improve ergonomics inside the active privacy scope. Decision gate required before broader ontology use.
Side note contradiction Preserve tension without derailing the current flow. Inventory contradiction, then ontology review if consequential.
Repeated context bundle Load the right evidence faster next time. Context solution candidate with expiry and selectors.

Why Memory Needs Boundaries

Memory is optimized for continuity, not truth. If memory silently becomes law, the system creates hidden rules from accidental circumstances. Promotion governance keeps that from happening.
