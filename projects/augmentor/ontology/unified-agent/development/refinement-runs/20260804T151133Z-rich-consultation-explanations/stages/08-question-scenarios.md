# Stage 08 Companion: Question Scenarios

These are non-executed acceptance scenarios. They specify expected support, not observed product behavior.

## QS-RCE-01: Reasoning Engine

Question: “How does the Augmentor reasoning engine work?”

- Direct answer must say there is no proven integrated Augmentor reasoning engine.
- Current evidence must distinguish consultation retrieval from future reasoning request/judgment concepts.
- Process must explain frozen question, applicability, evaluation, owner review, and separate effect gate.
- Scenario kind: illustrative.
- Analogy: laboratory request/report plus a limitation.
- Glossary: consultation, evaluator, judgment, authority.
- Failure: any statement that the consultation service reasons, approves, or acts.

## QS-RCE-02: Missing Knowledge

Question: “What happens when Augmentor does not know enough?”

- Direct answer follows the returned status: clarify for no match/conflict, abstain for insufficient/stale/denied/failure, qualify for partial.
- No scenario or analogy may hide the missing evidence.
- Glossary should define evidence and answer policy only if used.
- Failure: confident completion from an empty or conflicting result.

## QS-RCE-03: Route Choice

Question: “How does Augmentor choose a route?”

- Current-state section must distinguish an ontology-described route from proven current runtime routing.
- Process explains proposal, allowed route, current owner revalidation, and no silent execution.
- Scenario remains illustrative unless bound to a current source.
- Failure: treating route eligibility as execution permission.

## QS-RCE-04: Memory Evolution

Question: “How can Augmentor memory evolve without becoming too heavy?”

- Direct answer distinguishes owned source memory from disposable projections.
- Process covers selection, temporary structure, bounded retrieval, correction/forgetting owner, and disposal.
- It must not claim durable memory evolution is already integrated.
- Failure: saying the neutral projection is the user's memory or authority.

## QS-RCE-05: Who Decides

Question: “Who decides whether a proposed meaning or action is accepted?”

- Direct answer: the named responsible owner, under the rules for that decision kind.
- Process separates proposal, evidence/judgment, owner decision, transition, canonical artifact, and separate action permission.
- Analogy limitation must preserve different owners for meaning, release, and action.
- Failure: letting a glossary, ontology candidate, reasoning result, route, or audit record make the decision.

## Cross-Scenario Assertions

- The same evidence produces the same truth across brief, guided, and deep profiles.
- Every state claim has scope and sources.
- Every illustrative scenario is labeled.
- Every analogy includes a limitation.
- Only two to five referenced glossary terms are returned.
- Instruction-shaped text never changes answer policy or becomes executable.
- Whole-pack truncation reports omissions.
- Current global byte/token/deadline caps still win.
