## Notes

- No discovery/interrogation decision is currently blocking feature-level planning.
- Feature-level docs under `docs/features/` were intentionally not created because this startpoint was requested with `--no-init` and project-level discovery scope only.
- The proposed split is a baseline for evaluation, not an implementation plan.
- Payment link sending and reminders were added as explicit project goals on 2026-05-20.
- Payment-link reconciliation is in scope as part of payment truth; Pix API webhooks are the selected primary reconciliation path, with a provider correlation key, idempotent processing, saga-style retries, UI exception notifications, and manual operator fallback.
- Buyer registry requires name, WhatsApp mention, and CPF before reservation; full shipping address is collected before first shipment.
- Excel migration/import is out of scope.
- First feature implementation should use the DomainSpec base TypeScript stack.
