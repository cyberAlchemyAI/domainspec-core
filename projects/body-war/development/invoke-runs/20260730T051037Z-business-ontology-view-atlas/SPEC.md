# DomainSpec: Body War Business Ontology View Atlas

## Intent

Generate a deterministic, user-friendly local HTML atlas that lets a reader
move from the whole Body War business ontology into one of six editorial
lenses, inspect each literal `business_kind` subgroup assigned to that lens,
follow exact admitted relations across lenses, and see zero-degree nodes
without inventing missing meaning.

The atlas changes presentation only. It does not mutate ontology nodes,
relations, lifecycle policies, branch declarations, owner routes, promotion
state, or runtime application behavior.

## Actors

| ID | Actor | Goal | Constraint |
| --- | --- | --- | --- |
| `ACT-BWVA-READER` | Ontology reader, including keyboard and assistive-technology users | Understand the size and contents of each editorial lens and kind subgroup, then follow exact relations between lenses | Must not need pointer input, color, graph-layout interpretation, or inferred ontology meaning |
| `ACT-BWVA-OWNER` | Body War product ontology owner | Audit complete node and relation coverage and identify zero-degree nodes | Atlas cannot decide new predicates, directions, lifecycle membership, or promotion |
| `ACT-BWVA-VALIDATOR` | Development validator | Reproduce projection and browser structure from current source bytes | Structural success cannot claim comprehension, release, or production readiness |

## Operations

### `OP-BWVA-01 deriveAtlas`

Input: sorted current node documents, admitted relation set, package profile,
business branch declaration, and source digests.

Rules:

1. Reject duplicate node IDs, unknown relation endpoints, unsupported missing
   literals, or a relation-count declaration mismatch.
2. Validate that every observed literal `business_kind` occurs in exactly one
   of six cataloged editorial lenses and that the catalog has no absent kind.
3. Assign every node to exactly one core lens through that closed kind mapping.
4. Sort lenses by catalog order, kind groups by catalog order, and core nodes
   by label then concept ID.
5. If both endpoint kinds map to the same lens, add the relation once to that
   lens's internal relation index.
6. If the endpoint kinds map to different lenses, add one canonical portal
   record containing the exact source lens and target lens.
7. Add the portal relation ID to the source lens's outbound index and target
   lens's inbound index. These are references to one rendered relation, not
   copied or reversed relation rows.
8. Mark a node zero-degree only when its ID occurs in no admitted relation
   endpoint.
9. Do not derive or display a fabricated predicate, reverse edge, semantic
   branch, lifecycle membership, or authority value.

Output: canonical `ViewAtlas` data and HTML with `authority_effect:none`.

### `OP-BWVA-02 activateLocation`

Input: stable lens/node/relation fragment.

Validate all referenced IDs, reveal the requested lens, select and focus the
exact target, update history, and announce the resulting lens and node. An
invalid fragment falls back to the overview and exposes a bounded error.

### `OP-BWVA-03 activatePortal`

Persist the exact relation tuple, open the other endpoint's core lens, focus
that endpoint, and retain the admitted direction. Activation from the target
lens must not reverse the relation.

### `OP-BWVA-04 filterAtlas`

Match normalized query text against exact labels, concept IDs, kinds,
predicates, and relation descriptions. Results link to canonical atlas
locations. Empty input restores the unfiltered overview.

### `OP-BWVA-05 selectNode`

Reveal node source literals, incident internal and portal occurrences, and the
zero-degree cue when applicable. No other form of relatedness is inferred.

### `OP-BWVA-06 emitCoverageReceipt`

Bind source and output digests, exact node/kind/relation cardinalities,
partition proof, endpoint proof, occurrence proof, zero-degree proof, and the
claim ceiling.

## State Model

| State | Meaning | Allowed transitions |
| --- | --- | --- |
| `overview` | lens summaries and search entry | `open-lens`, `search-result` |
| `lens` | one editorial lens owns the main detail surface | `select-node`, `select-relation`, `activate-portal`, `overview`, `search-result` |
| `node` | one core node is selected inside its lens | `select-relation`, `activate-portal`, `lens`, `overview`, `search-result` |
| `relation` | one exact relation tuple is selected | `activate-portal`, `node`, `lens`, `overview`, `search-result` |
| `degraded` | fragment or source integrity failure prevents exact selection | `overview`, `retry-current-source` |

Every state remains an HTML projection. No state transition changes ontology
or release posture.

## Interface Contracts

### Projection core

```text
deriveAtlas(sourcePackage) -> AtlasProjection | AtlasError
```

The core is deterministic and independent of DOM, layout, browser history, and
generated output files.

### Static HTML

Every lens, core node, relation sentence, portal endpoint, zero-degree cue,
source path, and claim ceiling is present in the generated HTML before
JavaScript executes. Ordinary fragment anchors provide the no-JavaScript path.

### Progressive controller

A dependency-free inline controller enhances search, lens disclosure,
selection, focus transfer, announcements, and history. It does not own or
rewrite semantic data.

### Source boundary

Node JSON, relation JSON, profile, residue, lifecycle policies, and
`views/business.json` remain read-only inputs. The generated atlas is never
read back as ontology authority.

## Error Contract

| Code | Trigger | User-visible behavior | Evidence behavior |
| --- | --- | --- | --- |
| `ATLAS_DUPLICATE_NODE` | duplicate concept ID | generation fails | negative source fixture |
| `ATLAS_UNKNOWN_ENDPOINT` | relation endpoint absent | generation fails | negative source fixture |
| `ATLAS_PARTITION_MISMATCH` | node is missing or has multiple core memberships | generation fails | exact-set comparison |
| `ATLAS_OCCURRENCE_MISMATCH` | internal/cross relation occurrence count differs | generation fails | unique-ID and occurrence proof |
| `ATLAS_DIRECTION_DRIFT` | an occurrence reverses source and target | generation fails | tuple equality proof |
| `ATLAS_STALE_OUTPUT` | generated bytes differ from current rendering | `--check` fails | generated-byte comparison |
| `ATLAS_UNKNOWN_LOCATION` | fragment references an unknown ID | overview plus bounded error | browser negative assertion |

## Non-Goals

- Creating an actors-only ontology or splitting canonical ontology packages by
  `business_kind`.
- Adding, removing, reversing, repairing, or promoting ontology relations.
- Repairing the ten premise source-definition mismatches found by accepted
  research.
- Treating editorial lenses, URL fragments, layout, colors, or counts as semantic
  ontology branches.
- Replacing the existing curated business views or journey experiment.
- Claiming that all nodes should have an explicit edge.
- Claiming human comprehension, accessibility conformance, release,
  deployment, application integration, or production readiness.
