# Invoke Refresh Dispatch Technique Trace

No full dispatch is required: this is one local, deterministic, exact-scope
Refresh apply owned by the parent chat.

| Technique | Activation | Effect |
| --- | --- | --- |
| `sequence` | staged apply has ordered gates | capture -> propose -> materialize -> validate -> handoff -> apply -> audit |
| `artifact_contract_bridge` | audit findings must become typed deltas | every target change maps to the readiness report and signal pack |
| `concrete_path_evidence` | apply scope must be exact | ten normalized target paths equal approval, changes, and inventory |
| `owner_boundary_check` | Spellcraft cannot impersonate Invoke | Spellcraft owns the public audit; Invoke owns these private plan deltas |
| `validation_loop` | repair quality is not assumed | staged tests, material receipt, handoff receipt, post-apply audit |
| `residue_ledger` | runtime gaps remain after plan repair | output/audit admission and per-SWU material packages stay open |
| `authority_split_gate` | plan pass differs from execution readiness | selected unit remains none and mutation readiness remains false |

Skipped: multi-agent dispatch and handle handoff; no parallel or external owner
is needed for this bounded refresh.
