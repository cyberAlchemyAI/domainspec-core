# Body War Atlas Into OEW — Timing Decision

## Decision

**Split now and later.**

Select the OEW-native focus-scene design now, because it is the smallest
evidence-backed addition that repairs the observed OEW navigation failure.
Defer code incorporation until one bounded Work Pack explicitly owns the
overlapping source changes and orders them against `SWU-OEW-007T`.

In plain language: preserve the idea and exact test now; do not modify OEW yet.

This is not a recommendation to embed the Body War HTML or copy its editorial
projection into OEW. It also does not recommend building a launcher merely to
claim integration. A launcher has weaker product value, still requires owned
gateway/build/browser work, and does not fix the native focus failure.

## What To Incorporate

The selected target is:

1. one frozen four-node OEW focus scene derived from the existing Body War
   adapter graph and sidecar;
2. the literal directed portal
   `Identity and Consent —related to→ Authentication and Consent`;
3. source-derived internal-edge and boundary-portal tuples;
4. persistent relation, provenance, candidate, and `authority:none` state;
5. pointer, Enter, Space, breadcrumb/Back, forced-colors-safe focus, and
   reduced-motion semantic parity.

This target comes from the accepted black-box review, which found that tour
step 1 and non-tour Focus both retained all 237 nodes and 231 edges and named
the exact smallest implementation and test boundary
([black-box findings](../20260730-ontology-ui-black-box/findings.md#smallest-coherent-implementation-slice)).

## What Not To Incorporate

- **No static atlas embedding.** It would duplicate the generated presentation,
  renderer, navigation, source binding, and staleness lifecycle.
- **No second shared projection dataset.** The existing adapter already emits
  the deterministic OEW nodes, directed relations, tours, provenance, candidate
  posture, and `authority:none`.
- **No six-lens-to-layer semantic merge.** The atlas's six editorial lenses,
  OEW's 17 layers, and its five tours are different presentation systems.
- **No launcher as the default next slice.** An authenticated hash-bound
  launcher remains possible as a separately owned discovery feature, but it
  does not repair the 237/231 focus defect and is not currently authorized.

## Why Code Waits

The legacy Work Pack names `SWU-OEW-007T` as the only selected unit. It owns
strict-type repairs in the same `types.ts` and `store.ts` surface needed by a
native focus scene, while `013B`, `014`, and `014V` retain build, browser, and
independent-acceptance ownership
([legacy Work Pack](../../../../../cyberAlchemy-v2/development/ontology-evidence-workbench/planning/WORK-PACK.md#next-route)).

The completed thin prototype proves that a typed build, authenticated gateway,
and browser journey can work, but it intentionally leaves the legacy package
unchanged and does not own atlas-to-OEW recomposition
([thin Work Pack](../../../../../cyberAlchemy-v2/development/ontology-evidence-workbench-thin-prototype/planning/WORK-PACK.md#objective-and-success)).

Therefore, technical compatibility is plausible and bounded; mutation
authority and ordering are not yet closed.

## Exact Condition To Start Implementation

Start code incorporation only after one bounded Work Pack:

1. names the focus scene as its sole primary behavior;
2. owns the required `types.ts`, `store.ts`, and `OewApp.tsx` changes;
3. explicitly incorporates into, orders after, or refreshes the bindings of
   `SWU-OEW-007T`;
4. keeps the adapter graph/sidecar schema, ontology source, package root, and
   gateway contract unchanged unless a separately approved decision says
   otherwise;
5. owns fresh immutable build, authenticated gateway, browser, and closeout
   receipts.

If those ownership and ordering conditions cannot be satisfied without
invalidating the active `007T` frontier, implementation remains deferred.

## Exact Next Acceptance Boundary

The implementation must:

1. reproduce the failing baseline: tour step 1 and Focus render 237 nodes and
   231 edges;
2. render the test-owned four-node IDs, internal directed tuples, and crossing
   portal tuples;
3. reject one fixed unrelated node;
4. activate the literal `Identity and Consent —related to→ Authentication and
   Consent` portal;
5. prove byte-equivalent pointer, Enter, Space, breadcrumb/Back, persistent
   relation/provenance/authority, and reduced-motion semantic state;
6. retain gateway token/path negatives, zero outbound requests/errors, and
   complete teardown through a fresh immutable build.

## Claim Ceiling

release, deployment, or production state. The current evidence does not
establish human comprehension, accessibility conformance, or semantic
correctness.
