**Primary-source reach:** the local `web_fetch` MCP refused all direct page renders (URL provenance restriction). All claims trace to WebSearch summaries of the URLs above; rendered pages were not retrieved in-session. A future session with broader fetch provenance should retrieve the rendered pages directly and verify each claim against source.

**v0.13.0 "Tenacity Release" (tagged v2026.5.7, shipped 2026-05-07):** 864 commits, 588 merged PRs, 282 issues closed, 295 contributors. Adds persistent `/goal` (Ralph loop), durable multi-agent Kanban with heartbeat / reclaim / zombie detection, per-task retry budgets, auto-block on incomplete exit, post-write delta lint on `write_file`+`patch` for Python/JSON/YAML/TOML, an 8-P0 security wave (redaction default-on, Discord role-allowlists guild-scoped, WhatsApp stranger-rejection, TOCTOU closure across `auth.json` and MCP OAuth), Checkpoints v2 (real pruning, disk guardrails, no orphan shadow repos), session auto-resume mid-task, hallucination recovery on tool failure. Six new optional skills shipped.

**Reflective-phase trigger cadence (two trigger paths):**
1. **Periodic retrospective every ~5 tool calls or task-complete** — four questions: did that work; what took too long; what did the user reject; is there a reusable pattern here.
2. **On user correction** — agent can propose a new SKILL.md capturing the correction.

Skills do NOT auto-generate on every task. The system only writes a skill when it detects **repetition** (typically ≥5 tool calls on a pattern) or after a user correction teaching something general.

**Extracted-pattern shape — SKILL.md:** YAML frontmatter (required: `name`, `description`; optional: `version`, `author`, `license`, platform support, env vars, `skills.config` namespace) + Markdown body. Pending frontmatter feature request (#3879) proposes `keywords` and `when_to_use` for auto-discovery (not in v0.13.0). Recommended body sections that "survive partial loads": **When to use, Quick reference, Procedure, Pitfalls, Verification.**

**Skill folder layout:** `~/.hermes/skills/<category>/<skill-name>/SKILL.md` + optional `references/`, `templates/`, `scripts/`, `assets/`. Compatible with `agentskills.io` standard.

**Retrieval at next-use — three progressive loading levels:**
- **Level 0** — only `name` + `description` loaded (~3K tokens for 40+ skills); always-on routing layer.
- **Level 1** — full `SKILL.md` loaded on demand when description matches request.
- **Level 2** — specific reference files loaded only when the skill invokes them.

Selection is the model's own judgment over the `description` field — **no embedding retrieval surfaced in docs**. Selection quality is bound to description quality; multiple trigger phrasings increase match reliability. No automatic eviction surfaced; skills are user-pruned. Skill conflicts left to agent judgment.

**Where the safety gate sits:** Hermes implements human approval for the reflection-to-skill loop. The agent **proposes** a new SKILL.md; the user **approves, edits, or rejects** before it lands canonically. No automatic write to `~/.hermes/skills/`. Agent edits to existing skills are "treated like code: review diffs, export snapshots, reset bundled skills deliberately when upgrades drift."

**Unresolved production concerns (public commentary):** no signed provenance, no role-based approval, no organization-level governance, no audit trail of which session proposed which skill, **skill-poisoning attack surface remains open** (an attacker who lands a malicious SKILL.md via any side channel — Git, package install, MCP supply chain — gains a persistent influence channel). "An enterprise fork is almost inevitable" with signed skills + audit logs + RBAC.

**The three memory layers:**
1. **Layer 1 — Prompt Memory** (always-loaded): `MEMORY.md` (agent observations) + `USER.md` (user-specific knowledge). Captured once at session start to preserve LLM prefix cache.
2. **Layer 2 — Episodic Memory**: all conversations in `~/.hermes/state.db` (SQLite FTS5 full-text index). Past context is **searched, not loaded wholesale**; retrieved results pass through LLM summarization before injection.
3. **Layer 3 — Procedural Memory (Skills)**: SKILL.md files; three-level loading as above.

Architecture explicitly separates episodic ("what happened, when") from procedural ("how to do things"). Layer 2 holds the trace; Layer 3 holds the named-and-described capability.

**Primary-source reach:** official Anthropic docs URL not directly fetched (provenance restriction); details below are from search-result summaries across the multiple independent secondary sources above, which cross-check.

**Announcement:** 2026-05-06 at Code with Claude (San Francisco).

**Trigger model — two paths:**
1. **Manual / on-demand**: `/dream` command or direct Dreams API call.
2. **Auto Dream**: scheduled background process firing only when **both** conditions hold: (a) sufficient elapsed time since last dream, AND (b) sufficient session activity since last dream. Dual-gate prevents consolidation on lightly-used projects; active projects get regular cleanup.

API accepts up to 100 prior sessions per invocation; a dream can take several minutes.

**Write format:** dream produces a **new output memory store** — separate from input. Input store is **never modified**; operator reviews output and may discard. Output reorganizes memories, merges duplicates, replaces stale entries, surfaces patterns. Writes are "plain-text notes and structured 'playbooks' that future sessions can reference, making the entire process observable and auditable by humans." **Model weights are not modified** — consolidation is durable state in the memory layer.

**Read-back path:** output store is "an ordinary memory store in your workspace." Inspectable via Memory Stores API or Console. **Operator attaches it to future sessions explicitly — no automatic adoption.** `session_id` on the dream invocation points at the underlying session executing the pipeline; streamable events show what the dream reads/writes in real time. Session is archived (not deleted) on terminal state.

**Scope and consent:** single-agent / single-workspace per invocation. Operator opt-in (developer access). Up to 100 sessions per dream. Operator decides attachment. No cross-workspace dreaming.

**API beta headers required:** `managed-agents-2026-04-01` + `dreaming-2026-04-21`. Supported only on Claude Opus 4.7 and Sonnet 4.6. Currently Research Preview.

**Early adoption:** Harvey (legal AI) reported ~6x task-completion rate increase per VentureBeat coverage (single-vendor anecdote, pre-broad-rollout).

**Documented failure modes / guardrails:**
- **Memory store as long-lived influence channel** — poisoned info in memory is treated as trusted context by future sessions. **Dreaming can consolidate poisoned lessons** if input sessions are compromised.
- **Provenance preservation** — aggressive merging risks losing line back to source session.
- **Over-pruning** — edge-case notes pruned as "stale" may be rare-but-important.
- **Net-new attack surface** (Huang) — the dream pipeline itself is a target; manipulate enough sessions, and the dream output incorporates the manipulation as a "pattern."

Structural guardrails Anthropic shipped: input-immutable, manual-attach output. Operator review is the load-bearing safety boundary.

## Lane 3 — Academic baseline

**Reflexion (Shinn et al. 2023; arXiv 2303.11366; NeurIPS 2023):** https://arxiv.org/abs/2303.11366 · https://github.com/noahshinn/reflexion. Reinforces LLM agents through **verbal feedback** — not weight updates. Agent verbally reflects on task feedback, maintains reflective text in **episodic memory buffer** to improve subsequent trials. Three roles: Actor / Evaluator / Self-Reflection. Reflection acts as "semantic gradient signal." Reflection text is **bounded** (sliding window of recent reflections). **Relevant insight:** per-trial, bounded, consumed by next trial of same task — closer to "lessons applied next cycle" than to ever-growing skill library.

**Self-Refine (Madaan et al. 2023; arXiv 2303.17651):** https://arxiv.org/abs/2303.17651. Single-LLM FEEDBACK → REFINE → FEEDBACK loop. Same model is generator, feedback provider, refiner. No training data, no fine-tuning, no separate critic. Evaluated across 7 tasks on GPT-3.5/ChatGPT/GPT-4; ~20% improvement over single-shot. **Relevant insight:** Self-Refine is **within-cycle** refinement; Reflection Packet is **between-cycle**. The Tilth council's Scribe→Editor→Judge→Red Team loop already covers within-cycle.

**Voyager (Wang et al. 2023; arXiv 2305.16291):** https://arxiv.org/abs/2305.16291 · https://voyager.minedojo.org/ · https://github.com/minedojo/voyager. Canonical skill-library reference. Three components: automatic curriculum + ever-growing skill library of executable code + iterative prompting with environment feedback and self-verification. Skills are executable JavaScript, temporally extended, interpretable, compositional. Library stores `(name, description, code)` tuples indexed by description embedding. **Self-documented failure modes:** curriculum-level hallucinations (proposes invalid tasks — "craft a copper sword" when copper swords don't exist); code-generation hallucinations (invalid fuel sources, nonexistent API calls, semantically-wrong primitives). Mitigation: GPT-4 acts as critic on current state + task. **Canonical insight:** skill library MUST be coupled to executable test; without one, library accumulates plausible-but-wrong skills.

**ExpeL (Zhao et al. 2023; arXiv 2308.10144; AAAI-24):** https://arxiv.org/abs/2308.10144. Autonomous experience-gathering across training tasks; extracts natural-language **insights** by comparing failures to successes. At test time, recalls most-similar past successful trajectory + applies insights. No parameter updates. **Relevant insight:** failure-vs-success comparison maps to Reflection Packet "what worked / what didn't"; pattern-vs-instance separation maps directly to existing §15.9.2 F-ARCHIVIST-LESSON-INSTANCE-LEAK.

**Generative Agents (Park et al. 2023; arXiv 2304.03442; UIST 2023):** https://arxiv.org/abs/2304.03442 · https://github.com/joonspk-research/generative_agents. Memory stream (complete record in natural language) → periodic synthesis into higher-level **reflections** → dynamic retrieval. Three components: observation, planning, reflection. **Reflection cycle is importance-triggered** (fires when accumulated importance scores cross a threshold) and produces abstract second-order observations. Recursive — reflections become first-class memories. Retrieval scores on **recency** (exponential decay) × **importance** (LLM-assigned) × **relevance** (embedding). **Relevant insight:** importance-triggered cadence is cleaner than "every N tool calls"; for grant cycles, the salience threshold is naturally cycle-close (grant submission = highest-importance event).

**Surveys (2024-2026):**
- Lifelong Learning of LLM-Based Agents: A Roadmap (arXiv 2501.07278, 2025) — first systematic catalog; perception/memory/action module taxonomy.
- A Survey on the Memory Mechanism of LLM-Based Agents (Liu et al., ACM TOIS 2025): https://dl.acm.org/doi/10.1145/3748302 · companion paper list: https://github.com/Shichun-Liu/Agent-Memory-Paper-List
- From Storage to Experience (Preprints.org 202601.0618) — three-stage taxonomy: **Storage → Reflection → Experience**. Cleanest framing for where a Reflection Packet sits: Storage is raw audit trail; Reflection is per-cycle packet; Experience is the abstracted lesson Archivist proposes.
- Memory for Autonomous LLM Agents (arXiv 2603.07670, 2026) — frontier review.
- Awesome-Lifelong-Learning-Methods-for-LLM (ACM Computing Surveys 2025): https://github.com/zzz47zzz/awesome-lifelong-learning-methods-for-llm

**Established failure modes converged across the literature:**
1. **Drift** — system prompt loses binding after ~30 turns; reflection text substitutes for it and pulls behavior off-baseline.
2. **Hallucinated reusable patterns** — Voyager curriculum + code; self-verification helps but doesn't close gap.
3. **Eval gaming** — Reflexion can optimize for evaluator heuristics rather than ground truth.
4. **Catastrophic forgetting** — continual fine-tuning degrades prior capability; bounded for Tilth (no production fine-tuning).
5. **Retrieval mismatch** — embeddings great at "looks like," terrible at "is cause of"; semantically similar but functionally distinct skills get confused.
6. **Prompt injection via memory** — see Lane 5.
7. **Sycophantic self-validation** — same model judging its own work inherits RLHF agreement bias.
8. **Premature generalization** — N=1 lesson encoded as general rule; Hermes "5-tool-call repetition" trigger is field's best heuristic, still fragile.

## Lane 4 — Pydantic AI native primitives

**Sources:**
- Root: https://ai.pydantic.dev/
- Agents API: https://ai.pydantic.dev/api/agent/
- Message history: https://ai.pydantic.dev/message-history/
- Output: https://ai.pydantic.dev/output/
- Testing: https://ai.pydantic.dev/testing/
- Evals: https://ai.pydantic.dev/evals/ · quick-start: https://ai.pydantic.dev/evals/quick-start/
- DeepWiki eval framework: https://deepwiki.com/pydantic/pydantic-ai/9-evaluation-framework
- Logfire: https://pydantic.dev/logfire · AI observability: https://logfire.pydantic.dev/docs/ai-observability/
- Repo: https://github.com/pydantic/pydantic-ai

**Message history and conversation_id:** message history is a first-class typed object on every agent run result. `result.all_messages()` returns all messages including those from prior runs threaded via `message_history=`. A `conversation_id` is generated on first run and inherited by subsequent runs — load-bearing primitive for correlating multi-turn traces in Logfire. **No hidden `agent.memory` blob.** Reflection Packet emission can read `result.all_messages()` directly to construct the per-cycle trace.

**Dependency injection (RunContext):** dependencies passed via `RunContext`, parameterized with agent's `deps_type`. Natural place to thread reflection state (cycle_id, org_slug, classification_register_version) through every tool call.

**Output validation pipeline (two-stage):**
1. **Pydantic schema validation** — automatic from declared `output_type`.
2. **Custom validators** via `@agent.output_validator`.

`ValidationError` is converted to `RetryPromptPart` → agent retries. `ModelRetry` raisable from tool or output validator. Retry budget = `output_retries` (default 1), overridable per-agent/per-run/per-tool. `ctx.retry` exposes current count. **Reflection Packet implication:** packet IS a Pydantic-validated output type; schema mismatch / pattern-vs-instance violations become typed retries, not silent fallbacks. `@agent.output_validator` is natural attachment point for F-REFLECTION-* PRE-emission gates.

**Tool argument validation (args_validator):** runs after Pydantic schema validation, before tool execution. Receives `RunContext` first. Returns `None` on success; raises `ModelRetry` on failure. Natural attachment point for Cedar policy checks at Pydantic-AI boundary.

**Evals framework:** three components — **Dataset** (test cases), **Evaluator** (deterministic regex/PII checks OR LLM-based judgment for instruction-following / hallucination), **EvaluationReport** (metrics, assertions, labels, scores). Code-first; declared in Python or YAML loaded by Python. Results visualize in Logfire. **Span-based evaluation** evaluates internal agent behavior (tool calls, execution flow) via OpenTelemetry traces — essential for "how the answer was reached," not just final answer. **Right primitive for evaluating Reflection Packet quality:** a packet is correct not when it claims success but when its claims trace to the cycle's Logfire spans.

**Logfire spans:** OpenTelemetry-built. Every Pydantic AI run creates a detailed trace — every message, every tool call, every dependency lookup. Spans nest naturally (council-pipeline run spans Scribe → Editor → Judge → Red Team as child spans). **Critical Reflection Packet implication:** the packet's "what happened" content is already in Logfire as structured spans. **Packet should not duplicate spans; it should reference them via trace_id + structured extraction (gate-pass/fail counts, Judge/Red Team scores, time-to-completion), not re-narrate the trace.**

**Substrate fit:** the locked substrate (Pydantic AI + Logfire + Cedar) hosts a Reflection Packet natively. Pydantic BaseModel emitted as council's terminal artifact; validated by `@agent.output_validator` for schema + pattern-vs-instance discipline; referenced into Logfire spans via trace IDs; consumed by Archivist via existing `vault_read_intent_*` wrappers; subject to existing F-ARCHIVIST-* gates on read. **No new primitive required.**

**What does NOT fit:** parallel "skill library" alongside SKILL.md (Tilth's analogue is Cards / Cards / KFR / lessons.json); automatic lesson application without operator review (violates §15.9.3); frequent in-cycle reflection (message history + spans already cover within-cycle observability).

## Lane 5 — Field-documented self-improvement failures

**Sources:**
- AgentPoison (Chen et al., NeurIPS 2024): https://billchan226.github.io/AgentPoison.html · https://github.com/AI-secure/AgentPoison · https://openreview.net/forum?id=Y841BRW9rY
- MINJA (arXiv 2503.03704, 2025): https://arxiv.org/html/2503.03704v2
- MemoryGraft (arXiv 2512.16962, 2025): https://arxiv.org/html/2512.16962v1
- PoisonedRAG (USENIX Security 2025)
- Memory Poisoning Attack and Defense on Memory-Based LLM-Agents (arXiv 2601.05504, 2026): https://arxiv.org/abs/2601.05504
- Agent Security Bench (ASB; ICLR 2025): https://proceedings.iclr.cc/paper_files/paper/2025/file/5750f91d8fb9d5c02bd8ad2c3b44456b-Paper-Conference.pdf
- Survey on Security of Long-Term Memory in LLM Agents (arXiv 2604.16548): https://arxiv.org/html/2604.16548
- OWASP LLM Prompt Injection Cheat Sheet: https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html
- Arize field analysis: https://arize.com/blog/common-ai-agent-failures/
- Cognitive decay (Brsrk): https://dev.to/frank_brsrk/why-llm-agents-fail-four-mechanisms-of-cognitive-decay-and-the-reasoning-harness-layer-3148
- Mem0 security: https://mem0.ai/blog/ai-memory-security-best-practices
- MintMCP: https://www.mintmcp.com/blog/ai-agent-memory-poisoning
- Schneider: https://christian-schneider.net/blog/persistent-memory-poisoning-in-ai-agents/

**AgentPoison (NeurIPS 2024):** first backdoor attack targeting generic and RAG-based LLM agents by poisoning long-term memory or RAG knowledge base. Optimized trigger tokens crafted via constrained optimization map to unique embedding-space region. Trigger pattern in user instruction → malicious demonstrations retrieved with high probability. ≥80% average attack success rate, ≤1% impact on benign performance, poison rate <0.1%. **Implication:** vector-store retrieval is the attack surface; Reflection Packet content reaching Archivist must travel `vault_read_intent_*` wrappers, never raw vector queries.

**MINJA (2025):** practical attack — regular users with no elevated privileges can poison agent long-term memory through query-only interactions. Bridging steps, indication prompts, progressive shortening. >95% injection success (records stored), >70% attack success (agent produced attacker-desired output). **Implication:** threat model includes the operator's own conversational input. Operator commentary at cycle close is untrusted under MINJA; must be classified-routed and gate-checked.

**MemoryGraft (2025):** compromises agent behavior by **implanting malicious successful experiences** into long-term memory — not via immediate jailbreak, but via plausible-looking "good outcomes" retrieved as exemplars. Persists indefinitely. **Implication:** Reflection Packet must distinguish "this cycle's outcome" from "council's claim about this cycle's outcome." Outcome data should come from deterministic gate counts + Logfire spans, not from a single seat's free-text summary.

**PoisonedRAG (USENIX Security 2025):** first systematic knowledge-base corruption attack against RAG. Joint optimization over retrieval condition + generation condition. Five crafted texts in millions yield ~90% attack success. **Implication:** Funder Intelligence DB, Match DB, lessons.json are RAG-adjacent surfaces; Reflection Packet feeding any of these must be subject to F-ARCHIVIST-AUTO-APPLY-ATTEMPTED + new packet-side PRE-gate refusing retrieval-corruption-shaped content.

**Agent Security Bench (ASB; ICLR 2025):** formalizes attack categories — prompt injection, memory poisoning, knowledge-base poisoning, tool poisoning. Key finding: attacks achieve 80%+ success when agents consult memory before responding; existing defenses (tool contracts, circuit breakers, I/O moderation) fail because they detect **malicious actions, not corrupted beliefs**. Recommended defense primitives: **memory contracts (typed, schema-validated), belief drift detection, context provenance tracking.**

**Cognitive decay (production retrospectives — Arize, Brsrk, Redis):** four converged failure mechanisms:
1. **Attention decay** — system prompt loses binding after ~30 turns.
2. **Reasoning decay** — chain-of-thought quality degrades on long-horizon tasks.
3. **Sycophantic collapse** — model collapses toward user-frame agreement under uncertainty (RLHF gradient).
4. **Hallucination drift** — small factual errors compound across cycles when agent reads own prior output.

**Implication:** the Reflection Packet IS the agent reading its own prior output across cycles. Without a deterministic ground-truth anchor (gate counts, Logfire spans, operator-signed decisions), hallucination drift is the most-likely silent failure.

**Retrieval sycophancy (2025):** if user asks from false premise, retriever may fetch documents aligned with false framing → "hallucinate with citations." Retrieval layer inherits user-frame bias. **Implication:** Reflection Packet content read back into next cycle must NOT be retrieved by free-text query of operator's framing — retrieve by structured key (cycle_id, gate_code, score_dimension).

**Catastrophic forgetting:** bounded for Tilth (v0.1/v1 does not fine-tune in production; packet drives prompt-context, not weight updates). Relevant only if a future fine-tuning workstream lands.

**Eval gaming:** Reflexion-style verbal feedback can optimize for evaluator heuristics rather than underlying task. Tilth-specific manifestation: council learns to write to Judge's rubric heuristics rather than funder's actual rubric. Mitigated by cross-family Judge + Red Team divergence; Reflection Packet could re-introduce surface if "what worked" is measured by Judge score alone.

## Synthesis A — What generalizes to grant-writing vs what doesn't

**Generalizes:**

- **Reflection cadence at cycle close.** Generative Agents' importance-trigger maps cleanly — grant submission is the highest-importance event in the cycle. Cleaner than Hermes's noisy "every 5 tool calls."

- **Pattern-level extraction, not instance-level.** ExpeL + existing F-ARCHIVIST-LESSON-INSTANCE-LEAK agree: lessons propagating across cycles must be pattern-level. "Federal program officers in this category often decline when applicants undercount sub-awardees" generalizes; "Funder X declined Client Y for reason Z" doesn't. Reflection Packet schema must structurally distinguish.

- **Bounded reflection buffer, not ever-growing skill library.** Reflexion's bounded reflection text is right scale primitive for grant cycles. One packet per cycle close; Archivist consumes at cadence; proposes deltas to existing substrate (lessons.json, KFR, Match DB). The **substrate** is long-term memory; packets are transient.

- **Anthropic Dreaming's input-immutable / output-attached discipline.** Dream produces NEW output store; operator decides attachment. Maps directly onto Archivist proposes-only: packets land in `orgs/<slug>/reflection_packets/<cycle_id>.yaml`, Archivist reads them, proposes deltas, operator approves each delta. No automatic substrate mutation.

- **Span-based evaluation via Logfire.** Packet's claims about "what happened" verifiable against Logfire span tree. Pydantic Evals' span-based evaluation is native primitive — a packet asserting "Editor flagged 3 jargon items" is checkable against actual span count.

- **Three-stage taxonomy (Storage → Reflection → Experience).** Tilth already has Storage (`pipeline/validation/`, Logfire traces) and Experience (lessons.json, KFR, Match DB). Reflection Packet fills the missing middle.

- **Memory contracts (ASB / ICLR 2025).** Typed, schema-validated, provenance-tagged. The Reflection Packet IS a memory contract. Pydantic AI's typed output is the right substrate.

**Does NOT generalize:**

- **Hermes's auto-write-on-correction posture (user already flagged).** Agent-initiated SKILL.md writing into canonical folder after lightweight user approval — failure modes (skill poisoning, unsigned provenance, no audit trail) map onto exactly the threat surface §15.9.3 F-ARCHIVIST-AUTO-APPLY-ATTEMPTED was designed to deny. Tilth's inverse posture: structured proposal from cycle → Archivist proposes-only on consumption → operator owns canonical state. **Do not copy.**

- **Hermes's description-based natural-language retrieval.** Vulnerable to retrieval mismatch (the SoK trivy-vs-dependency-security example). Tilth's Reflection Packet retrieved by structured key (cycle_id, org_slug, funder_id, CIC, CLC), not description embedding.

- **Voyager's executable-code skills.** No analogous executable surface in grant writing (text output, not code). Packet should not carry executable code; it carries structured assertions + pointers into existing artifacts.

- **Self-Refine's same-model-judges-itself loop.** Already mitigated by cross-family Judge + Red Team. Packet must not re-introduce single-model self-judgment — "what worked" sourced from gate counts + cross-family scores, not single seat's free-text reflection.

- **Hermes's Layer 1 always-loaded `MEMORY.md`.** Tilth's analogue is **operator-curated**, not agent-curated. Reflection Packet must NOT propose edits to workspace-level always-loaded memory. That layer is operator-owned.

- **Auto Dream's automatic consumption cadence.** Archivist is operator-driven cadence at v0.2; v1.x scheduled-task lands fail-closed PRE-gate. Packet **emission** is automatic (every cycle close); **consumption** by Archivist remains operator-triggered until v1.x. Do not slip auto-consumption into v0.1.

**Specific translations:**

| Field-of-origin primitive | Tilth-native analogue |
|---|---|
| Hermes SKILL.md frontmatter (name, description) | Pydantic `ReflectionPacket` BaseModel with declared fields |
| Hermes Layer 2 (SQLite FTS5 archive) | Logfire span tree + `pipeline/validation/<cycle_id>/` |
| Hermes Layer 3 (skills folder) | `orgs/<slug>/reflection_packets/<cycle_id>.yaml` + Archivist-proposed deltas to KFR / lessons.json / Match DB |

| ExpeL failure-vs-success insight | `ReflectionPacket.gate_pass_counts` + `score_deltas` + `outcome` (provisional at submission, backfilled post-award) |
| Generative Agents importance trigger | Cycle-close trigger (grant submission event) |
| ASB memory contract | The ReflectionPacket Pydantic schema itself |
