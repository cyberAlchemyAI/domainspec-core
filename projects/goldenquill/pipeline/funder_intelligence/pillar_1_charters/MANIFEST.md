2. **Operator override at sign** of any default by PR comment or direct edit before signing.

3. **Ed25519 sign each charter** against the FID publisher pubkey at `vault_shared/funder_intelligence/publisher_pubkey.signed.yaml`. **Helper now landed** at `pipeline/funder_intelligence/_methodology/sign_charter.py` (14 passing tests). Workflow:

   ```bash
   # Step 1: get canonical bytes + hash
   python -m pipeline.funder_intelligence._methodology.sign_charter \
       pipeline/funder_intelligence/pillar_1_charters/<artifact_id>_charter_v0_DRAFT.md \
       --dry-run

   # Step 2: operator signs canonical_bytes offline with FID publisher Ed25519 key

   # Step 3: apply signature
   python -m pipeline.funder_intelligence._methodology.sign_charter \
       <charter_path> \
       --signer-pubkey-fingerprint <hex> \
       --signature-hex <hex> \
       --signed-at <UTC-ISO-8601>
   ```

   The helper canonicalizes the charter body (§7 signature block normalized to placeholders), computes SHA3-512, verifies the signature against the pinned FID publisher pubkey, renames the file to `_charter_v1_SIGNED.md`, fills the §7 block with the operator signature data, and updates this MANIFEST row's Sig status with the hash prefix.

4. **Pillar-2 corpus assembly fires per-charter** once that charter's signed file is on disk. Corpus directories at `_research_corpus/<artifact_id>/` are created at sign-event, not before.
