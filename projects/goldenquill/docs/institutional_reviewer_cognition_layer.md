# Institutional Reviewer Cognition Layer

## 1. Purpose
Behavioral architecture in Golden Quill / Tilth OS is a mechanism of cognitive load engineering for institutional work. Its purpose is to minimize human processing errors, eliminate domain-jargon fatigue, preserve operator orientation, and expose implicit structural boundaries. It ensures that complex, cross-sector institutional funding streams are navigable safely and deterministically by operators without requiring cognitive strain to maintain workflow state.

## 2. Rejected Patterns
The following consumer software patterns and manipulation tactics are explicitly forbidden across all Golden Quill / Tilth OS interfaces:
- Growth hacking or conversion funnel optimization
- Manipulative UX, gamified engagement, or "streak" psychology
- Nonprofit SaaS theater
- Dark patterns (e.g., hidden costs, deceptive framing, passive telemetry)
- Fake urgency, fake scarcity, or fake progress
- Fake autonomy or "AI is thinking" theater lacking genuine backend operations
- "Dismiss warning" compliance bypasses or generic "ignore" links
- Cartoon onboarding, celebratory confetti, or playful badges

## 3. Core Operating Doctrines
1. **Anti-Theater Law**: Every visual indicator must represent a deterministic backend event, explicit state, or auditable data condition. No fake progress, confidence, or agency.
2. **Chronological Lifecycle Discipline**: The operator console must orient the user through the lifecycle securely.
3. **Plain-Text Decision Strip**: The UI should persistently answer: what is happening, what is blocked, what must be addressed, what is the next valid action.
4. **Recovery Cognition**: Engineering for interrupted institutional work by answering where the operator is and what changed.
5. **Evidence Ladder**: Evidence quality is an epistemic state, not a flattened score.
6. **Confidence State**: The UI must support institutional confidence progression and stability.
7. **Cognitive Temperature**: Different workflows require different cognitive postures (e.g., Compliance Review requires high precision; Strategy Mapping requires exploratory expansiveness).
8. **Sturdier Ladders, Zero Snakes**: Reject consumer SaaS snakes; implement sovereign institutional ladders like fail-closed evidence quarantine and signed risk overrides.
9. **Surface Tone Boundary**: Customer-facing UI language must remain calm, plain, grounded, and supportive. Internal doctrine may use rigid/hard language, but the surface should not be over-militarized.

## 4. Canonical Lifecycle
The lifecycle for processing opportunities and maintaining cognition must rigidly follow:
Discover → Ingest → Gate → Decompose → Draft → Score → Authorize

## 5. Plain-English State Translation
Internal alphanumeric codes or backend terminology (e.g., "Gate E-104 failed") must be mapped to clear operational language in the decision strip (e.g., "ISSUE MUST BE ADDRESSED: Applicant registration status is unresolved. Gate E-104.").

## 6. Evidence Ladder
Evidence must be categorized into the following deterministic tiers:
- **Verified**: Traceable documentary proof.
- **Grounded**: Strong operational evidence.
- **Plausible**: Reasonable but incomplete support.
- **Aspirational**: Strategic intent only.
- **Unsupported**: Must not survive export.

## 7. Recovery Cognition Questions
Every major operator screen must immediately answer:
- Where am I?
- What changed?
- What is blocked?
- What is next?
- What requires me specifically?
- What already happened?

## 8. Scout First
The `/scout` interface shall be the first UI surface configured under this doctrine because it defines the operator’s initial cognitive relationship with the system and bears the highest risk of information overload.

## 9. Boundary Statement
This doctrine codifies cognitive presentation and operator orientation. It **does not authorize**:
- Autonomous submission or auto-submit features.
- Partner outreach.
- Drafting escalation.
- Model calls.
- `funder_terrain` mutation.
- UI bypass of deterministic gates.
