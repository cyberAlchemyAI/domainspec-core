# Whisper Ontology And Runtime Research Strategy

## Preliminary Answer

Whisper does not need a blank-slate ontology or a second prompt wrapper. It already
has named lifecycle artifacts, validators, evidence axes, human gates, and a generated
runtime projection. The research target is the missing middle: a small admitted
semantic model plus an executable lifecycle that can prove one bounded run. The
co-op-engine folder may incubate and demonstrate that candidate, but canonical Whisper
meaning remains owned by public Arcanum.

## P1 Trigger

This is a governed dispatch. Parallelism holds because ontology modeling and runtime
architecture are independent research fronts. Synthesis holds because repository
sources, external primary precedents, and two explorer returns must be reconciled.
Isolation holds because exploratory models and raw source notes should remain
discardable until adversarial review and exact evidence closure.

## Objective And Evidence Boundary

The output is an exact-binding research finding and implementation handoff for:

1. a candidate Whisper ontology covering meaning, story/composition objects,
   lifecycle state, evidence, receipts, and forbidden authority edges; and
2. a candidate runtime covering commands, events, artifacts, validation, human gates,
   recovery, replay, projections, and a thin co-op-engine demonstrator adapter.

Research may inspect and recommend. It may not create or admit the ontology, implement
the runtime, edit canonical Whisper, edit or deploy co-op-engine, append the dispatch
ledger before confirmation, promote authority, publish, release, or claim production
readiness.

## Dependency Flow

```text
ontology explorer ─┐
                   ├─> synthesizer <─(one bounded evidence feedback)─┐
runtime explorer ──┘        ⇄ reviewers (max two turns)             │
                                  │                                  │
                         exact evidence closure                      │
                                  │                                  │
                                writer <─ auditor (one repair) ──────┘
                                  │
                           parent final approval
```

- Explorers run in parallel.
- Synthesizer follows both explorer receipts.
- Reviewers run in parallel and may zig-zag with the synthesizer up to two turns.
- Missing source evidence may use one already-declared synthesizer-to-explorer
  feedback edge.
- The writer remains blocked until the exact-binding evidence gate is `ready`.
- The auditor may request one bounded writer revision; the parent remains final
  approver.
