# Stage 05 — Distill coherent tower unit

- Capability: `distill`.
- Mode and budget: `standard`; one proposal track, Proposer/Balancer, two finite rounds.
- Objective: select the smallest coherent design unit that produces a proper tower without mixing evidence meaning, layout, and future spatial-engine scope.
- Output artifact: the design-unit handle consumed by Invoke Design.
- Verdict: `pass`.

## Layer map

```text
CyberAlchemy Lab research workbench
└── Tower Evidence Navigator
    └── White Tower View
        ├── semantic scene contract
        ├── architectural tower shell
        ├── selection/refusal projection
        └── browser acceptance boundary
```

## Role trace

### Round 1

- Proposer: select a `White Tower View` comprising one shell, one spine, three evidence floors, one detail surface, and one separate System reference.
- Evidence/assumption: the current manifest already has exactly three evidence scenes and separately namespaced System descriptors; no new data model is needed.
- Balancer objection — responsibility leak: the current manifest does not enforce all floor bindings required by the view.
- Reconciliation: include a small semantic-contract hardening prerequisite, but keep it separate from layout mutation.

### Round 2

- Proposer: implement all contract, layout, interaction, mobile, and testing work as one task.
- Balancer objection — independent acceptance: manifest hardening, shell structure, interaction projection, and responsive/accessibility validation can fail independently.
- Reconciliation: keep `White Tower View` as the coherent feature, but split future execution into four ordered SWUs. The first is contract hardening, not the full UI.

## Smallest coherent unit

**White Tower View contract**: given the existing verified synthetic scene manifest, render exactly one ordered three-floor evidence tower whose selection projects state/source/ceiling into one detail surface, while a separate System reference can only render refusal.

It cannot be split further as a design concept because shell, floors, selection detail, and System separation jointly define what “proper tower” means. It must be split for implementation because its contract, structure, behavior, and browser evidence have independent acceptance boundaries.

## Recomposition proof

- Contract hardening guarantees every floor has sufficient data and truthful state.
- Tower shell makes that state navigable in a vertical architecture.
- Projection/refusal behavior connects native controls to the existing evidence detail without authority effects.
- Responsive/accessibility tests prove the selected layout contract at supported viewports and motion preferences.
- Together they recompose into the prior Tower Scene Canvas objective while removing the rejected scenic layer.

## Deferred complexity

- multi-tower navigation;
- pan/zoom/free camera;
- game or animation engine;
- generated images and robots;
- live graph, personas, MOGT policy, scoring, adjudication;
- human comprehension study and production packaging.

## Technique trace

- abstraction-level guard: kept the unit at the feature-view level, not CSS atoms or a whole Lab runtime;
- recomposition proof: pass;
- cognitive-load check: reduced competing focal regions to tower + detail;
- boundary-object check: the manifest remains the source/UX seam;
- premortem: likely failure is a beautiful tower that collapses evidence state or mobile reading order; guard with contract-first SWU and negative/browser tests;
- frame expiry: revisit if multiple real towers are selected or pan/zoom becomes a confirmed requirement.

## Navigation

Start with manifest contract hardening. Do not begin with CSS or delete the old page composition until the future implementation run has a passing contract test baseline.
