# White Tower View — implementation layering

- Capability: `implementation-layering`.
- Target: CyberAlchemy Lab White Tower View.
- Mode: created as run-local planning evidence.
- Layer count: 4.
- Boundary heuristic: applied.
- Recommended next layer: L0 only.

## L0 — contract truth

**After this layer, we know whether** every floor and System descriptor carries enough enforceable evidence to support a truthful tower UI.

- Minimum working unit: harden scene-manifest validation and negative tests.
- Included: evidence `implementation_status`, exact ceiling equality, blocked-state reason, axis membership, stable System evidence selector policy.
- Deferred: layout, wording in HTML, responsive behavior, animation, manual accessibility.
- Visible outcome: none beyond deterministic failure messages; this is a trust-building prerequisite.
- Risk reduced: visually convincing but semantically invalid floor data.
- Exit evidence: focused Node tests pass, including new negative cases.
- Promotion decision: only then begin the structural shell.

## L1 — architectural shell

**After this layer, we know whether** the current page can become a legible white three-floor tower without changing the API or depending on an engine.

- Minimum working unit: white workspace, tower shell/spine/floors, anchored detail, separate System region, forbidden decoration removed.
- Included: semantic markup, CSS layout/tokens, exact synthetic wording, static selector assertions.
- Deferred: final interaction projection, mobile hardening, contrast proof, motion polish.
- Visible outcome: first proper white tower at desktop width.
- Risk reduced: layout concept infeasible in plain DOM/CSS.
- Exit evidence: Node/server contract and focused structural browser assertions.
- Non-regression: L0 manifest failure behavior remains unchanged.

## L2 — behavior and resilient access

**After this layer, we know whether** tower selection, System refusal, reset, repeated inspection, responsive reflow, and reduced motion preserve the same semantics.

- Minimum working unit: state projection plus separately accepted responsive, accessibility, and motion units.
- Included: pressed mutual exclusion, focus contract, one live status, persistent listeners, mobile order/overflow/zoom, true no-motion preference, contrast checks.
- Deferred: human comprehension and production packaging.
- Visible outcome: locally testable, keyboard/mobile-operable tower prototype.
- Risk reduced: semantic drift across interaction modes and viewports.
- Exit evidence: focused Node + desktop/mobile Playwright + existing workbench compatibility.
- Non-regression: L0 truth and L1 structure/wording remain intact.

## L3 — manual evidence and polish

**After this layer, we know whether** the prototype's visual details survive manual assistive review without inflating readiness claims.

- Minimum working unit: manual screen-reader/browser matrix and restrained visual polish.
- Included: manual matrix, contrast confirmation, focus inspection, typography/roof/base refinements; optional short spine transition only if validated.
- Deferred: human comprehension study, multi-tower, engine, packaging, deployment.
- Visible outcome: reviewed local prototype.
- Risk reduced: automated tests missing assistive or visual defects.
- Exit evidence: manual receipt plus unchanged automated suite.
- Promotion decision: separate owner choice; no automatic release/deploy claim.

## Value/cost boundary

L0 unlocks truth at the lowest cost. L1 unlocks the visual concept. L2 unlocks repeatable interaction and viewport robustness. L3 adds manual evidence/polish. Combining them would delay the first falsifiable result and hide independently repairable failures.
