# Stage 08 — Distill Repair

- Capability: `distill`.
- Mode: `validate`.
- Pattern: `toy_game` plus validation loop.
- Evidence artifact: this scenario matrix.
- Verdict: `pass` for non-executed Plan authoring.

## Repair objective

Falsify the authored design cheaply before planning product edits. A scenario passes only when its required semantic state can be expressed without the removed scenic composition or an unproven capability.

“Pass” means the design specifies an unambiguous expected result and failure route. It is not runtime/browser evidence.

## Repaired design boundary

- First implementation unit: scene-manifest invariant hardening.
- Second: white tower structural shell and removal of scenic composition.
- Later units: projection/refusal interactions, responsive reflow, accessibility/repeatability, motion/contrast, browser closeout.
- No engine, asset, server-route, external-source, authority, promotion, publication, or deployment work enters the plan.

## Premortem

Likely failure: implementation begins with a large visual rewrite, then discovers that state labels and tests cannot distinguish blocked evidence from unavailable System capabilities. Guardrail: contract-first SWU with failing negatives, followed by one independently reviewable concern per SWU.

## Recomposition

The repaired unit still recomposes into the prior Tower Scene Canvas: it preserves the manifest/API, selection/refusal/source behaviors, and candidate ceiling while replacing only the rejected composition and strengthening its truth boundary.
