Pack that answers:

1. Which artifact is created first and where is its candidate-local owner?
2. What decision packet is needed for T04 representative selection versus T26

7. Where are the corpus-owner, ontology-owner, IDE-owner, privacy, validation,
   promotion, publication, deployment, and release gates?

## Candidate first-slice alternatives

Refine must compare, not silently choose, these candidate cuts:

- **A — package-only:** create the private Research Tower-shaped contract and
  fixtures, with no compiler or UI.
- **B — package plus deterministic projection:** create the package, exact
  manifest, machine-readable candidate ontology, compiler, and negative-test
  witness; defer the IDE shell. This is the provisional preferred cut because
  it can falsify identity and relation rules without conflating them with UI.
- **C — vertical navigator slice:** create package, projection, direct-GET
  adapter, and minimal trusted shell together. This has higher integration
  value but crosses more owners and risks hiding ontology defects behind UI.

Selection criteria must include evidentiary closure, owner-boundary count,
falsifiability, privacy exposure, reversible scope, implementation cost,
recomposition into the full Navigator, and avoidance of fixture-only success.

## Required low-cost falsification

fixture containing exactly one complete tower manifest, one source-backed

as cleared, projection-attempted promotion, POST/publication, and a
non-allowlisted tower. This Refine run designs the evidence contract; it does
not execute the fixture.
