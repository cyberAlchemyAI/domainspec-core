## The design in plain language

```text
Research Tower source package
  -> exact source and ordered package snapshots
  -> source-backed claims and byte-bound evidence anchors
  -> candidate ontology plus typed relations
  -> deterministic privacy-filtered projection
  -> later direct-GET trusted shell
```

Each arrow preserves ownership:

- source packages own authored evidence;
- Inventory, when used later, may discover evidence but cannot decide meaning;
- candidate ontology proposes meaning with no authority effect;
- the compiler creates a disposable read model, not a source or decision;
- the future workbench displays the projection without inheriting corpus, ontology, validation, or promotion authority.

The package and generated witness have separate identities. The package contains authored contracts, fixtures, compiler source, and tests. Generated projection/receipt bytes live outside it in the witness-run folder, avoiding a circular “projection derived from a package that includes the projection” claim.

## Candidate ontology and identity contract

Core kinds are `SourceSnapshot`, `TowerPackageSnapshot`, `Claim`, `EvidenceAnchor`, `DefinitionReference`, `ResidueItem`, `OntologyCandidate`, `ValidationRecord`, `PromotionRecord`, and `Relation`. Required relations are `package_contains`, `anchored_by`, `supports`, `references_definition`, `derived_from`, `blocked_by`, and explicit `contradicts` when present.

Identity rules:

- logical IDs, byte digests, and snapshot IDs are separate;
- equal bytes never create semantic identity or ownership;
- tower snapshot identity binds the complete ordered authored-file manifest;
- manifest reorder creates a new tower snapshot ID;
- anchors use raw UTF-8 byte ranges and selected-byte digests;
- projection revision binds the exact package/input snapshots, relation/rule/generator contracts, and privacy policy;
- changed inputs invalidate current use without rewriting historical evidence.

Stage 08 narrows canonicalization to `cal-canonical-json-v1`: ASCII object keys, safe integers, deterministic ECMAScript string escaping, preserved arrays, sorted object keys, no floats/exponents/negative zero, and duplicate-key rejection.
