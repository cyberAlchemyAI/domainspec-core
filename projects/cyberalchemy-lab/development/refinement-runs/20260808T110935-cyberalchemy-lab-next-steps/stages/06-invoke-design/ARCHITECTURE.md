# CyberAlchemy Lab L0 Candidate Architecture

## Design identity and evidence ceiling

- Selected unit: private Research Tower package plus deterministic one-manifest projection proof.
- Candidate package path: `projects/cyberalchemy-lab/research/tower-evidence-navigator/`.
- Candidate witness-run path: `projects/cyberalchemy-lab/development/witness-runs/l0-synthetic-001/`.
- Evidence state: `design-validator-pass` for this run-local design only.
- Plan evidence: `plan-evidence-pending`.
- Authority effect: `none`.
- Excluded implementation surface: `projects/ide-extension/**`.

The package holds authored contracts and test material. Generated projection bytes and executed receipts live in the witness-run path, preventing a derived projection from becoming part of the source package identity it claims to derive from.

### Closed record kinds

Every record includes `schema_version`, stable logical `id`, `record_snapshot_id`, `status`, `privacy_class`, `provenance`, `authority_effect: "none"`, and `fixture_class`.

| Kind | Required distinguishing fields | Invariant |
| --- | --- | --- |
| `SourceSnapshot` | `logical_source_id`, `content_digest`, `byte_size`, `media_type`, `locator`, `capture_context`, `owner`, revision relations | ID binds logical source and digest; equal digest does not merge logical sources. |
| `TowerPackageSnapshot` | `tower_logical_id`, complete ordered artifact manifest, source bindings, `manifest_digest` | Order is semantic for snapshot identity; reordering changes ID. |
| `Claim` | proposition, scope, owner, status, claim ceiling | One falsifiable proposition per record. |
| `EvidenceAnchor` | exact source snapshot, byte-range selector, selected-byte digest, role | Selector must resolve against exactly one immutable snapshot. |
| `DefinitionReference` | governed term ID, owning path, exact selector/digest, binding status | Candidate package references; it does not redefine the governed term. |
| `ResidueItem` | question/failure, scope, owner, status, blocked claims/gates | Open residue cannot be projected as cleared. |
| `OntologyCandidate` | proposed meaning, scope, evidence ceiling, review state, contradiction path | Candidate status and no authority effect are constant. |
| `ValidationRecord` | validator/profile/version, exact inputs, command, environment, result, violations, time | Proves only the named check over exact inputs; compiler cannot validate itself. |
| `PromotionRecord` | one primary candidate, exact evidence, owner, gate result, scope, contradiction, expiry, rollback, decision ref | L0 fixture requires `gate_result: "block"`; projection cannot change it. |
| `Relation` | kind, from/to IDs, direction, provenance, status | Kind must exist in the closed registry and endpoints must match admitted kinds. |

`fixture_class` has a closed initial vocabulary:

- `synthetic-contract-fixture`
- `mechanics-only-private-provisional`
- `owner-selected-real-tower`

Only the final value can cross the real-source admission gate, and it still proves one bounded tower rather than corpus coverage or representativeness beyond the exact owner decision.

### Evidence selector contract

L0 uses `utf8-byte-range-v1`:

```json
{
  "kind": "utf8-byte-range-v1",
  "start_byte": 0,
  "end_byte_exclusive": 42,
  "selected_bytes_sha256": "<64 lowercase hex>"
}
```

Offsets address raw file bytes; `start_byte < end_byte_exclusive <= byte_size`. The selected slice digest must match. No newline or Unicode normalization is permitted. Optional line/heading hints are display metadata and never selector identity.

### Package self-binding rule

`PACKAGE-SNAPSHOT.json` is part of the package, so a normal whole-file self-digest would be circular. `normalized-self-v1` resolves this explicitly:

1. In the manifest entry for `PACKAGE-SNAPSHOT.json`, set `content_digest` to 64 zeroes while computing `manifest_self_digest`.
2. In the document root, set both `manifest_self_digest` and `tower_snapshot_id` to 64 zeroes for the same computation.
3. Canonicalize with RFC 8785 JSON Canonicalization Scheme semantics and hash the UTF-8 bytes with SHA-256.
4. Put that value in the manifest entry and root `manifest_self_digest`.
5. Compute `tower_snapshot_id = SHA256(canonical({schema_version, tower_logical_id, ordered_artifacts_with_manifest_self_digest, source_bindings, definition_bindings_digest, privacy_policy_digest}))`.
6. Materialize `tower_snapshot_id`. Verification repeats normalization; no other field is excluded.

The ordered manifest covers every authored file in the candidate package. Generated witness-run files are not package files and are instead bound by `INPUT-LOCK.json` and their ValidationRecords. Any authored file add/remove/change/reorder creates a new package snapshot.

### Required relation registry

| Relation | From -> to | Cardinality/cycle policy |
| --- | --- | --- |
| `package_contains` | `TowerPackageSnapshot` -> any package record | one package to one-or-more records; acyclic |
| `anchored_by` | `Claim` or `OntologyCandidate` -> `EvidenceAnchor` | one-or-more anchors; acyclic |
| `supports` | `EvidenceAnchor` -> `Claim` or `OntologyCandidate` | many-to-many; acyclic in L0 |
| `references_definition` | `OntologyCandidate` -> `DefinitionReference` | one-or-more; acyclic |
| `derived_from` | projection record -> every input snapshot/record ID used | one-or-more; acyclic |
| `blocked_by` | `PromotionRecord` or candidate -> open `ResidueItem`, contradiction, or failed ValidationRecord | one-or-more while blocked; acyclic |
| `contradicts` | `Claim` -> `Claim` | explicitly symmetric pair with scoped status; cycles limited to the symmetric pair |

Unknown kinds or endpoint combinations fail. Relation order in input is normalized by `(kind, from_id, to_id, relation_id)` for output only; it does not create identity or discard duplicates with different logical IDs.

## View 4 — Workflow process

### Authoring workflow

1. Candidate package owner creates the Research Tower spine, closed schemas, synthetic fixture, compiler source, test vectors, and all `not-run` validation expectations.
2. Package snapshot tool enumerates every authored file in declared order, applies `normalized-self-v1`, and emits the candidate package snapshot.
3. Validation owner checks structure, schema closure, exact manifest coverage, and candidate-only invariants.
4. Corpus owner later supplies an independent decision and exact real-tower manifest; that creates a new package input snapshot, not a reinterpretation of the synthetic fixture.

### Compiler workflow

```text
load exact package snapshot and one allowlisted fixture/input
  -> reject parse/schema/closed-vocabulary violations
  -> recompute file digests, sizes, source IDs, normalized manifest self-digest,
     tower snapshot ID, definition/privacy/generator contract digests
  -> resolve every byte-range anchor against exact source bytes
  -> validate record ownership, status, evidence ceiling, contradiction and residue
  -> validate relation endpoints, cardinality, direction and cycle rules
  -> validate blocked PromotionRecord and authority_effect none constants
  -> apply privacy policy field-by-field; fail on denied material
  -> build stable records plus forward/reverse adjacency
  -> compute projection revision from exact inputs/rules/generator/privacy
  -> write canonical JSON to a temporary file, fsync when supported, atomically rename
  -> independent harness compares bytes and records a ValidationRecord
```

The compiler reads source bytes and writes one local disposable projection. It is therefore not “zero-write.” Zero domain mutation and zero interaction persistence belong only to the later navigation shell contract.

### Projection revision

```text
projection_revision = SHA256(canonical({
  projection_schema_version,
  tower_snapshot_id,
  input_record_snapshot_ids_sorted,
  relation_registry_digest,
  projection_rules_digest,
  generator_contract_digest,
  privacy_policy_digest
}))
```

The projection contains the formula inputs, stable records sorted by `(kind,id)`, relations sorted by registry order then IDs, forward/reverse adjacency, privacy decisions, invalid/stale state, and `authority_effect: none`.

## View 5 — Decision flow

```text
Does input claim representative/real-tower status?
  no -> mechanics-only lane; projection may prove contract mechanics only
  yes -> is exact corpus-owner decision + complete manifest bound?
          no -> BLOCK before compilation
          yes -> validate one owner-selected real tower

Do all digests, byte sizes, IDs, selectors, kinds and relations close?
  no -> FAIL CLOSED; emit no new projection
  yes -> apply privacy policy

Does any denied/private field escape the exact allowlist?
  yes -> FAIL CLOSED; emit no new projection
  no -> build canonical projection

Are contradiction/residue/PromotionRecord states still represented exactly?
  no -> FAIL CLOSED
  yes -> write candidate projection; independent validation remains separate
```

An existing valid projection is never overwritten after a failed run. The failed run may write a run-local diagnostic receipt but cannot relabel the prior projection as current.

## View 6 — Dependency and interface

| Boundary | Producer | Consumer | Contract | Gate |
| --- | --- | --- | --- | --- |
| Accepted findings -> package | research owner | candidate package owner | exact source selectors/digests | no authority uplift |
| Owner selection -> real source | corpus owner | package/compiler owner | decision record + complete ordered manifest | owner prerequisite |
| Package -> compiler | package owner | compiler | `PACKAGE-SNAPSHOT.json`, schemas, fixture/input, privacy/rules | exact digest validation |
| Compiler -> witness run | compiler | validation owner | canonical projection + input lock | local reversible write only |
| Witness run -> validator | compiler | independent test harness | exact inputs, command, environment, bytes | compiler cannot self-issue pass |
| Projection -> future IDE | witness run | IDE adapter | projection schema/revision and allowlisted path | later Work Pack; direct GET only |
| Private -> public | private owners | public Arcanum owner | scrubbed candidate plus explicit decision | entirely outside L0 |

Reserved later direct-GET response fields are: `projection_schema_version`, `projection_revision`, `tower_snapshot_id`, `generator_contract_digest`, `privacy_policy_digest`, `fixture_class`, records, relations, forward/reverse adjacency, source digest, selector, owner, privacy class, claim ceiling, contradiction/residue state, invalid/stale state, and `authority_effect`. The later adapter must bind exact adapter version, session, allowlist, and privacy policy. It may expose no POST/publication route.

| ID | Decision | Rejected alternative | Revisit condition |
| --- | --- | --- | --- |

| D-06 | Treat synthetic validation as mechanics-only. | Infer real-source or representative readiness. | Never reinterpret; create a separate real-source receipt. |
| D-07 | Defer UX plan and IDE implementation. | Select UX from future product vocabulary alone. | Revisit when a natural-person rendered surface enters the selected footprint. |

## Risks and design mitigations

| Risk | Mitigation | Owner |
| --- | --- | --- |
| Self-referential manifest identity | `normalized-self-v1` with exactly two normalized root fields and one manifest-entry digest | package/validation owners |
| Projection included in its own source identity | generated output lives in witness run outside package | package owner |
| Equal bytes collapse distinct sources | owner logical IDs remain primary; digest is snapshot content only | ontology owner |
| Fixture-only false success | closed `fixture_class`; separate real-source admission/receipt | validation and corpus owners |
| Private path/content leakage | field-level privacy allowlist plus output scan negative | privacy owner |
| Compiler self-validates | compiler emits bytes/input lock; independent harness issues ValidationRecord | validation owner |
| UI creates hidden state | IDE slice deferred; direct GET and navigation-only contract reserved | IDE owner |
| Candidate becomes authority by projection | constants, blocked PromotionRecord, negative promotion mutant | authority owner |

## Design Distill check

- Mode: `validate`, parent role simulation.
- Coherent unit: package contracts plus deterministic projection proof.
- Split pressure: source package and generated witness run have distinct identities but must stay in one Work Pack because the compiler proof is the acceptance boundary selected by Distill.
- Recomposition: the future IDE consumes the projection contract without changing source/ontology identity.
- Result: `pass` after explicitly separating generated output from package identity and preserving the corpus-owner prerequisite.
- Evidence emission: `not-configured`; run write scope excludes observability.
