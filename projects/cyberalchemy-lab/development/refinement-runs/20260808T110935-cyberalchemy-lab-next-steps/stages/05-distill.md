## Role conversation trace

### Round 1

- Proposer claim: select B; a package without a compiler leaves the central identity/relation rules unfalsified, while UI is not necessary to test them.
- Evidence/assumption: accepted findings require deterministic projection and negative tests; existing IDE patterns can consume a later revision-bound projection.
- Balancer objection category — scope leakage: B may quietly become a full ingestion pipeline or primary graph store.
- Reconciliation: constrain B to one allowlisted manifest, JSON artifacts, one dependency-free deterministic compiler, disposable output, no inventory ingest, and no graph database.

### Round 2

- Proposer claim: a synthetic complete toy fixture permits reversible schema/compiler work while the representative tower is unresolved.
- Evidence/assumption: the Refine seed explicitly requires a controlled toy fixture; accepted findings allow mechanics-only evidence but deny representativeness.
- Balancer objection category — evidence substitution: a passing synthetic fixture might be treated as the real one-tower witness.
- Reconciliation: split evidence states. Synthetic fixture validation proves `contract-mechanics-pass` only. Real-tower admission requires an owner decision, complete manifest lock, and distinct validation receipt before any source-derived projection claim.

Stable disagreement: none about the first cut after the evidence-state split. The corpus owner choice remains unresolved by design.

## Closure and recomposition proof

B closes because it owns named inputs (one manifest, locked snapshots, rules, privacy policy), behavior (validate then deterministically project), outputs (projection plus ValidationRecord), and failures (closed negative matrix). It recomposes upward because the later IDE adapter needs only direct GET of the exact projection schema/revision; adding the shell does not change source identity or ontology rules. Multi-tower evolution can later add an aggregation layer without changing one-tower snapshot semantics.

## Evolution profile and deferred complexity

- Expected evolution: admit one real selected tower, then provide a read-only IDE shell, then test repeatability across multiple owner-selected towers.
- Smallest extension boundary: versioned projection contract with `tower_snapshot_id`, `projection_revision`, record/relation registries, privacy profile, invalid/stale status, and generator version.
- Deferred: IDE route/shell, browser/UX/accessibility, multi-tower aggregation, Inventory ingestion, durable/graph storage, cross-repository publication, authority/promotion, deployment/release.

## Tension ledger

- Resolved: falsifiability versus scope — select B and keep output disposable.
- Resolved: synthetic progress versus owner selection — separate mechanics evidence from real-source admission.
- Resolved: future UI seam versus present owner count — reserve contract fields; defer adapter and shell.
- Unresolved: representative tower and exact real manifest — corpus owner.

## Premortem

Most likely failure: a clean synthetic projection is shown as proof that the repository corpus is modeled correctly. Guardrail: every fixture, projection, and receipt carries `fixture_class`; only `owner-selected-real-tower` can satisfy the real-source gate, and even that proves one bounded tower rather than corpus coverage.

## Frame-expiry note

Re-run Distill if the first required decision changes to human usefulness, accessibility, multiple towers, external publication, or a durable graph. Those frames change the smallest coherent unit and owner set.

## Navigation guide

Start Design from selected unit B. Preserve A as its package/schema component and C as the recomposition target. Design the synthetic fixture and compiler so the real tower can be substituted only through the corpus-owner admission record; do not add the IDE surface to the first Work Pack.
