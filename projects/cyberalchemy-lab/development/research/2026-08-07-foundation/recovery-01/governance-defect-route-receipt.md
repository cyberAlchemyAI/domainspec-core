## Root cause

The route projection mixed step artifact outputs with role receipt outputs. `findings.md` correctly belongs to step `s2.outputs`, but `findings-writer.output_refs` must contain only the writer receipt because capability-bound wave gates consume role receipts. The three `research` step capability handles also lacked local-extension metadata, and the dispatch cited no catalog technique.

There is a separate validator/schema tension: the schema permits `subagent_strategy.parallelism: none`, but the semantic validator rejects `none` whenever strategy status is `recommended` or `required`. The confirmed recovery is sequential, with every execution wave declaring `parallel: false`. To meet the sidecar requirement that the staged candidate reach `VALIDATION=pass`, the candidate uses validator-compatible `parallelism: mixed` while preserving all three waves as strictly sequential. `mixed` is a compatibility label only; no agents run concurrently, and it is not authority to run roles concurrently.

## Affected invariant

For capability-bound delegation, each role output reference must be a receipt output of its applied step, and every non-final wave gate must require those exact role receipts. Noncanonical capability handles must identify their local-extension source. The route must cite a validated technique reflected in its structure. Strategy metadata must not contradict the executable wave ordering.

## Minimal repair

1. Removed only `findings.md` from `findings-writer.output_refs`; retained it as the artifact output of step `s2` and in the writer's existing write scope.
2. Left `g-findings.requires_role_receipts` bound only to `findings-writer.json`.
3. Added `capability_status: local-extension` and source metadata for `research` to steps `s1` through `s3`, using `implementation/domainspec/internal_tools/subagents-dispatch-hooks/skills/research/SKILL.md`.
4. Added the catalog technique `observability_grouping`, which is reflected by the existing `observability.signal_grouping` field.
5. Set the validator-facing `subagent_strategy.parallelism` value to `mixed`; every execution wave remains `parallel: false`, in the same role and dependency order.

No role, step, wave, dependency, gate, artifact output, write scope, forbidden scope, observability event, promotion guardrail, or authority boundary was added or removed. The original route was not modified.
