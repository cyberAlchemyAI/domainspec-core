## VerificationPromptProjection contract

```text
VerificationPromptProjection
  selected_floor_id: FloorId
  bound_evidence_refs: SourceBindingRef[1..n]
  known_evidence: EvidenceStatement[1..n]
  unbound_evidence: EvidenceGap[1..n]
  verification_question: NonEmptyText
  route_suggestion:
    route_id: RouteId
    label: NonEmptyText
    executable: false
```

`route_suggestion` has no `endpoint`, action, request method, dispatch hook, command binding, or execution status. `executable` is required and literally `false`.

Contract laws:

1. `selected_floor_id` equals the active `[data-scene-id]`.
2. Every `known_evidence` item cites one or more `bound_evidence_refs` whose status is `verified`.
3. Every `unbound_evidence` item names a concrete missing witness; Inventory absence alone is not evidence of the gap.
4. `verification_question` changes only through the selected-floor projection.
5. `route_suggestion` remains descriptive and non-executing.
6. Different floors have distinguishable bindings or question fields; generic repetition fails.
7. No field implies ontology admission, authority, workflow execution, learning, implementation, promotion, release, deployment, or production status.

These fields and laws are a synthesis contract grounded in `research.md` § Agent 3, Ranked experiment 1, and § Agent 2, workflow-specification/execution Boundary law 5; their immutable precedent selectors are RP-LG `## Result`, `## Reuse Boundary`, `## Proof Boundary` and SLX `### 3. Workflow specification versus execution`, lines 64–68. They are not claimed as already implemented.

## C2 investigation-state/open/return contract

```text
WhiteTowerInvestigationState
  active_floor_id: FloorId
  inspection_kind: "floor" | "source" | "candidate" | "relation"
  inspection_record_id: RecordId | null
  relation_filter: String
  opened_reference_id: SystemReferenceId | null
  focus_return_target: ElementId | null
```

`open_system_reference(reference_id, trigger_id)` requires readable investigation state and a declared unavailable reference. It sets only `opened_reference_id` and `focus_return_target`; preserves floor, inspection, record, and filter byte-for-byte; keeps the reference unavailable and non-executing; focuses the reference heading or status; and creates no request, run, effect, score, verdict, promotion, or authority state.

`return_from_system_reference()` requires an opened reference plus a resolvable target or declared stable fallback. It clears only `opened_reference_id`; preserves the rest of the investigation state; returns focus to the recorded target or to the active inspection heading with an announced fallback; and reconstructs nothing from prose or defaults.

The contract collapses if open clears or mutates investigation state; if retained context and opened reference are not named separately; if return rebuilds default state; or if the System acquires execution or authority semantics. This is recommended as a structural correction only. ## Fail-closed source-binding contract

```text
SourceBindingRef
  repository_ref: RepositoryIdentity
  object_id: CommitOrGitObjectId
  path: RepositoryRelativePath
  expected_sha256: Sha256
  observed_sha256: Sha256 | null
  status: "verified" | "object_unavailable" | "path_missing" | "digest_mismatch"
```

Resolution must locate the exact repository/object and path, hash those bytes, and set `verified` only on digest equality. Object, path, or digest failure must show the exact identity and an unavailable/unverified status while suppressing ordinary sourced-claim presentation. Inventory may supply a locator; it cannot replace bytes, object, path, or digest, repair a mismatch, or upgrade status. Cached prose, summaries, or labels are not substitutes. Any binding failure that still renders an ordinary verified claim fails the contract. [Explorer basis: `research.md` § Agent 3, experiment 5 and “No-effect/regression counterexamples”; immutable selectors: RP-IOLM `## Public And Authority Boundary`; WT-R proof ceiling.]

### C2 — investigation continuity

- **Population:** intended evidence inspectors, with novice and experienced strata reported separately.

### E1 — verification prompt

- **Population:** intended inspectors, novice and experienced strata reported separately.
- **Task:** identify the selected floor’s known evidence, unbound evidence, verification question, and whether the route can execute.
- **Manipulation:** floor-bound `VerificationPromptProjection`.
- **Comparator:** no projection, with the same statements available in existing content.
- **Primary outcome:** correct identification of all four elements, including non-executability.
- **Secondary outcomes:** false-command rate, response time, omission type, and candidate-route/authority confusion.
