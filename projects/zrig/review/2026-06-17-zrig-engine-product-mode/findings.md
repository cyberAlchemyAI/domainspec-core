# Z-Rig Engine / Product-Mode Findings

Dispatch: `2026-06-17-zrig-engine-product-mode-review`
Status: verified change-request list, pending final coverage approval.

Severity key:

- `CRITICAL`: product-mode gate can report success while a governed condition is failed or unevaluated.
- `MAJOR`: load-bearing engine/product-mode gap, reachability gap, trust-boundary gap, or operator-blocking missing contract.
- `MINOR`: accounting, documentation, or lifecycle drift that should be fixed but is not by itself a product-mode break.

## Ranked Fix Order

1. Fix gate coverage and fail-closed behavior for unimplemented gates (`F1`).
2. Make deploy/sentinel reachability and live bridge trust explicit (`F4`, `F5`, `F6`, `F7`).
3. Fix auditability and operator validation blockers (`F3`, `F8`).
4. Correct runtime authority/accounting bugs (`F9`, `F10`, `F11`, `F12`).
5. Clean product/spec drift and non-wired lifecycle features (`F13`, `F14`).

## Refuted Or Downgraded Claims

- `AUTO` is not used by the checked-in `examples/run_config.json`; that part of the initial Turing claim was dropped.
- The code schema does accept `AUTO`; the finding is only PDF-vs-code/docs drift, not a schema rejection.
- Dry-run/stub success is not a hidden behavior because CLI help labels `--live` as non-default; this was downgraded from major to minor and retained as an assurance-boundary improvement.
