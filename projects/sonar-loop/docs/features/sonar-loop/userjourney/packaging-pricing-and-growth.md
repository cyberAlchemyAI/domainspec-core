# Packaging, Pricing, and Growth

## Scope

Commercial packaging, pricing axis, ongoing operations cadence, and expansion path.

## Finalized Decisions (Wave 4)

| Question | Decision                                                 | Implication                                                                                                     |
| -------- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Q13      | `A` primary with `B` secondary intent                    | Primary package is docs/spec product, with guided implementation accelerator as a secondary packaging motion    |
| Q14      | `A` mapped to one-time non-SaaS purchase                 | Pricing communication is per repository under governance, sold as a one-time package rather than recurring SaaS |
| Q15      | `A` weekly governed loop with low intervention           | Steady-state operator journey is weekly, checkpoint-driven, and low-friction                                    |
| Q16      | `A` land one repo, expand to adjacent repos in same team | Initial expansion strategy is repo-based replication inside one team                                            |

## Packaging Model

Primary:

- docs/spec product that defines the governed quality-loop contract

Secondary intent:

- guided implementation accelerator package for teams that need assisted rollout

## Pricing Axis

- Repository-based packaging anchor.
- One-time non-SaaS purchase framing for initial commercialization.
- Pricing language should stay aligned with repository-scoped governance outcomes.

## Ongoing Operator Journey

Steady-state operations are defined as:

1. weekly governed loops
2. low intervention by default
3. explicit checkpoint outcomes when intervention is required

Reference: [AutonomousCheckpointWorkflow](../workflows.md#autonomouscheckpointworkflow)

## Growth Path

Expansion starts with one repository and scales to adjacent repositories in the same team after proof continuity.
