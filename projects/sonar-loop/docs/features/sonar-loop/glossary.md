# Glossary: Sonar Loop

Quick-reference glossary of feature language and concepts distilled from the feature specification and aspect documents.

Scope note: This glossary explains what feature terms mean in ordinary product language first, then links each formal concept back to its authoritative source. Authoritative behavior, fields, rules, and lifecycle contracts remain in the linked source documents.

## Feature Language

| Term                   | Meaning in this feature                                                                                                                | Related Concepts                                                                                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Parent cycle           | The durable loop container that survives across one or more remediation passes for the same repository quality effort.                 | [ExecutionCycle](domain.md#executioncycle), [ProgressiveQualityLoopWorkflow](workflows.md#progressivequalityloopworkflow)                                                  |
| Child pass             | One ordered iteration inside a parent cycle, used to compare gate progress, findings, tasks, and telemetry over time.                  | [ExecutionCycle](domain.md#executioncycle), [CycleTelemetryEvent](observability.md#cycletelemetryevent)                                                                    |
| Quality gate           | The selected Sonar threshold profile that decides what quality bar the current cycle is trying to satisfy.                             | [QualityGateProfile](domain.md#qualitygateprofile), [DetermineTargetQualityGate](operations.md#determinetargetqualitygate)                                                 |
| Runtime fallback       | Governed movement from the default Sandcastle runtime to another approved runtime when availability or policy conditions require it.   | [ExecutionRuntimeMode](domain.md#executionruntimemode), [ExecutionProviderFallbackPolicy](rules.md#executionproviderfallbackpolicy)                                        |
| Runtime-invoking stage | A loop stage that actually calls an execution runtime and therefore must carry fallback evidence when it does not use Sandcastle.      | [RuntimeInvokingStage](domain.md#runtimeinvokingstage), [SandcastleAgentExecutionInterface](interfaces.md#internal-sandcastleagentexecutioninterface)                      |
| Evidence               | Persisted proof that a gate, retry, fallback, export, override, or checkpoint decision met the required policy conditions.             | [TelemetryEnvelope](domain.md#telemetryenvelope), [TelemetryCompletenessRule](rules.md#telemetrycompletenessrule)                                                          |
| Checkpoint             | A controlled decision boundary where the loop can continue, pause, halt, or complete based on mode-control authority.                  | [CheckpointControl](domain.md#checkpointcontrol), [ApplyModeControlCheckpoint](operations.md#applymodecontrolcheckpoint)                                                   |
| Halted                 | A resumable checkpoint-hold state entered after a stop request is honored with timestamp and checkpoint proof.                         | [ModeControlOutcome](domain.md#modecontroloutcome), [AutonomousCheckpointAndStopPolicy](rules.md#autonomouscheckpointandstoppolicy)                                        |
| Pause                  | A first-class checkpoint outcome, especially for assisted operation, that holds the cycle until an explicit follow-up decision exists. | [ModeControlOutcome](domain.md#modecontroloutcome), [AssistedDecisionWorkflow](workflows.md#assisteddecisionworkflow)                                                      |
| Risk acceptance        | A governed approval artifact that can permit completion under export degradation only after validity checks pass.                      | [RiskAcceptanceOverride](domain.md#riskacceptanceoverride), [RiskAcceptanceOverrideValidityPolicy](rules.md#riskacceptanceoverridevaliditypolicy)                          |
| Export degradation     | A task-delivery condition where active retries or degraded GitHub/Jira export outcomes would normally block completion.                | [CompletionGateUnderExportDegradationPolicy](rules.md#completiongateunderexportdegradationpolicy), [ApiFirstTaskIntegrationPolicy](rules.md#apifirsttaskintegrationpolicy) |
| Skill bundle           | An agent-agnostic capability package that is reused when still valid and recomposed only when deterministic triggers require it.       | [SkillBundleProfile](domain.md#skillbundleprofile), [SkillBundleReusePolicy](rules.md#skillbundlereusepolicy)                                                              |
| Sonar retry            | The single permitted remediation-evidenced second attempt after an initial Sonar evaluation failure.                                   | [SonarRetryPolicy](rules.md#sonarretrypolicy), [EvaluateWithSonarQualityGate](operations.md#evaluatewithsonarqualitygate)                                                  |
| Learning               | Feedback captured from operator-selected solution choices so later cycles can improve ranking and abstraction decisions.               | [LearningMemory](domain.md#learningmemory), [LearningFeedbackRule](rules.md#learningfeedbackrule)                                                                          |

- Keep each formal concept definition to one domain-level sentence, but make the sentence teach the term rather than repeat the source table.
- Link every entry to the authoritative source anchor.
- Update this glossary whenever concept names, concept IDs, source anchors, or definitions change.
- Do not introduce new canonical behavior here; update the source aspect document first.
