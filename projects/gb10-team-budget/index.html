Capability fit

Use local GB10 for iteration. Use cloud when the run gets expensive.

Local sweet spot

Private prototypes, agent testing, eval harnesses, small fine-tunes, demos, and local inference where predictable spend matters more than raw datacenter speed.

Useful limits

NVIDIA positions DGX Spark around 128GB unified memory, up to 1 petaFLOP FP4, fine-tuning up to 70B parameter models, and inference/testing up to 200B parameter models.

Cloud escape hatch

The 2k training reserve is for burst jobs that need bigger GPUs. The 3k inference reserve covers APIs, hosted endpoints, and external customer demos.

Source anchors: NVIDIA DGX Spark workload page and Acer Veriton GN100 specification page.

Team of 5 operating model

Four boxes work if ownership is explicit.

1
Builder A Primary local model dev. Owns one node during build hours.
2
Builder B Fine-tuning and data prep. Owns one node plus scheduled cloud bursts.
3
Eval lead Regression, scoring, and benchmark runs. Owns one node.
4
Platform lead Shared serving, images, model registry, and deployment hygiene.
5
Product lead Uses scheduled access, cloud inference budget, and demo windows.

The fifth person does not need a dedicated local box if the shared node is treated as a staging and demo resource, with booking rules and idle shutdown discipline.

Rollout plan

Procurement should land with a 30-day proof loop.

Order and receive Confirm stock, tax, warranty, return terms, and whether 4TB storage is included.
Standard image Baseline DGX OS, SSH access, users, containers, model cache, telemetry, and backup path.
Workload lanes Assign local inference, eval, fine-tune, and shared staging lanes with booking rules.
Proof checkpoint Measure utilization, cloud spend, model sizes, queue time, and team friction before buying more.
