## Execution Order

1. `SWU-MSB-006`: one-shot ready/claim/result/interrupt session client.
2. `SWU-MSB-007`: required task, truthful approval, split receipt display.
3. Join both results and execute `SWU-MSB-008`: target/claim/recovery/result UX.

## Parallel Merge Rules

- 006 owns session script/protocol/tests; 007 owns initial HTML/DOM tests.
- Neither changes kernel semantics or the other unit's focused tests.
- Resolve interface drift through the owning W1 contract before 008.

## Exit Gate

- CLI commands are one-shot, loopback-only, machine-readable, and powerless to
  ready/release/requeue or mint receipts.
- Workbench requires task and makes authorization/execution visibly distinct.
- Every v2 state/action, singleton conflict, recovery, and terminal evidence flow
  passes focused workbench tests at narrow and desktop widths.

## Stop Conditions

A background poller/executor becomes necessary; UI needs to bypass actor rules;
kernel interface drift remains unresolved; or responsive controls overlap.
