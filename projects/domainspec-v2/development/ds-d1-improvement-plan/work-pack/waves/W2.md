# W2: Semantic Hardening

## Purpose

Add finite, validator-backed distinctions for the highest-risk DS-D1 backend
categories and resolve Saga's boundary with Workflow.

## Sequence

1. Run SWU-DSD1-007 for the Saga fork decision.
2. Run the selected Saga branch: SWU-DSD1-008 or SWU-DSD1-009.
3. Run backend hardening SWUs that remain selected: SWU-DSD1-010,
   SWU-DSD1-011, SWU-DSD1-012.
4. Run SWU-DSD1-013 only for validator support required by selected schemas.
5. Run SWU-DSD1-014 after criterion support is stable.

## Entry Gate

W0 must be complete. Saga mutation requires SWU-DSD1-007.

## Parallelization

Backend hardening SWUs can run in parallel only when their schema, fixture, and
test scopes are disjoint. Validator helper conflicts must be coordinated by a
parent owner.

## Exit Gate

Selected type distinctions have positive and negative fixtures, validation
evidence, and human-readable correction routes.

## Validation

- `npm --prefix projects/domainspec-v2/impl run tools:test`
- `npm --prefix projects/domainspec-v2/impl run validate`
- Focused generated-instance validation when schema criteria change.
