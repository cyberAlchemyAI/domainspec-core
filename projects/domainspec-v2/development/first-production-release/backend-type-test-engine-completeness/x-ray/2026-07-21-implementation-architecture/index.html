How we are going to implement it

Compile governed JSON sources with a separately versioned YAML formation contract, turn the compiler’s normalized graph into an exact set of obligations and runnable tests, then prove every expected test executed, every targeted invalid case failed, and every result can be replayed to its source bytes.

01 · THE IMPLEMENTATION IN ONE SENTENCE

One causal pipeline, four separated planes

Authority says what is allowed. The compiler turns authored sources into a graph. The proof plane derives and executes exact checks. Consumers independently show the graph remains useful without becoming DomainSpec authority.

02 · WHAT WE KEEP

Use the proven core

Reuse the strict YAML criterion kernel, minted-node body adapter, source hashing, compiler graph/manifest shape, deterministic utilities, and narrow receipt-verification patterns.

03 · WHAT WE ADD

Build the missing proof spine

Add versioned replacement contracts, independent edge sources, minted-graph derivation, independent obligations, strict bindings and evaluators, execution/mutation evidence, complete receipts, replay, and fail-closed aggregates.

Most important architecture correction

Do not make the legacy Markdown parser the BTE source path

The current test-derivation engine’s public entrypoint parses Markdown/aspect documents into its own ConceptGraph. The BTE requirement says the minted compiler’s MintedGraph and MintedSourceManifest are the canonical derivation inputs. We should add a dedicated minted-project adapter and proof IR, then reuse deterministic keying, evaluation, emission, and receipt utilities only where their contracts still fit.

Reuse vs build

What changes in the codebase

The target is not a rewrite. It is a new, explicit proof path connected to existing compiler primitives.

Reuse and harden

  • meta-type-criteria.ts: parser, preflight, evaluator, stable violations.
  • meta-type-body-adapter.ts: node-body normalization and schema digest check.
  • resolver.ts: path containment, aliases, source hashing, canonical source-set digest.
  • compiler.ts: profile binding, node validation, deterministic graph/manifest output.
  • Existing keying, formal evaluation, deterministic serialization, and receipt-verification techniques where compatible.

Build as bounded modules

  • Versioned formation-replacement and JSON-retirement contract loaders.
  • Independent edge schema/root resolver and ordered graph model.
  • Minted graph → proof IR adapter.
  • O_spec validator, O_gen deriver, exact-set comparator.
  • Strict binding resolver, evaluator registry, test/mutation runner.
  • Causal receipt schema, replay verifier, core/consumer aggregate runners.

Do not carry forward

  • Current-v1 in-place widening or silent JSON retirement.
  • Node-embedded connections as the claimed independent-edge design.
  • Markdown/aspect parsing as minted graph authority.
  • First-match binding resolution.
  • Generated todo/skip as completeness evidence.
  • Count equality, literal pass fields, or producer-authored consumer receipts.

Implementation lifecycle

Build in seven dependency-safe slices

Each slice should begin with a failing control, implement the positive path, and finish with tamper/replay validation. Completed kernel and adapter receipts remain historical facts.

SLICE 0 · DESIGN

Freeze contracts

Profile identity, formation schema, retirement map, failure precedence, edge record, proof IR, bindings, evaluator, receipts. Then refresh Plan/layering.

SLICE 1 · FORMATION

Implement replacement

Load the new contract, evaluate required structure and stronger criteria, run current-v1 migration and false-green controls.

SLICE 2 · GRAPH

Add edge sources

Resolve independent edges, enforce root/scope/direction/order, emit deterministic graph and complete manifest.

SLICE 3 · BREADTH

Build exact corpus

13 positive kinds, 16 criterion mutants, and—after admission—selected causal relationship witnesses.

SLICE 4 · DERIVE/RUN

Prove exact sets

Freeze O_spec, derive O_gen, emit tests, resolve strict bindings/evaluators, run all tests and mutants.

SLICE 5 · EVIDENCE

Receipt and replay

Join source-to-result identities and digests, detect tampering, and expose fail-closed verify:bte:core.

SLICE 6 · CONSUMERS

Independent proof

IOLM and Body War run from the exact core handle; consumer and terminal aggregates validate fresh receipts.

Reader terms

Plain language for the new architecture

Open any term you need. Each definition explains why it exists and how it can be misused.

Authority plane

The versioned machine files saying which kinds, rules, relationships, and layouts are allowed. Why it matters: generated output cannot define its own success. Markdown and this x-ray are not members.

Compiler plane

The source resolver, contract loader, validators, kernel, edge resolver, and graph builder. Why it matters: it is the only valid bridge from authored source to derivation input. Current code needs a successor path rather than in-place v1 widening.

Proof plane

The independent catalogue, derived obligations, exact comparison, tests, bindings, evaluators, runs, mutations, receipts, and replay. Why it matters: it detects omitted work rather than trusting a green summary. Most of this plane remains to build.

Normalized graph

The compiler’s deterministic generated node/edge view. Why it matters: all derivation sees one canonical input. It is a read model, not authored authority, and it is different from the legacy Markdown-derived ConceptGraph.

Source manifest

The join from graph IDs to exact source paths and hashes. Why it matters: every proof result can be traced to authored bytes. A graph item without a source join is an error.

Independent catalogue

The expected obligation set, frozen outside the generator implementation. Why it matters: a bug cannot shrink both output and denominator. The engine reads it but cannot overwrite it.

Binding and evaluator

A binding uniquely selects the runtime target and fixture; the evaluator independently judges one bounded claim. Why it matters: a test must say what it runs and who judges it. First-match selection and universal-oracle claims are forbidden.

Mutation

A deliberately invalid input paired with one required obligation. Why it matters: it proves the check distinguishes invalid structure. Failure at an unrelated earlier layer does not kill the targeted mutant.

Receipt and replay

The receipt records the causal identity/digest chain; replay recomputes it from raw artifacts. Why it matters: stale or tampered evidence fails even when a stored field says pass. Neither one grants admission.

Exact-set proof

Compare all stable IDs, not only totals: O_spec = O_gen = T_gen = E_run = M_killed. Why it matters: equal counts can hide substitutions, duplicates, omissions, skips, and survivors.
