The Whole Idea

1. What We Want To Achieve

Poker Agent Arena is a competition harness where agents play progressively harder poker-like games through a constrained decision protocol. The arena should make strategic strength visible without letting protocol loopholes, hidden-information leaks, or slow responses masquerade as intelligence.

Picture a table with no speeches, no screenshots, and no hand-waving. Two agents receive the same kind of observation: public betting history, their private card, and the legal actions available right now. The clock starts. One bot folds too quickly. One tries to bet outside the rules. One waits too long. Another makes the boring legal call that keeps it alive for the next hand.

Over many hands, the noise starts to fall away. The table begins to show the difference between a wrapper that can talk about poker and an agent that can play inside a strict game.

The long-term shape is a ladder: small toy games first, board-reveal games next, then larger poker engines once the harness has earned trust. Each step adds more uncertainty, more state, and more room for adaptation.

The arena should feel like a fair table, a pressure test, and a measuring instrument at the same time.

2. What Counts As A Good Agent

Strategic Under Uncertainty

It builds a plan from incomplete observations instead of hoping the harness leaks the answer.

Fast Enough To Sit

It makes a playable decision inside the budget, while the hand is still alive.

Protocol Clean

It speaks the table's language exactly: one decision id, one legal action, one valid response.

Robust Over Many Hands

It survives variance, seat rotation, resets, and repeated evaluation orbits.

Adaptable

It notices styles, traps, and reveal patterns without touching forbidden information.

Auditable

Its wins can be replayed from transcripts instead of defended by vibes.

Competition Mechanics

3. The Core Loop

Every hand is a small contract between the referee and the agent. The referee deals the visible world; the agent chooses one move; the arena decides whether that move belongs at the table.

1

Observe

The agent sees public table state and only its permitted private view.

2

Commit

It sends one action before the decision clock expires.

3

Validate

The arena checks shape, id, legality, amount, and timing.

4

Resolve

The game applies the action or a deterministic fallback.

5

Remember

The hand becomes transcript, diagnostics, and redacted public replay.

5. Human Rules And Agent Rules

Before there is a leaderboard, there has to be a table contract. The arena needs two complementary rule files: one for people who want to understand the contest, and one for agents and implementers that need exact protocol boundaries.

Human rule view
  • What game is being played.
  • What information each player can know.
  • What counts as a violation.
  • How wins, losses, and diagnostics are reported.
  • What is excluded from the current league.
Agent rule view
  • Decision-envelope schema.
  • Action-envelope schema.
  • Deadline and timeout semantics.
  • Invalid-output taxonomy.
  • Transcript, replay, and redaction contract.

6. The Rule Of The Table

PrincipleOperational Meaning
No hidden-state leakageAgents see only public state plus their own private hand, never raw seed, deck order, opponent cards, or future board state.
One decision, one responseEach decision id expects exactly one JSON action envelope before the deadline.
Legal actions are authoritativeThe referee decides what can be played. The agent chooses from that set, or the table notices.
Failures are scored, not hiddenInvalid output, timeouts, crashes, and fallback events become part of the agent's record.

Scoring And Pressure

7. Winning Should Be Multi-Dimensional

Raw chip EV is necessary, but it is not enough. The best agent is not just the one that wins a noisy run; it is the one whose wins survive pressure, repetition, and inspection.

Score SurfaceMeasuresFailure Signal
Clean EVPerformance when valid decisions are madeThe strategy itself is losing.
Fallback-inclusive EVActual result after timeouts and invalid actionsProtocol failures are dragging the agent down.
Invalid rateSchema, id, legality, and amount errorsThe agent cannot reliably sit at the table.
Timeout rateLatency against the decision budgetThe strategy may be clever, but it is too slow for the league.
Replay determinismWhether a result reproduces from transcriptThe result is not auditable enough to share.

Game Ladder

9. Why Start With Toy Games

The first table should be small enough that mistakes are visible. Start with a room where every leak, late answer, and illegal move can be found. Then add cards, streets, opponents, and richer histories.

StageGame ShapeNew Capability Tested
Stage 0Kuhn hidden informationBasic private observation, legal actions, bluff/call/fold pressure, deterministic replay.
Stage 1Leduc-style board revealBelief updates as public information arrives after private cards.
Stage 2Configurable toy tournamentsSeat rotation, opponent mixes, longer orbits, comparative diagnostics.
Stage 3Engine-backed pokerLarger action spaces, bet sizing, richer histories, engine parity.
Stage 4Hosted leagueSubmission workflow, public leaderboards, versioned seasons, reproducible reports.

10. What The Arena Should Feel Like

For an agent author, the first experience should be direct: write a CLI-compatible agent, run it locally, watch it fail loudly if it breaks the rules, then improve it until the transcript and diagnostics become respectable.

The competitive pull comes from the table being strict enough to make competence visible. A clean win should feel earned: the agent read the hand it was allowed to see, made a timely decision, accepted the risk, and left evidence another person can inspect without trusting the bot author.

Arena protocol Decision envelope, action envelope, legal-action masks, invalid-event taxonomy, deadline and fallback policy.
L2
Game fixtures Kuhn first; Leduc board reveal and larger engines later.
L1
Agent process Any CLI-driven agent wrapper that can read one decision envelope and emit one action envelope.
L0
Contracts Human rules, agent rules, versioned spec files, output layout, and hard acceptance gates.

The load-bearing separation is simple: the game referee decides legal state; the arena owns process protocol, observation filtering, deadlines, fallback, transcript, replay, and diagnostics. One side deals the hand. The other keeps the room honest.

12. What The MVP Is Actually Testing

Local Arena CLI v0 is deliberately narrow. Its job is not to deliver the final league. Its job is to prove that the arena can enforce the mechanics that make the larger idea credible: legal moves, hidden information, timed action, fallback, replay, and diagnostics.

MVP TestPass Means
CLI agent protocolAgents can connect as local processes through a stable decision/action contract.
Hidden-information boundaryKuhn observations expose only allowed state, and canary scans catch forbidden leakage.
Deadline enforcementLate output is ignored for gameplay and counted in diagnostics.
Invalid-output handlingMalformed, illegal, or mismatched actions trigger deterministic fallback.
Transcript and replayThe match reproduces from private transcript and exports a redacted public replay.
DiagnosticsClean EV, fallback-inclusive EV, invalid rate, timeout rate, fallback count, and replay determinism are reported.

Safety And Honesty

14. Hidden Information Is The Product Boundary

A poker table has secrets by design. A live agent must never observe opponent private cards, deck order, raw seed, future state, referee traces, or reversible hidden-state hashes. The arena should test this not just in decision envelopes, but in transcripts, logs, public replay, stdout/stderr capture, diagnostics, and retained inputs.

Private Transcript

Authority for replay and diagnostics; may contain referee-only material.

Public Replay

Redacted narrative/export; uses opaque seed handles and no raw seed material.

Canary Scan

Checks observations, action history, state hashes, logs, replay exports, and retained inputs.

15. Why Fallback Must Be Boring

Fallback exists to keep evaluation moving when an agent fails the protocol. It should be deterministic, legal, and competitively dull. A fallback that improves rank teaches agents to break the harness instead of play the game.

Bad BehaviorExpected Treatment
Malformed JSON or prose before JSONInvalid event, deterministic fallback, diagnostic count.
Mismatched decision idInvalid event, ignored action, deterministic fallback.
Late outputTimeout event; late action ignored for gameplay.
Crash or EOFNamed diagnostic event, deterministic fallback or match-level report.

17. The First Proof To Ask For

The useful next proof is not a polished leaderboard. It is a local command sequence that proves the table is real:

doctor reports environment, protocol, and fixture availability.

eval runs bundled sample agents through the Kuhn hidden-information fixture.

replay reproduces payouts, fallback events, invalid/timeout diagnostics, and emits a redacted public replay.

If that proof passes, the arena has earned the right to get more interesting. Until then, the small table is doing its job: making every agent show what it can actually play.
