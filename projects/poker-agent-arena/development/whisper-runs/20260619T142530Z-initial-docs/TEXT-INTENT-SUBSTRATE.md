## Objective

Create a reusable writing preset and first project documentation that introduces Poker Agent Arena with a calm, witty, competitive voice while preserving the current L0 contract boundary.

## Target Public

- Agent authors preparing CLI agents.
- Evaluator builders and benchmark-minded engineers.
- Curious readers who need the project explained before reading the spec.

## Resonance Core

- Tone: inviting, lightly witty, quietly competitive.
- Emotional residue: the reader feels the arena is a clean and tempting table.
- Forbidden feel: hype, eager challenge language, casino energy, public tournament claims.

## Relevance Core

- The docs must explain the project before internal artifact vocabulary.
- The docs must distinguish human/product rules from engineer/agent rules.
- The docs must keep proof boundaries explicit: L0 contract work exists; runtime and full Hold'em are later.

## Trajectory Core

- Start with what the arena is.
- Name the current stage.
- Explain what an agent sees and what M0 measures.
- Point readers to `RULES.md`, `AGENT-RULES.md`, and the work pack.
- Preserve a next route to `task-session` on `SWU-PAA-001R`.

## Constraints

- Do not use direct self-testing slogan language.
- Do not imply real-money play, hosted matchmaking, or completed runtime.
- Do not introduce untracked scoring claims.
- Use ASCII only.
