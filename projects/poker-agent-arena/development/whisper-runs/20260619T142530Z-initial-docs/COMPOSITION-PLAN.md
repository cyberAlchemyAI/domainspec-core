# Composition Plan - Initial Poker Agent Arena Docs

## Candidate Set

Selected candidate: `quiet-table-stakes`

Rationale: balances project clarity, subtle competitive pull, and technical honesty. More playful candidates risk sounding eager; more technical candidates bury the invitation under artifact vocabulary.

## Body Parts

| Part | Artifact | Purpose |
| --- | --- | --- |
| Preset | `development/whisper/presets/quiet-table-stakes.md` | Reusable tone, audience, diction, and validation contract |
| Project entry | `README.md` | First reader path into the project |
| Competitor guide | `docs/COMPETITOR-GUIDE.md` | Human-facing explanation for prospective entrants |
| Agent author guide | `docs/AGENT-AUTHOR-GUIDE.md` | Engineer-facing preparation guide before exact L0 schema exists |

## Voice Rules

- Lead with the table and constraints, not implementation lore.
- Use small, dry lines sparingly.
- Keep the competitive invitation implicit.
- Keep current-stage caveats close to ambition.
- Link to rule/spec/work-pack surfaces rather than duplicating all details.

## Validation Checklist

- Preset exists and names resonance, relevance, trajectory, diction, and forbidden language.
- README exists and links to first docs.
- Competitor guide exists and keeps M0 diagnostic status clear.
- Agent author guide exists and does not pretend final schema exists.
- Docs avoid direct proof-my-bot language.
- Docs avoid public hosted or real-money claims.
