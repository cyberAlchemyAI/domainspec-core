Date authored: 2026-06-08 · Source precedent: GoldenQuill client-sendable package (read-only).

## What this template is

A layered client package a CyberAlchemy consultant fills in per engagement. It is **vertical-agnostic**:
the core sections are written once; each vertical (cap factory, logistics) gets a clearly-marked
instantiation block. Where a section needs a real client number, it carries a labeled
`[PLACEHOLDER — fill from <source>]` slot — **do not fabricate client data.**

## Reading order (BI-led — the positioning decision)

The package leads with the **evidence-linked BI layer** (the fastest, most measurable value), then
shows ontology cards, the classification register, the promotion DAG, and agent governance as **what
makes that BI trustworthy and self-improving**. Source: `decisions/pilot-and-positioning.md`
(Decision 2 — *Combined, BI as the lever*).

1. `overview.md` — one-page framing of the offer (BI first).
2. `executive_brief.md` — the four installed layers, BI-led, with the honesty posture.
3. `reference_appendix.md` — KPI/ontology taxonomy (the evidence-linked metric model + node/edge vocabulary).
4. `client_decisions.md` — the owner decisions that become the implementation spec, each with a cost/consequence.

## Gap-closing sections (the five inherited GoldenQuill gaps)

These were missing from the GoldenQuill package and are required here:

1. `gaps/meta-metrics.md` — does the governance layer itself work?
2. `gaps/buyer-readiness.md` — is the buyer ready, and how do they tell?
3. `gaps/consequence-cost.md` — what each owner decision costs / risks.
4. `gaps/transition-plan.md` — explicit current→target plan.
5. `gaps/failure-modes.md` — how this can fail, in buyer language.

## Per-vertical instantiation stubs

- `verticals/cap-factory.md` — continuous-production seed (labeled placeholders only).
- `verticals/logistics.md` — discrete-shipment seed (labeled placeholders only).

## Honesty gate (G-honesty)

Every capability claim in this package is tagged `[proven]` or `[hypothesis]` (`/ interpretive` is a
qualifier on `[hypothesis]`, never a third class). A claim-tag audit is at the bottom of
`executive_brief.md`. The anti-collapse "concept erasure vs number hallucination" framing is an
**interpretive principle**, not a proof — stated as such wherever it appears.

> **Consultant note (internal, not client-facing):** the proven-basis for each `[proven]` tag traces to
> the GoldenQuill reference build indexed in `projects/ontologize/levels/L0-corpus.md`. Client-sendable
> files state "demonstrated in the GoldenQuill reference build" without internal repo paths.

## Scope note

This package stays focused on business value, governance, evidence, metrics, decisions, and risk. It
contains no pricing, no contract terms, and no signed-client commitments.
