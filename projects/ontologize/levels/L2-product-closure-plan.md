# L2 — Product Closure Plan

How the L1 patterns close into a sellable CyberAlchemy consulting product. This is the bridge
from "patterns extracted" to "offer a client can buy." All items are **candidate** until owner review.

## Closure thesis

CyberAlchemy's first product is a **consulting engagement that installs an ontology + DAG layer
over a company's existing data and agents**, turning scattered runs and dashboards into a governed
learning loop with auditable business intelligence. GoldenQuill is the reference implementation /
proof.

## Pattern → offer component

| Pattern                    | Becomes this engagement component                             | Deliverable                       |
| -------------------------- | ------------------------------------------------------------- | --------------------------------- |
| P1 two-axis ontology       | **Ontology mapping** of the client's subject × mechanism axes | segment & mechanism card set      |
| P2 classification register | **Data governance register** install                          | signed field→class register       |
| P3 promotion DAG           | **Governed learning loop** design                             | promotion DAG + gate ruleset      |
| P4 evidence-linked BI      | **BI re-architecture** (traceable KPIs)                       | KPI taxonomy + receipt pattern    |
| P5 routing + gates         | **Agent governance** design                                   | routing map + deterministic gates |
| P6 autonomy discipline     | **Agent maturity assessment**                                 | Four-Rules scorecard              |
| P7 packaging               | **The deliverable itself**                                    | client-sendable package           |

## Engagement arc (candidate)

1. **Discovery / assessment** — map the client's two ontology axes; inventory data sources and
   existing agents; score agent maturity (P6).
2. **Design** — propose the ontology, classification register, promotion DAG, and KPI taxonomy
   (P1–P4); identify owner decisions (who approves reuse, what stays private, review cadence).
3. **Pilot** — install a thin slice (one segment × one mechanism, one learning loop), prove
   evidence-linked metrics on real data.
4. **Handoff** — deliver the package (P7) + a current→target transition plan; train owners on the
   governance gates.

## Closure gates (must hold before the offer is "ready")

- **G1 Source honesty** — every capability claim ties to a GoldenQuill pattern (proven) or carries
  a validation step (hypothesis). No "already built" claims.
- **G2 Generality** — each component is stated company-agnostically, not in grant vocabulary.
- **G3 Governance** — the offer names who owns promotion decisions and what stays private.
- **G4 Honest gaps** — the client-package gaps Lane 5 found (meta-metrics, buyer readiness,
  consequence/cost statements, transition plan, failure modes) are addressed or listed as backlog.
- **G5 Promotion guardrail** — no pricing, contracts, or named clients committed here.

## Open product decisions (carry to NEXT)

- Positioning: BI-led vs agent-governance-led vs combined (recommend combined, BI as the lever).
- Target buyer: ops/data leader vs agent/AI lead vs executive sponsor.
- Pilot scope default and what "proof" means for a non-grant client.
