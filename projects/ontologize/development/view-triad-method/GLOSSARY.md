# Glossary - Ontologize View-Triad Method

Local glossary for this development pack. No term here is promoted to canonical Arcanum or Ontologize vocabulary by this artifact.

| Term | Meaning |
| --- | --- |
| View triad | The coordinated `system-view`, `engineer-view`, and `ontology-view` artifact set. |
| System-view | Stakeholder-altitude shape artifact. It names live stances and points to engineer-view rows, but decides no verdict and defines no term. |
| Engineer-view | Mechanics and verdict artifact. It owns exactly one decision row per named stance, with status and verified authority. |
| Ontology-view | Typed node/edge artifact. It owns term meaning, edge legality, forbidden relationships, guards, and ontology graph projection. |
| Stance | A load-bearing shape choice named by the system-view whose alternative would change mechanics or stakeholder judgment. |
| Decision row | A row in engineer-view that gives one stance its single verdict, status, and authority. |
| Authority strike | Downgrade of a RESOLVED engineer-view row when the cited authority cannot be verified on disk. |
| Provisional stance | A system-view stance whose owning engineer-view row is not authored yet; it must carry a blocker OQ instead of an inline verdict. |
| Forbidden-edge discipline | Ontology-view rule that forbidden relationships become unconstructible by endpoint typing or blocked by named guards. |
| View-triad method | Ontologize method that turns source corpus into the view triad, then integrates the triad into client/package/BI deliverables. |
| BI-expression layer | Existing Ontologize optimization-chain layer that turns evidence-linked metrics and analysis methods into bounded BI claims. |
| No double decision | A cross-artifact invariant: shape in system-view, verdict in engineer-view, meaning in ontology-view, BI claim in optimization chain. |
| Branch materialization | The method-local rule that B1 meaning, B2 system, B3 run-context, and B4 bridge must appear through the three existing view authorities. |
| Branch Materialization Register | Run evidence table that maps each branch selector to system-view shape, engineer-view decision/mechanic, ontology-view typing, status, owner, and residue. |
| Branch coverage profile | Citation-backed coverage layer inside the existing triad; it is not a canonical branch definition source and not a fourth view. |
| B3 run-context record | Required record for run boundary, denominator, lifecycle state, scope/posture, stage-vs-outcome check, source events, and open run-boundary decisions. |
| B4 bridge ledger | Required ledger for cross-branch edge, source branch, target branch, evidence, drift/contradiction status, owner-decision route, catalog status, and residue. |
| Raw drift | Neutral observed divergence between behavior and intended meaning; it preserves both sides and does not decide a conflict. |
| Adjudicated contradiction | Governance conflict that blocks promotion until an owner decision resolves it. |
