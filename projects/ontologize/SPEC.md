# SPEC — CyberAlchemy ontology+DAG engagement

Define-mode synthesis. Consolidates the research baseline ([PRODUCT.md](PRODUCT.md),
[L1-pattern-map.md](levels/L1-pattern-map.md), [DEFINITIONS.md](DEFINITIONS.md)) and the resolved
[decisions](decisions/pilot-and-positioning.md) into a single spec the design/plan modes build on.

## Intent

Build the authoring + delivery baseline for CyberAlchemy's first product: a consulting engagement
that installs an ontology + DAG layer over a company's existing data and agents, proven by two
parallel pilots (cap factory + logistics company), led by evidence-linked BI.

## In scope

- A repeatable **assessment instrument** (intake → ontology map + data/agent inventory + maturity score).
- A vertical-agnostic **deliverable template** (client-sendable package), BI-led.
- A repeatable **four-layer install method** (ontology / classification register / promotion DAG /
  evidence-linked BI + governed agents).
- A repeatable **optimization-chain method** that expresses run nodes, evidence-linked KPIs,
  analysis methods, and named BI optimizations as plain-language and schema-backed contracts.
- **Per-vertical instantiations** for cap factory and logistics.
- A **proof harness** measuring one evidence-linked metric movement per vertical.

## Out of scope (guardrails)

- No pricing, contracts, or signed-client commitments.
- No promotion of terms/brand to canonical Arcanum vocabulary.
- No modification of the GoldenQuill project (read-only precedent).

## Requirements

- R-A Assessment is repeatable and vertical-agnostic; outputs the two ontology axes, a data-source
  inventory, an agent inventory, and a Four-Autonomy-Rules maturity score.
- R-B Deliverable leads with evidence-linked BI; closes the five inherited GoldenQuill gaps
  (meta-metrics, buyer readiness, consequence/cost per decision, current→target transition, failure modes).
- R-C Method install is staged: each layer produces standalone value before the next.
- R-D Honesty is enforced at two altitudes: **document-level** capability claims are tagged
  proven/hypothesis in prose (G-honesty-doc); **DAG nodes** (N3 MetricObservation / N4 PromotionCandidate
  / N6 KnowledgeProjection) carry formal `veracidade` + `evidence_refs`, checked deterministically by the
  L0 validator (G-honesty-node). Honesty gate from [L2](levels/L2-product-closure-plan.md) G1.
- R-E Proof is measured independently per vertical, then compared to evidence generalization (R1).
- R-F Privacy/governance: a signed classification register gates data movement before any agent runs.
- R-G Optimization chains connect operational actions to KPI movement using a named method, claim
  label, interpretation limits, contradiction path, and owner-decision route. See
  [OPTIMIZATION-CHAIN-METHOD.md](OPTIMIZATION-CHAIN-METHOD.md).

## Success criteria

- Both pilots produce a filled assessment, an instantiated method, and one moved evidence-linked metric.
- Each pilot produces at least one valid optimization-chain definition for its proof metric.
- The deliverable template is reused across both verticals with only per-vertical instantiation changing.
- Cross-vertical comparison yields an explicit verdict on the generalization hypothesis.
