DomainSpec Core

A history of learning through correction

How it got here

DomainSpec Core began by holding too much. In April 2026, the parent workspace contained both the map and copies of the implementation it was meant to coordinate. One week later, the copies were removed and the owner repositories remained: the filesystem learned the boundary the architecture had only described.

The system grew through correction, not a clean version march. Concrete project work fed back into DomainSpec; failures produced named controls; Arcanum separated reusable method from private intent; formalization narrowed claims that outran their assumptions; and the later v2 work made authority and inheritance explicit.

What it does

It keeps intent, execution, evidence, and authority traceable without letting any artifact claim more than it proves.

GROUND

Let real project work expose what the framework missed

SEPARATE

Remove mirrors and give each responsibility one owner

OBSERVE

Retain receipts, failures, drift, and residue as evidence

GOVERN

Route changes through owners; no artifact promotes itself

What is being built now

Four owners remain distinct. DomainSpec owns private typed intent. Arcanum owns the public, reusable methods used to perform bounded work. CyberAlchemy v2 owns the private authority spine: vocabulary, source routing, owner routes, and promotion gates. Saturn names the private convergence architecture intended to compare intent with reality and return pressure for correction.

That separation is the point: what is intended, how work is done, who may change owned truth, and how evidence returns are different responsibilities.

The repository contains committed mechanisms, bounded executions, and local witnesses. It does not yet prove one integrated three-pillar runtime, public shipment beyond Arcanum, deployment, adoption, production readiness, or a closed Saturn loop. The durable rule is simple: preserve the failure, narrow the claim, and let proof set the ceiling.
