# Intent Record

## Approved intent

Create an Invoke development package that defines, designs, and plans the
Orchestrate update needed to detect and manage agent-thread capacity before a
Task Session or governed dispatch starts spawning a wave.

## User outcome

An agent or one-interface consumer should receive an honest pre-spawn result:

- the whole requested wave is admitted from current evidence;
- the wave is blocked because evidence is missing, stale, or insufficient; or
- the user is offered explicit topology or session alternatives that require a
  new route decision when they materially change the approved strategy.

The system must not first discover a predictable capacity problem by leaving a
partially spawned wave behind.

## Decisions carried from the conversation

- Author Define, Design, and Plan now; do not implement runtime code.
- Keep receipt/audit work subordinate to agent experience, except where an
  honest blocked result cannot otherwise be represented.
- Preserve one interface and multiple thread/run concepts without creating a
  second scheduler, session store, execution owner, or capacity authority.
- Treat the prior refresh requirement as a symptom to explain and manage, not
  as proof of undocumented host internals.

## Discovery basis

- The failed 2026-08-03 run is the direct incident source.
- The accepted Augmentor routing and subagent blueprints supply consumer and
  degraded-mode constraints, not implementation authority.
- Current canonical Orchestrate source defines the actual implementation seam.

## Authoring authorization

The user's request to use Invoke and create this package is the lifecycle-owner
approval for private authoring. It is not approval to mutate public Arcanum,
generated mirrors, host runtime behavior, or product consumers.
