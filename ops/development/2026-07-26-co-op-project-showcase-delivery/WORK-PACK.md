# Work Pack — Co-Op Project Showcase Page

Status: selected for the active native Goal

## Objective

Finish one browser-native page that is simultaneously:

- the live presentation for the existing Co-Op Engine meeting;
- a self-guided explanation of fourteen projects;
- a truthful recruitment surface for technical builders and domain
  practitioners such as writers and musicians who want to work with AI and
  build their own things.

## Selected unit

`SWU-COOP-SHOWCASE-001` is the only selected unit.

Primary behavior: help a visitor understand the portfolio, choose a project
worth opening, inspect what exists and what does not, and formulate a
non-binding human contribution offer; let a facilitator present the same
records without a separate deck.

## Source authority

1. Direct user requirements and the active native Goal.
2. Accepted `findings.md` and `PARENT-VALIDATION.md` from the corrected
   showcase/recruitment research.
3. This work pack, strict context pack, and Whisper result.
4. The older Exchange work-pack only as negative and historical evidence.

## Write scope

- `projects/co-op-engine/index.html`
- `ops/development/2026-07-26-co-op-project-showcase-delivery/**`
- `output/playwright/ux-validator/co-op-showcase-20260726/**`

No other project, Arcanum source, DomainSpec implementation, ledger,
publication, hosting, or deployment path is in scope.

## Done criteria

1. One dependency-free local HTML file contains all CSS, content, and
   interaction code.
2. The opening says the Co-Op Engine is the existing 45-minute weekly meeting,
   not an autonomous matcher or a new workflow product.
3. The page offers both decision-lens-first and complete project-map entry.
4. All fourteen projects have a memorable opening and expandable detail with:
   vision, what exists, honest limit, next experiment, and possible
   contribution.
5. Whisper’s writer-studio vision includes character, place, encounter,
   timeline, and connection exploration while keeping current proof distinct.
6. Presentation mode uses the same DOM records and supports previous, next,
   exit, keyboard navigation, and progress.
7. Functional meta-narration states what the current page region is helping
   the visitor do.
8. Recruitment language remains non-binding and tells visitors to confirm
   welcome and scope with a human project owner.
9. Technical terms are bridged or replaced with plain language. The copy
   remains useful to technical builders and domain experts.
10. Responsive desktop and mobile layouts preserve content with no horizontal
    overflow.
11. Keyboard focus is visible; skip navigation, landmarks, heading order,
    reduced motion, and accessible disclosure controls are present.
12. Black-box browser evidence proves fourteen unique projects, filtering,
    details, presentation transitions, meta-cue updates, responsive
    preservation, clean console, and no external network requests.
13. A separate copy audit covers conversational-AI terms, speaker/action
    clarity, claim ceilings, ease of understanding, coherence, and
    meta-narration.
14. Desktop and mobile screenshots are captured and visually inspected.

## Constraints and boundaries

- No external resources, remote fonts, analytics, tracking, forms, or browser
  storage.
- No autonomous matching, inferred welcome, public job opening, verified
  recruitment, privacy-safe, efficacy, shipped-product, or public-release
  claim.
- No presenter-only project truth.
- Project welcome is `confirm with owner` unless an owner-backed open ask is
  later admitted.
- Browser evidence does not prove comprehension, delight, or recruitment
  outcome.
- The page is local and reviewable. Publication and deployment require a
  separate owner/public-boundary decision.

## Validation surface

- static source and copy assertions;
- Playwright CLI desktop and mobile snapshots and interactions;
- DOM probes for record count, unique IDs, disclosure fields, filtering,
  presentation state, overflow, landmarks, and external resources;
- console and request review;
- desktop and mobile screenshots;
- `git diff --check` over the declared scope.

## Blocked stop condition

Stop before claiming completion if any project is missing, a source-bounded
claim cannot be preserved, presentation requires a second truth source, the
browser cannot execute the required flows, external requests appear,
responsive overflow remains after three evidence-backed corrections, or the
implementation would require publication or private-project disclosure beyond
the accepted substrate.
