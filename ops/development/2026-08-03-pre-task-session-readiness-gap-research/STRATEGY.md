# Pre-Task-Session Readiness Gap Research Strategy

## Preliminary answer

No Task Session actually ran. `task-session-until-blocker` caught the missing
material and closeout contracts in its outer preflight, before the first Task
Session and before product mutation. The user-facing failure happened earlier:
the August 3 Invoke Plan output described the work pack as executable in shape
and recommended Task Session even though its own canonical Plan contract
requires the exact fields that were absent.

Existing audited research had already proposed the right architectural
direction: produce and validate an authority-neutral Work Pack Readiness Audit
admission projection before Task Session. This dispatch therefore investigates
why that accepted direction was not consumed by the Augmentor Refine route and
specifies the smallest integration that prevents recurrence.

## P1 trigger

This is a governed `research` dispatch.

- **Synthesis:** the answer must reconcile the current Augmentor incident,
  canonical Invoke/Task Session contracts, prior accepted research, readiness
  maintenance, WPRA v2 implementation, Refine routing, and generated runtimes.
- **Context protection:** the exact clause, schema, fixture, runtime, and
  observability trace is larger than the parent should carry directly.
- **Isolation:** a causal explanation and change map must survive independent
  precedent, non-vacuity, and definitional attacks.
- **Parallelism:** incident forensics, adoption archaeology, and formal contract
  design can proceed independently.

## Dependency flow

```text
explorers (parallel)
  -> synthesizer
     -> explorers feedback (missing exact evidence only, cap 1)
     <-> skeptics (zig-zag, cap 1)
        -> evidence closure
           -> writer
              -> auditor
                 -> writer revision (cap 1)
                    -> parent final approval
```

All initial dependencies are sequential or zig-zag. Feedback edges are repair
routes only and do not make a downstream stage initially ready.

## Evidence and scope contract

The dispatch uses `exact-binding`. Every load-bearing claim must carry an exact
source path plus heading, JSON Pointer, schema property, fixture id, or stable
line selector; an explorer-return reference; evidence scope; and observed,
executed, or unverified status.

The research is local and read-only except for its own `research.md`,
`findings.md`, normalized receipts, and closeout artifacts. It may recommend a
later Spellcraft, Invoke, Refine, or Task Session maintenance route, but it may
not edit Arcanum, DomainSpec, Augmentor product files, work packs, authority,
telemetry, Git, or external systems.

host rejected `spawn-0003` with `agent thread limit reached`. Orchestrate does
not permit an implicit retry, and the all-explorer gate requires all three
receipts, so the reducer blocked the route before synthesis. See `RESULT.md`,

tension evidence, explicit confirmation, registration, and closeout; this
closed dispatch supplies no standing approval for that route.
