# Craft Consultation API Contract

Status: repaired candidate design, not implemented. Version prefix: `/v1`. The
service is private, read-only at its HTTP surface, and subordinate to Craft
source-ledger authority.

## Common response contract

Every successful data response binds to one immutable snapshot:

```json
{
  "api_version": "craft-consultation.v1",
  "authority": "derived",
  "snapshot_id": "sha256:<manifest-record-byte-digest>",
  "imported_at": "<RFC3339>",
  "freshness": "fresh|stale|unknown",
  "data": {}
}
```

L0 defaults freshness to `unknown`. `fresh` or `stale` is permitted only when a
valid freshness observation defined in `DATA-MODEL.md` exists. Import age alone
never yields `fresh`, and no request triggers source comparison.

## L0 routes and actions

| Method and route | Required action | Result |
| --- | --- | --- |
| `GET /healthz` | none | Process liveness only: `{"status":"ok"}`. No snapshot details. |
| `GET /v1/status` | `craft:status:read` | Readiness, snapshot ID, import time, freshness, and API features. |
| `GET /v1/spaces` | `craft:space:list` | Authorization-filtered base metadata. |
| `GET /v1/spaces/{space_id}` | `craft:space:read` on the opaque space resource | Base metadata and capabilities. |
| `GET /v1/spaces/{space_id}/raw` | `craft:raw:read` on the opaque space resource | Exact verified UTF-8 YAML bytes and provenance headers. |

No POST, PUT, PATCH, DELETE, refresh, rebuild, or write route exists.
Unsupported methods return `405` with the exact `Allow` header.

## Space identity

`space_id` is opaque and snapshot-local. It is generated by:

```text
material = UTF8("craft-space-id/v1\0")
           || raw_32_bytes(snapshot_manifest_sha256)
           || 0x00
           || exact_UTF8_bytes(source_path_as_stored_in_manifest)
space_id = base64url_no_padding(first_24_bytes(HMAC-SHA-256(space_id_key, material)))
```

The snapshot builder must validate each manifest path as NFC UTF-8, `/`
separated, repository-relative, with no empty, `.` or `..` segment, and preserve
those exact validated bytes. `space_id_key` is a secret configuration value,
never returned or logged. Key rotation changes every ID and invalidates all
cursors. A collision makes the full snapshot unavailable. IDs are not Craft row
IDs or stable cross-snapshot project identities. Deterministic vectors are
required before implementation admission.

## Metadata authorization tiers

Base space metadata contains only `space_id`, `authority`, freshness, schema
class, and capability flags permitted by `craft:space:list` or
`craft:space:read`. `source_path` requires `craft:path:read`.
`source_sha256`, exact `size_bytes`, and raw provenance headers require
`craft:provenance:read` or `craft:raw:read`; they are never list-only fields.

## Collection and pagination

Space ordering is lexicographic by `space_id`. The service filters unauthorized
spaces before count, sort, or page. It returns only `items`, `returned_count`,
and `next_cursor`; no pre-authorization total is exposed.

The canonical authorization-view input is canonical JSON with sorted keys and
arrays containing: principal/session binding, policy revision, action,
snapshot ID, and the ordered visible opaque resource IDs. Its SHA-256 digest is
bound into a short-lived, authenticated cursor. The cursor body is canonical
JSON and the token is `base64url(body).base64url(HMAC-SHA-256(cursor_key,
body))`. It contains:

- `kind=spaces`, snapshot ID, authorization-view digest;
- last emitted `space_id`, effective limit, cursor format version;
- issue time and expiry.

`limit` defaults to 50 and is constrained to 1..100. A changed snapshot,
principal/session, policy revision, visible set, limit, or expired/tampered token
returns `409 cursor_invalidated` without explaining which binding changed.

## Raw response and snapshot pinning

`GET /v1/spaces/{space_id}/raw` returns
`application/yaml; charset=utf-8`, `Cache-Control: private, no-store`, and:

- `ETag: "sha256:<verified-source-byte-digest>"`;
- `X-Craft-Authority: derived`;
- `X-Craft-Snapshot-Id: sha256:<manifest-record-byte-digest>`;
- `X-Craft-Freshness: fresh|stale|unknown`;
- verified `Content-Length`.

`If-None-Match` is cache revalidation only and may return `304`; it never creates
a snapshot precondition. `X-Craft-Snapshot-Match` is the snapshot precondition:
an exact mismatch returns `412 snapshot_precondition_failed` with the active
snapshot ID only when the caller is already authorized for the target. `200` and
`304` carry the snapshot and authority headers. Range requests are not admitted.

## Conditional L1 row routes

Rows are advertised only after a version-specific adapter passes schema,
unique-identity, reference, and fixture validation.

| Method and route | Required action | Semantics |
| --- | --- | --- |
| `GET /v1/spaces/{space_id}/rows?family=<family>&limit=<n>&cursor=<token>` | `craft:rows:list` on space/family | One validated family in canonical row-key order. |
| `GET /v1/spaces/{space_id}/rows/{family}/{row_key}` | `craft:row:read` on space/family/row | One exact row envelope. |

Row authorization occurs before family existence, capability, schema, parsing,
lookup, count, or page observations. A denial uses the same concealed response as
an absent space/row. `row_key` is the family ID field; recomposition uses a
length-prefixed `(child_id,parent_id)` key.

A row cursor is separately typed and authenticated. It binds `kind=rows`,
snapshot ID, space ID, family, authorization-view digest, last canonical row
key, effective limit, adapter/index version, format version, issue time, and
expiry. It cannot be replayed across family, space, policy, snapshot, limit, or
adapter changes.

## Error precedence and disclosure

The fixed decision order is:

1. parse only route shape and transport-safe scalar bounds; malformed shapes
   return `400` without resource lookup;
2. authenticate, else `401`;
3. resolve the opaque space and authorize the route action; absent or denied is
   concealed as `404 space_not_found`;
4. for row routes, authorize the family/row resource; absent or denied is
   concealed as `404 row_not_found`;
5. evaluate capability/schema; unavailable rows return
   `409 capability_unavailable`;
6. validate cursor and snapshot precondition;
7. perform exact lookup.

Duplicate row identity disables rows for the whole space. The caller sees only
`409 capability_unavailable`; `ambiguous_row_identity` remains internal.
Unsupported/missing schemas use the same 409 behavior in v1; `422` is not used.

Errors use `application/problem+json` with `type`, `title`, `status`, `code`, and
`request_id` and never expose content, private paths, WaveDB keys, stack traces,
policy details, or which concealed check failed.

| Status | Code | Meaning |
| --- | --- | --- |
| 400 | `invalid_request` | Transport-safe route, scalar, or token shape is malformed. |
| 401 | `authentication_required` | Principal missing or invalid. |
| 404 | `space_not_found` | Space absent or concealed. |
| 404 | `row_not_found` | Authorized route has no visible exact row. |
| 409 | `cursor_invalidated` | Any protected cursor binding differs. |
| 409 | `capability_unavailable` | Validated rows are unavailable, including duplicates or unsupported schemas. |
| 412 | `snapshot_precondition_failed` | Explicit snapshot pin does not match. |
| 503 | `snapshot_unavailable` | Snapshot failed startup or runtime integrity checks or a resource ceiling. |

## Mandatory resource ceilings

All ceilings are immutable configuration for a running process, reported only
through private operations, and enforced before allocation where possible.
Candidate L0 defaults (subject to executable boundary tests) are: manifest
1 MiB; 256 entries; 16 MiB per raw record; 256 MiB aggregate verified bytes;
30 seconds startup validation; 8 concurrent raw responses; zero request-body
bytes on GET/HEAD. YAML parsing is L1-only and bounded to 16 MiB, depth 64,
1,000,000 nodes, no aliases, no executable/custom tags, and a 5 second parse
budget. A limit breach fails the whole affected snapshot/capability closed; it
does not truncate a response or partially serve data.

## Cache policy

All authenticated responses use `Cache-Control: private, no-store` and
`Vary: Authorization`. ETags support caller-side revalidation only; shared-cache
authorization reuse is forbidden.

## Contract ceiling

This is a repaired design contract. OpenAPI, schemas, server code, policy
bindings, fixtures, and executable tests do not yet exist.
