## Killed Duplicates And Mechanisms

- raw `supported_by`, generic `derived_from`, stored inverses, generic
  `is_part_of`, self-authored lifecycle/authority state, and automated
  truth/publication/promotion;
- a separate Phase-0 `EvidenceAssertion`;
- a prose-only central contract catalogue;
- content-bearing capability profiles;
- importing PROV-O, Web Annotation JSON-LD, RDF, DataCite, PREMIS, or Olog as a
  Phase-0 runtime substrate.

## Producer-Consumer Dependency Map

```text
Phase 0
Contributor
  ├─ SourceRecord ─┐
  └─ ClaimRecord ──┴→ Shape Validator
                         → Cross-Record Validator
                         → ValidationFact
                              → Inventory Projector
                              → ProjectionReceipt + Generated Inventory
                                   → Parity Checker
                                   → Selector Engine
                                   → bounded attributed result

Phase 1 candidate
TaskSnapshot + BasePolicyPacket + last trusted RegenerationReceipt
  → ContextPacket
  → ContentCandidate
  → P0 validators + PR ValidationReport + ReviewFindings
  → typed OwnerDecision(s)
  → observed MergeReceipt
  → trusted RegenerationReceipt
  → fresh ContextPackets

Later
selected authored claims + exact selectors
  → Phase-2 evidence/assessment surfaces
  → typed owner decision
  → Phase-3 ontology candidate
  → separate ontology-admission decision
  → promoted meaning under one scheme/policy
```

Every arrow carries exact IDs, versions and/or digests. No generated or report
surface writes authority upstream.

## Lifecycle And Authority Non-Collapse

| Surface | Establishes | Does not establish |
|---|---|---|
| authored fact | contributor recorded value in one record | external truth |
| source description | contributor’s identity/metadata statement about a resource | the resource itself, evidential support, reuse permission |
| claim | contributor-attributed proposition | source wording, accepted interpretation, truth |
| evidence selector/value | exact located segment plus contributor’s relation/interpretation | proof that the segment supports the claim |
| validation fact | predicate result over exact bytes and versions | assessment, approval, permission |
| Inventory projection/query | deterministic attributed read model/result | new identity, confidence, meaning, acceptance |
| assessment/review finding | assessor’s scoped judgment on a named basis | conformance, owner authorization, universal truth |
| owner decision | exact effect of one bound decision kind | all downstream effects |
| merge receipt | observed repository action | publication or semantic correctness |
| publication effect | publish/unpublish effect of a publication decision | truth, rights permission, ontology admission |
| ontology candidate | proposed semantic object grounded in authored records | canonical concept or promoted meaning |
| promoted meaning | exact effect of ontology admission under one scheme/policy | truth, permission, publication, general production authorization |

There is no automatic lifecycle conveyor.

## Version, Compatibility, Deprecation, And Migration Candidate

1. Every artifact declares its own version namespace: record schema, predicate
   profile, selector profile, generator, projection, receipt, packet, policy
   and candidate envelope.
2. Before parsing or projection, a registry resolves the complete supported
   tuple. Unknown, unsupported, or internally mixed tuples fail with candidate
   diagnostic `UNSUPPORTED_CONTRACT_TUPLE`; processors do not partially
   reinterpret input.
3. Phase 0 makes no predecessor compatibility promise. Reader compatibility,
   writer compatibility, identity preservation, selector preservation and
   projection parity are separate declarations.
4. Canonical-byte policy must bind UTF-8, newline handling, duplicate-key
   rejection, serialization profile, digest algorithm and receipt byte format
   before byte-identical output becomes interoperable. RFC 8785 is not selected
   implicitly.
5. No version is deprecated until a successor has a bound owner, effective-date
   policy, migration/rollback witnesses and explicit rejection behavior.
6. Migration is forbidden by default. Admission requires old/new tuples,
   identity-preserved versus superseded mapping, lossy-field disposition,
   selector behavior, projection parity, rollback, immutable receipt, a
   positive witness and a single-fault negative.
7. Material revision invalidates dependent artifacts rather than silently
   refreshing them.

All diagnostics named in this synthesis are candidates, not current registry
entries.

## Smallest Witnesses

| Boundary | Positive | Single-fault negative |
|---|---|---|
| Record shape | one valid source plus one evidence-bearing claim | add one unknown property |
| Identity/reuse | A1 and A2 reuse one Source A | duplicate the same identity at the same level/scope |
| Evidence endpoint | A1 selector resolves to Source A | change only `source_id` to unknown |
| Rights | `unknown`, or asserted license with basis | remove only asserted-rights basis |
| Selector result | selector returns A1/A2 and excludes B1 | remove exact origin from one result |
| Projection | repeat same bound inputs/versions | flip one generated byte |
| Authority ceiling | result contains attribution, selectors and separate receipt state | add `accepted=true` |
| Version tuple | supported tuple processes normally | change only selector version to unsupported |
| Migration | identity disposition and parity/rollback pass | omit only identity disposition |
| P1 task | bounded cohort, exact selectors, content allowlist | target `.github/**` |
| P1 report | expected check from expected App | same check name from wrong App |
| Review | distinct reviewer assesses exact head | reviewer authored candidate |
| Owner decision | genuinely bound owner decides one exact question | role label only |
| Merge | reviewed head reaches base with policy evidence | indirect reachability only |
| Regeneration | merged base rebuild matches output digest | build from unmerged head |
| Context packet | all dependencies resolve and packet reproduces | change one dependency digest |
| Semantic admission | direct references fail a required query but typed candidate answers | treat Inventory entry as admitted concept |

## Proposed Public Design Delta

### `ARCHITECTURE.md`

1. Define `SourceRecord` as a contributor-authored source description.
2. Add an unresolved selector-profile contract: selector type, normalization,
   source-state binding or declared absence, resolution result, diagnostics,
   and version.
3. Add the unresolved canonical-byte contract: UTF-8, newline, duplicate-key,
   canonical serialization, digest algorithm and receipt format. Byte
   determinism remains a Design claim until selected and witnessed.
4. Expand versioning with explicit supported tuples, reject-before-processing,
   no predecessor promise, directional compatibility, deprecation
   preconditions and fail-closed migration admission.
5. Separate assessment, owner decision, merge receipt, publication effect,
   ontology candidate and promoted meaning as later surfaces.
6. Add the compact Phase-1 candidate seam:
   `TaskSnapshot + BasePolicyPacket → ContextPacket → Candidate →
   ValidationReport + ReviewFinding → OwnerDecision → MergeReceipt →
   RegenerationReceipt`.
7. Add or refine unresolved ownership for compatibility/migration and selector
   profile without inventing bindings.

### `VALIDATION-CONTRACTS.md`

Add planned Design-only groups:

- `VC-SERIALIZATION`
- `VC-DIAGNOSTIC`
- `VC-VERSION`
- `VC-MIGRATION-ADMISSION`
- `VC-SELECTOR-STATE` only after selector state rules are chosen

Extend `VC-PHASE-BOUNDARY` so assessment, owner decision, merge, publication,
and ontology admission remain absent from Phase-0 outputs.

### `CONTRACT-CATALOG.md`

Do not add it. A prose catalogue has no distinct consumer or validation
behavior. A machine-validated registry is deferred until validators, readers,
or packet builders consume it and reject unregistered or multiply-owned
contracts.
