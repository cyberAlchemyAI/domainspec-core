Lesson 1 of 7

Choose the smallest responsible shape

Begin with the safeguard the work needs. The formal route names come only after you have made both decisions in ordinary language.

7 minutes
source-backed distinction teaching scenarios
First visible thought

What must stay independent?

Imagine two requests. In the first, someone needs to find the file and exact line behind an error; the parent will inspect the report. In the second, two reviewers must challenge the same proposal separately before a later decision may use their reports.

Ask yourself: if you removed the extra role, which request would lose an important safeguard?

A request needs the file and exact line behind an error. The parent will inspect the report before using it.

Which setup is enough for this request?

A proposal must receive two judgments that do not stand in for each other. Both reports will be considered before implementation planning.

Which setup preserves what this request needs?
Distinction earned

Name what each setup protects

  1. 1 · BoundaryA decision, permission, or responsibility that must stay separate.
  2. 2 · Bounded helperOne person with one clearly limited job whose result the parent can inspect.
  3. 3 · Governed dispatchA coordinated job with separate roles, checks, and stop points.
  4. 4 · AuthorityPermission to make a change or claim.

One bounded helper is enough when one inspectable result protects every needed decision. Multi-agent dispatch is justified only when the work itself needs separate judgment, producer/reviewer separation, parallel results, a dependent decision, or isolated write areas—and it is governed only when those roles, checks, and stops are explicit.

What still does not follow: choosing either shape does not grant permission, record the route, or start the work. More agents do not create more authority.

Changed movement: the second request keeps its reviews separate. Before the later decision may rely on their results, what must be true of both results?

Hold that question for Lesson 3. It asks how separate judgments become usable evidence rather than asking you to repeat either setup choice.

Lesson 2 of 7

Find the last proven step

A convincing result can tempt us to skip the transitions between “returned,” “admitted,” “joined,” and “accepted.” Use four questions to hold the boundary.

7 minutes
Context before you inspect

A result changes status one boundary at a time

A worker returning, a file existing, a receipt being admitted, that receipt joining a reduction, and a gate passing are different claims. Begin with the strongest statement direct evidence supports; then name the next owner instead of borrowing certainty from a later-looking artifact.

The missing, excluded, or still-owned-elsewhere part is the residue. Keeping it visible prevents a valid partial result from being enlarged into completion.

Lesson 4 of 7

Read the work ticket in code

The action JSON is a boundary object: the coordinator, driver, parent, host, and later evidence all refer to the same exact job instead of reconstructing it from chat.

10 minutes
Context before you read the JSON

The work ticket exists before the side effect

The relay needs one object every later stage can identify. Persisting an action first prevents the role, inputs, expected output, and write boundaries from being reconstructed from conversational memory after a host call has already happened.

Read the excerpt as four questions: which exact job is this, which capability may it use, where may it write, and which paths remain forbidden? Ownership then stays split across compilation, request preparation, native invocation, result recording, and evidence validation.

Inspect a field

action_id

Stable identity for this one work ticket. Later events and receipts must bind back to it.

Boundary: this is an explanatory excerpt, not a schema-valid action by itself. The complete action also binds dispatch, run, step, target, input, and output identities.

Coordinator

Validates the dispatch and compiles the first eligible wave into state, run plan, and action files. It does not launch agents.

Driver

Checks persisted artifacts, prepares exact host requests, records results, admits receipts, and advances waves. It does not invoke collaboration tools itself.

Parent and host

The parent invokes the active native host once using the prepared request; the host returns a binding or failure.

Evidence validator

Replays events as a causal state machine. Correct order does not establish that a worker's claim is true.

Lesson 5 of 7

Stop at the first missing cause

Failing closed does not erase partial evidence. It preserves the last supported state and refuses to invent the missing transition from later, plausible-looking events.

7 minutes
Context before you diagnose

Keep the valid prefix; stop at the first unsupported edge

A broken history does not force you to discard everything, and a plausible later event does not repair an earlier gap. Read from left to right and ask what prerequisite each event needs. The first absent prerequisite marks the recovery boundary.

The validator error names the causal boundary being protected. Recovery can preserve every earlier supported event while refusing to manufacture the missing one or silently retry the side effect.

Build the handoff before deciding whether work can begin

Two independent reviewers returned checked results. A review decision now allows implementation to be planned, but the repository still has no separately governed input for an implementation worker. A named implementation owner is responsible for preparing that next-worker input.

The decision changes what may be planned; it does not itself describe a worker start. Draft the four links below in ordinary language. The formal mapping stays unavailable until you have reconstructed the transfer and attempted the later start decision.

Owner premise: checked results support a decision that allows planning. The implementation owner still has to prepare the exact next-worker item.
What bounded work and checked results were received?
What decision changed the present state?
What may happen next, and what exact next-worker item is still absent?
Who owns the next move, and what would that move still leave unproved?
Four provisional links present

Now decide whether the next worker can begin

The required reviews are part of the decision, and that decision permits planning. No downstream worker input exists. Is the current evidence sufficient for the implementation worker to begin?
Branch explained · formal mapping available

Separate eligibility from the next worker's input

  1. 1 · ReceiptThe structured record of an expected result.
  2. 2 · AdmittedThe receipt passed its expected identity-and-shape checks.
  3. 3 · JoinedAll required admitted results are included in the decision set.
  4. 4 · GateThe declared decision rule is applied.
5 · Persisted action: the exact saved work record that must exist before a host can be asked to start a worker. Eligibility, an exact action, a host attempt, and execution are separate facts.
