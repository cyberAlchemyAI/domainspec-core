Distinction earned

Name what each setup protects

  1. 1 · BoundaryA decision, permission, or responsibility that must stay separate.
  2. 2 · Bounded helperOne person with one clearly limited job whose result the parent can inspect.
  3. 3 · Governed dispatchA coordinated job with separate roles, checks, and stop points.
  4. 4 · AuthorityPermission to make a change or claim.
Analogy—then drop it: a repair bench may hold many tools while one mechanic still owns one diagnosis. A two-key safe is different: separating the key holders is itself the safeguard. The number of moving parts does not decide the work shape; the judgment boundary does.

One bounded helper is enough when one inspectable result protects every needed decision. Multi-agent dispatch is justified only when the work itself needs separate judgment, producer/reviewer separation, parallel results, a dependent decision, or isolated write areas—and it is governed only when those roles, checks, and stops are explicit.

What still does not follow: choosing either shape does not grant permission, record the route, or start the work. More agents do not create more authority.

Changed movement: Priya keeps Card B's findings separately attributable. Before the release decision may rely on them together, what must be true of both results?

Hold that question for Lesson 3. It asks how separate judgments become usable evidence rather than asking you to repeat either setup choice.

Find the last proven step

A convincing result can tempt us to skip the transitions between “returned,” “admitted,” “joined,” and “accepted.” Use four questions to hold the boundary.

Context before you inspect

A result changes status one boundary at a time

A worker returning, a file existing, a receipt being admitted, that receipt joining a reduction, and a gate passing are different claims. Begin with the strongest statement direct evidence supports; then name the next owner instead of borrowing certainty from a later-looking artifact.

The missing, excluded, or still-owned-elsewhere part is the residue. Keeping it visible prevents a valid partial result from being enlarged into completion.

Read the work ticket in code

Context before you read the JSON

The work ticket exists before the side effect

The relay needs one object every later stage can identify. Persisting an action first prevents the role, inputs, expected output, and write boundaries from being reconstructed from conversational memory after a host call has already happened.

Read the excerpt as four questions: which exact job is this, which capability may it use, where may it write, and which paths remain forbidden? Ownership then stays split across compilation, request preparation, native invocation, result recording, and evidence validation.

Inspect a field

action_id

Stable identity for this one work ticket. Later events and receipts must bind back to it.

Boundary: this is an explanatory excerpt, not a schema-valid action by itself. The complete action also binds dispatch, run, step, target, input, and output identities.

Coordinator

Validates the dispatch and compiles the first eligible wave into state, run plan, and action files. It does not launch agents.

Driver

Checks persisted artifacts, prepares exact host requests, records results, admits receipts, and advances waves. It does not invoke collaboration tools itself.

Parent and host

The parent invokes the active native host once using the prepared request; the host returns a binding or failure.

Evidence validator

Replays events as a causal state machine. Correct order does not establish that a worker's claim is true.

Separate eligibility from the next worker's input

Analogy—then drop it: an approved building permit allows work to be planned; a crew still needs a work order naming the job, place, and limits. The permit is the decision. The persisted action is the work order. Neither one proves that a worker started or that the result will be correct.
  1. 1 · ReceiptThe structured record of an expected result.
  2. 2 · AdmittedThe receipt passed its expected identity-and-shape checks.
  3. 3 · JoinedAll required admitted results are included in the decision set.
