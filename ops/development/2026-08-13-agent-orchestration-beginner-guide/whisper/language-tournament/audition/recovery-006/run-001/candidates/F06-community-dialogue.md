# F06 — Community spine × decision-room dialogue

## Candidate card

- Design claim: short community-hall conversations can make ownership and consequence audible to beginners before exact software terms appear.
- Community spine: Salma coordinates Riverside Community Hall, Jo maintains it, Mina reviews access, and Ren owns approved follow-on work.
- Proposer evidence: dialogue exposes mistaken leaps at all three routes and stops before resolving the learner's choice.
- Assumption: conversational familiarity outweighs the cost of carrying four names.

## Route 1 sample — opening, two work cards, shared attempt, branch explanation, formal reveal, transfer, claim limit

### Opening

The hall projector fails before a workshop, and the reopening plan needs separate exit-safety and wheelchair-access reviews.

“Give both jobs to everyone,” Jo says. “More hands cannot hurt.”

Mina shakes her head. “Sometimes another role protects a different judgment. Sometimes it protects nothing.”

Salma asks you to decide which is which.

### Two work cards and shared attempt

**Card A:** identify the failed cable or socket, photograph it, and return one fault report for Salma to inspect.

- One investigator returns one evidence report for Salma to inspect before deciding.
- Two reviewers return separate evidence reports for Salma to compare before deciding.

Binding: `choose-one`; values `helper`, `dispatch`; expected `helper`.

**Card B:** keep the exit-safety judgment and wheelchair-access judgment separate before Salma decides to reopen.

- One investigator returns one evidence report for Salma to inspect before deciding.
- Two reviewers return separate evidence reports for Salma to compare before deciding.

Binding: `choose-two`; values `helper`, `dispatch`; expected `dispatch`.

Shared action: **Check both decisions**.

### Branch explanation

- Card A, correct: Salma says, “Yes. One bounded diagnosis gives me the inspectable result this problem needs.”
- Card A, corrective: Jo asks, “Which second responsibility would another report preserve?” There is only one fault to locate.
- Card B, correct: Mina says, “Yes. My access judgment cannot stand in for the exit review, or vice versa.”
- Card B, corrective: Salma says, “One combined voice would erase the separation the decision needs.”

### Formal reveal

1. **boundary** — a decision, permission, or responsibility that must stay separate.
2. **bounded helper** — one person with one clearly limited job whose result the parent can inspect.
3. **governed dispatch** — coordinated work with separate roles, checks, and stop points.
4. **authority** — permission to make a change or claim.

The projector diagnosis fits a bounded helper. The reopening reviews fit a governed dispatch. No number of people grants authority or starts work.

## Route 3 sample — concrete returned-result problem, predecessor attempt, branch explanation, exact nine-state reveal, limit attempt, loop and closeout, claim limit

### Concrete returned-result problem and predecessor attempt

“My access report is back,” Mina says.

“Then we can decide,” Jo replies.

Salma points to the empty exit-review slot. “Which evidence level does the decision actually need?”

- The request to begin has a recorded outcome.
- One returned record matches its expected identity and shape.
- Every required checked record is included in the decision's evidence set.

Binding: `relay-predecessor`; values `host-result`, `receipt-admitted`, `receipt-joined`; expected `receipt-joined`.

### Branch explanation

- Correct: Salma says, “Yes. The decision needs the complete checked set.”
- Corrective: Mina says, “That answer names an earlier fact, before every required checked record is together.”

### Exact nine-state reveal

1. **Action persisted** — An exact bounded job is saved. The runtime has not been asked to start a worker.
2. **Attempt recorded** — Intent to invoke that exact action is recorded. The runtime has not accepted it and no worker is established.
3. **Host result recorded** — The runtime's start result is recorded. A started worker has not necessarily finished.
4. **Terminally accounted** — The worker's finish, failure, or stop is recorded. Returned work has not entered the evidence set.
5. **Receipt admitted** — The expected record's identity and shape were checked. Its contents are not proved and it has not joined the decision set.
6. **Receipt joined** — The admitted result is included with every required decision input. No gate has necessarily passed and its claim is not thereby correct.
7. **Gate decided** — The declared decision rule was applied. A passing decision does not start the eligible wave.
8. **Dependent plan persisted** — Exact actions for the dependent wave now exist. None has been attempted; each action re-enters this lifecycle.
9. **Terminal closeout recorded** — The route has a final resolution or explicit stop. No canonical status, publication, deployment, production readiness, or truth follows.

### Limit attempt, dependent loop, and closeout

“The decision passed,” Jo says. “Ren can start.”

What is still required before Ren's dependent worker can start?

- Nothing; gate passage starts the worker.
- A fresh persisted action plan for the eligible wave.
- Proof that the earlier receipt is semantically true.

Binding: `relay-limit`; values `nothing`, `new-plan`, `truth`; expected `new-plan`.

- Correct: Salma says, “Yes. Ren still needs an exact persisted action.”
- Corrective: Mina says, “The decision opens a transition; it cannot create or execute Ren's job.”

The **dependent-work loop** returns new work through attempt, host result, terminal accounting, admission, join, and gate. The **terminal-closeout branch** requires resolution or explicit stop; a plan is not terminal.

### Binary start attempt and branch explanation

- Yes — the owner may use the decision as the worker's start instruction.

## Guide-wide pattern

Use three-turn exchanges to surface a tempting leap, a boundary question, and an unresolved learner decision. Reuse the community cast, then transfer explicitly to software at each repository connection. Stop dialogue at the formal reveal.

## Known risks

- Four names and repeated quotation marks raise cognitive and screen-reader load.
- The knowledgeable character can become an answer cue even when choices are balanced.
- Community dialogue may feel staged rather than like recognizable agent work.
