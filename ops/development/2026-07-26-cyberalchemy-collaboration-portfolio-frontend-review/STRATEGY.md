# CyberAlchemy Collaboration Portfolio Frontend Review Strategy

Status: form-valid and double-PASS; unconfirmed, unregistered, not run

## P1 Trigger

This is a governed `review` dispatch. Synthesis, isolation, and parallelism all
apply: the existing frontend must be attacked across conversion, information
architecture, accessibility, interaction behavior, public claims, and contact
mechanics without allowing any one lens to rewrite the others.

## Lanes, Subagents, And Outputs

1. `attackers` runs three explorers in parallel with robot talks on the
   canonical `methodology` axis.
   - Peirce uses a cold-arrival-to-contact task walkthrough.
   - Alexander uses a hierarchical content inventory and
     progressive-disclosure trace.
   - Kahneman uses standards-based DOM and black-box falsification.
2. `synthesizer` runs MacIntyre after all attacker returns and reconciles them
   into candidate cited change requests.
3. `verifiers` runs Popper and Quine in parallel after synthesis.
   - Popper falsifies scope, literal evidence, and over-removal.
   - Quine falsifies browser behavior, accessibility, and testability.
4. `coverage-auditor` runs Brandenburg after verification and recommends
   accept or reject without adding findings. The parent remains the independent
   final approver required by the live form owner.

The review produces `attacks.md` and `findings.md`. Attackers and verifiers are
read-only over the frontend.

## Dependency Flow

`attackers -> synthesizer -> verifiers -> coverage-auditor`

- Attackers to synthesizer: sequential.
- Synthesizer to verifiers: zig-zag, cap 1.
- Synthesizer to attackers: conditional feedback, cap 1, only if material
  coverage is missing.
- Verifiers to coverage auditor: sequential.
