supports, inventory proposals and open hypotheses, map the proposed recursive

kill candidate integration seams into the private agent-reasoning-engine.

The exact-binding contract requires every load-bearing row to carry an immutable
source identity, an exact selector or structured pointer, the explorer return

are frozen by the SHA-256 values in `strategy-inventory-packet.json`.

## Lanes, groups, and subagents

### Exploration wave — three agents in parallel

Anti-bias axis: composite methodology and source corpus.

- `Turing, Alan` — implementation explorer. Empirically audits current tracked
  runtime code, migrations, CLI/API surfaces, tests, and as-built evidence. It
  returns a capability/proof-tier matrix and a precise delta from the historical
  Inventory classification.
- `Simon, Herbert` — proposal explorer. Classifies the untracked recursive-work
  design and ontology, tracked workflow-graph discovery, autonomous-agent-graph
  target model, hypotheses, decisions, non-decisions, and every open residue.
- `Hewitt, Carl` — integration explorer. Builds exact owner-preserving mappings
  from current implementation to recursive Work and from the orchestrator/Work
  boundary to entry gate, ACI actor/journal, bounded L0 semantic evaluator,
  replay, exact-effect eligibility, and later reasoning-engine layers.

Every explorer is read-only. Their pairwise predicted disagreements are stored
in the admitted sheet, not only in this prose.

### Synthesis wave — one agent

- `Shannon, Claude` — synthesizer. Reconciles, rather than averages, the four
  evidence ceilings; creates the current-state map, proposal and residue ledger,
  two integration matrices, candidate topology verdicts, smallest safe
  documentation-only integration contract, recomposition path, and negative
  controls.

### Review wave — three agents in parallel

Anti-bias axis: attack vector.

- `Lakatos, Imre` — precedent and owner-duplication gate. Every seam is
  classified as already implemented, build-from-owned, proposal-only,
  owner-conflicting, or precedent-clean after a direct bounded search.
- `Gödel, Kurt` — non-vacuity gate. Forces current-state and integration claims
  through finite positive, negative, blocked, retry, replay, and revalidation
  paths; a seam with no discriminating witness is killed.
- `Quine, Willard Van Orman` — definitional and authority gate. Prevents
  definition/run/history/cursor/status, orchestration/reasoning, gate/verdict/
  effect, evidence/authority, and parent/target binding governance from
  collapsing.

### Evidence closure — parent-owned gate

The writer remains blocked until every positive row is `bound`, `deferred`, or
`killed`. Missing provenance, selectors, anchors, or source reads route only to
the confirmed explorer feedback edge; interpretation conflicts route through
the bounded synthesizer/reviewer zig-zag.

### Writing and audit waves

- `van Lamsweerde, Axel` — writer. Writes only `findings.md` from the
  evidence-closed package.
- `Loregian, Fosco` — auditor. Reads only the findings and closure evidence,
  then returns `ACCEPT` or one bounded writer-revision request.
- Final approver: `parent`.

## Dependency flow

```text
implementation explorer ┐
proposal explorer       ├─ parallel ─> synthesizer <─zig-zag(2)─> three reviewers
integration explorer    ┘                   │                          │
          ^                                  └─feedback(1)─────────────┘
          │
          └──────── evidence repair only

reviewers -> exact-binding closure -> writer -> auditor -> parent
                                      ^          │
                                      └feedback(1)
```

All agents inside a fan-out wave run concurrently and join with policy `all`.
Every non-final wave has a named receipt gate. Missing, mismatched, partial, or
timed-out receipts block downstream execution rather than becoming implicit
partial proof.
