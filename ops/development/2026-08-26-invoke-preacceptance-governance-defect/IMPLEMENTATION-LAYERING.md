# Implementation Layering: Invoke Preacceptance Governance Defect

## Purpose

Repair the smallest complete vertical slice of Invoke governance without treating
planning, candidate validation, request emission, acceptance, and application as
the same state.

## Layer Boundary Rule

Each layer answers one question. Promotion requires the listed evidence from the
previous layer.

## Layer Decision Table

| Layer | Decision question | Minimum working unit | Included scope | Deferred scope | Exit evidence | Promotion decision |
| --- | --- | --- | --- | --- | --- | --- |
| L0 | After this layer, do nonempty exact candidate bytes have a truthful non-authorizing state? | The material package schema, validator, receipt, and fixtures accept one explicitly versioned staged-candidate representation and emit a distinct non-authorizing outcome, never `ready`. | Consumer/version inventory, state transition table, exact package validation, compatibility controls, downstream fail-closed checks. | Mixed content, owner-request binding, stage orchestration, generated runtime sync. | Positive and negative material-package fixtures; all existing proposal-only and apply-approved fixtures retain their meaning; legacy/single-axis consumers fail closed. | Promote only if candidate validation is exact, the token/version decision is owner-accepted, and every handoff consumer keeps `mutationReady=false`. |

## Non-Regression Guardrails

- Candidate validation is not apply approval.
- No consumer may derive mutation authority from one state, mode, verdict, or
  handoff field; unknown versions/tokens fail closed.
- Exact digest and size checks apply to every content kind.
- A YAML file may be declared `utf8-text` and checked with literal assertions. A
  structural `yaml` content kind is allowed only after parser ownership, exact
  version, safe-load behavior, and a JSON-compatible value subset are pinned.
- Preacceptance writes only isolated run-local evidence.
- Preacceptance collects all still-reachable checks and preserves the first nonzero
  status; effectful execution remains fail-fast.
- Existing `proposal-only + proposal-only` and
  `apply-approved + materialized` packages retain their meaning.
- Private Body War evidence never becomes a public Arcanum fixture.
- Changing an authority-bearing schema or runner invalidates older closure bindings.
