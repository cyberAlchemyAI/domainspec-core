## Provisional architecture hypothesis to test

Use one shared protocol, not one shared super-owner.

The shared kernel should contain only stable cross-module record shapes and transition rules, provisionally:

- `WorkPackSnapshot`
- `SelectedUnitReceipt`
- `ConsumerEntryReceipt`
- `MaterialPackageReceipt`
- `MutationAdmissionReceipt`
- `ExecutionTerminalReceipt`
- `OwnerJoinReceipt`
- `SynchronizedResult`
- `ContinuityCursor`
- `LifecycleDecisionReceipt`
- `RegistryReleaseReceipt`

Each record must name its producer, consumer, authority effect, freshness or replay binding, validation result, residue, and owner-declared next-transition hint. The pure validator checks structure only; it never decides semantic legality. The kernel must not choose an SWU, execute owner work, synchronize closeout, mutate Craft, promote a capability, or release a registry entry.

Candidate modules to preserve and clarify:

1. **Authoring:** Invoke plus Implementation Layering and Distill.
2. **Contract freeze and semantic selection:** Work-Pack Readiness Audit.
3. **One-unit consumer and executor:** Task Session.
4. **Owner-hop transport:** Continuation Router.
5. **Closeout mutation:** Invoke Refresh.
6. **Ordered-series coordination:** exactly one selected owner after `DECISION-LOOP-OWNER-001`.
7. **Recursive local work state:** Craft, with `.craft/ledger.yml` authoritative only for its scope.
8. **Delegated runtime:** Dispatch Spec plus Orchestrate, limited to capability-bound delegated work.
9. **Capability lifecycle:** Sigil Development or Spellcraft plus Experiment Harness, Signal Observer, and Workflow Reflect.
10. **Read models:** Inventory and observability, never promoted into source authority by inference.
11. **Packaging and parity:** canonical-to-generated package synchronization plus behavioral parity receipts.
12. **Conformance:** a protocol witness suite spanning the complete owner chain.

This is a hypothesis for the Refine tournament, not an accepted architecture.

## Alternatives that must survive until Distill

- **A — Owner-preserving contract kernel:** shared types and transition validators; existing capabilities retain authority.
- **B — Hierarchical pipeline coordinator:** one build coordinator owns the top-level state machine and delegates capability work.
- **C — Event/ledger-centered composition:** owner receipts are joined through a durable work graph, with Craft or a separate ledger as the coordination substrate.

The run must compare cohesion, authority safety, migration cost, backward compatibility, diagnosability, replay safety, and ability to prove the positive end-to-end witness. It must not select A merely because this seed proposes it.
