# Glossary: Invoke Design Coverage

| Term | Meaning |
| --- | --- |
| authored concern | a concern explicitly declared by the Design author |
| `authored-complete` | required authored fields and planned witness contracts exist; no validator-backed claim |
| concern denominator | union of authored concerns and independently extracted scope signals |
| Design evidence state | one of the governed authored, validator, or Plan-evidence states |
| `DesignDenominatorReceipt` | extractor output bound to the manifest input digest and detector identity |
| Design extension | concern-specific architecture depth selected by a predicate; not a new template family |
| `DesignScopeManifest` | normalized, digest-bound statement of inspected scope, explicit exclusions, and unknowns |
| fixed point | unchanged manifest, denominator, ownership, dispositions, and selected outputs after exactly two passes |
| human semantic contract | meaning a natural person reads, trusts, decides from, corrects, recovers through, or operates accessibly |
| primary concern | the single accountable risk class assigned to a detected signal before cross-references |
| `recommended` | bounded advisory output with owner, evidence, and revisit condition; it does not select a required companion |
| `not-applicable-with-rationale` | detector-negative disposition proved by cited selectors and a checkable boundary |
| planned witness | Design-authored `fixture_spec` or `validator_contract`; not executed evidence |
| selection result | digest-bound concern ownership, dispositions, selected outputs, fixed-point state, and evidence state |
| six-view baseline | mandatory Design navigation that is explicitly not a sufficiency proof |

Candidate terms remain package-local until Definitions Governance explicitly
accepts any public vocabulary change.
