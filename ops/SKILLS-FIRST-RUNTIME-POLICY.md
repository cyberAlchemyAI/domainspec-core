# Skills-First Runtime Policy

Date: 2026-05-29
Status: active for repository-organization cleanup

## Purpose

Define the first cleanup rule for Arcanum and DomainSpec agent surfaces in `domainspec-core`: skills are the default runtime surface, and command files are not a required repository layer.

This policy narrows the broader runtime-surface policy from `ops/REPOSITORY-ORGANIZATION-DESIGN.md`.

## Decision

The repository should expose reusable agent behavior through skills first.

Command surfaces are allowed only as explicit, proven runtime adapters. They are not canonical source, not the default install target, and not a reason to keep duplicate copies of Arcanum behavior.

## Layer Order

| Layer | Role | Keep? | Rule |
| --- | --- | --- | --- |
| Canonical capability source | `arcanum/arcana/*`, `arcanum/spells/*`, DomainSpec canonical skill sources | yes | Edit here first. |
| Skill runtime surface | `.github/skills/*`, machine Codex skills, same-checkout skill facades | yes | Default install and discovery layer. |
| Runtime scripts/tools | `arcanum/tools/*`, deterministic helper scripts | yes, when sourced | Use as implementation helpers called by skills. |
| Command files | `.codex/commands/*`, `.arcanum/runtimes/codex/commands/*` | no by default | Delete or avoid generating unless a runtime requirement is documented. |
| Generated/local state | `.arcanum/observability/*`, caches, outputs | no by default | Ignore, untrack, or promote deliberately as evidence. |

## Repository Rules

- Do not create new Arcanum `.codex/commands` files as part of normal repo organization.
- Do not treat command wrappers as evidence that a capability is installed correctly.
- Prefer one skill wrapper that points to canonical Arcanum source over paired skill and command wrappers.
- Keep `.github/skills/arcanum-*` as the current repo-local skill discovery layer.
- Keep global Codex skill installation as a separate machine-global task; do not use the repository cleanup pass to mutate `/mnt/c/Users/vlad_/.codex`.
- If a future runtime truly requires command files, document the runtime, source, target path, regeneration path, and validation command before adding them back.

## Cleanup Implications

Already tracked root command bridges can be removed when equivalent skill surfaces exist or when the command only forwards to canonical Arcanum source.

Root command directories should not be regenerated by bootstrap unless the operator explicitly asks for a command compatibility adapter.

The remaining cleanup pass should focus on:

1. skill inventory and duplicate wrappers,
2. canonical-source mapping,
3. generated/local state,
4. superseded names such as `sigils-library/`.

## Validation

A skills-first cleanup is valid when:

- no tracked root `.codex/commands/*.md` files remain,
- no tracked root `.arcanum/runtimes/codex/commands/*.md` files remain,
- Arcanum skill wrappers remain discoverable under `.github/skills/arcanum-*`,
- repository organization docs no longer list commands as a required target layer.
