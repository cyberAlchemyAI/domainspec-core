A team confuses a note with a rule.

The system still runs. The documents still exist. The meaning has already drifted.

Source noteA thing someone found during work.
DefinitionA thing the project accepted.
RuleA thing that constrains future action.
SignalA thing the system emitted later.
SummaryA thing generated from nearby text.
Observation.

These are different objects. They can mention the same word. They cannot carry the same authority.

Concrete first. Then structure.1 / 8
Start with the operational confusion. The failure is not missing documentation. The failure is role collapse.

The problem

Meaning drifts when roles are implicit.

Role

What kind of object is this?

Source

Where did the claim enter the project?

Status

Is it draft, candidate, reviewed, blocked, or promoted?

Use

What may a human or agent rely on?

A week later, the same word appears in a handoff. The folder tree says where the file lives. It does not say what the file is allowed to mean.

Location is not meaning2 / 8
The style here commits. Location helps retrieval. It does not protect meaning.

Definition

Ontology is the structure that keeps project meaning inspectable.

Objects

Definitions. Decisions. Rules. Workflows. Signals. Claims.

Relations

Traced to. Governed by. Tested by. Realized by. Drifts from.

Receipts

Source refs. Confidence. Status. Promotion state. Use obligations.

Mechanism.

The ontology tells the project what each object is, what it connects to, what supports it, and where the authority stops.

Boundary.

Evidence is not authority. A useful candidate is not a promoted rule. The ladder prevents the story from skipping steps.

Authority

The ontology can point. It cannot approve.

In CAV2, definitions, constitutions, specs, runtime contracts, and public claims remain authoritative only through their own owner routes.

Allowed

Classify. Relate. Trace. Condense. Prepare a promotion request.

Blocked

Promote itself. Redefine a constitution. Treat a generated index as authority.

Reason

Governance must stand outside the object it governs.

This is the non-negotiable caveat7 / 8
This mirrors the writing style's hard commit: software necessitates governance, but it cannot contain it. Here: ontology prepares governance work, but it does not own promotion.
